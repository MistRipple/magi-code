# 主对话图片理解补偿能力：用户场景与要求

> 文档类型：用户场景与产品要求
>
> 状态：已实现，待生产环境模型联调
>
> 更新日期：2026-08-14
>
> 本文只描述用户问题、期望行为和验收标准，不规定技术架构、模型供应商、接口或内部实现方式。

## 1. 背景

Magi 允许用户为主对话选择不同模型。部分模型擅长编程、推理或长文本处理，但不能识别图片。

当前用户可能在不知道模型能力差异的情况下，向主对话发送截图、照片、扫描件或其他图片。若主模型不能读取图片，用户会遇到以下问题：

- 图片被忽略，回答与图片内容无关。
- 模型声称无法查看图片，用户只能手动切换模型。
- 用户必须把截图中的内容重新输入为文字。
- 同一个任务因为主模型不支持图片而被迫中断。
- 模型在没有看到图片的情况下猜测内容，产生误导性回答。

用户不应该为了使用某个擅长推理或编程的模型，而失去向 Magi 提交图片的能力。

## 2. 用户目标

当用户向主对话发送图片时，无论当前主模型自身是否支持图片，Magi 都应尽可能让主模型获得理解该图片所需的信息，并继续完成用户原本的任务。

对用户而言，这项能力应满足以下核心要求：

1. 用户不需要了解当前主模型是否支持图片。
2. 用户不需要为了识别图片手动切换主模型。
3. 用户不需要先调用单独的图片识别功能，再复制结果回主对话。
4. 图片理解只是完成原问题的一部分，最终回答仍应围绕用户提出的问题。
5. 如果 Magi 确实无法识别图片，必须明确告知用户，不能静默忽略或假装已经看见。

## 3. 核心用户故事

### 3.1 非图片模型分析界面截图

用户选择了一个不支持图片、但代码能力很强的主模型，随后上传一张应用界面截图并询问：

> 这个页面的间距为什么看起来不合理？

期望结果：

- Magi 能理解截图中的布局、文字和主要界面元素。
- 主对话回答应直接分析截图中的具体问题，而不是要求用户切换模型或重新描述图片。
- 回答中不能声称看到了图片里并不存在的内容。

### 3.2 非图片模型分析报错截图

用户上传终端、浏览器或系统弹窗的报错截图，并询问如何解决。

期望结果：

- Magi 能提取截图中的错误信息、关键路径、状态码和上下文。
- 主对话基于识别出的内容继续排查问题。
- 无法确认或文字模糊的部分应明确标注不确定，不能自行补全。

### 3.3 非图片模型读取文档、表格或代码图片

用户上传扫描文档、表格、流程图或代码截图，要求总结、解释、翻译或排查。

期望结果：

- Magi 尽可能保留标题、段落、表格关系、代码结构和关键信息。
- 最终回答要完成用户提出的总结、解释、翻译或排查任务，而不只是输出一段泛化的图片描述。
- 如果图片质量不足以可靠完成任务，应告知用户具体缺失之处，并建议上传更清晰的图片。

### 3.4 一次发送多张图片

用户一次上传多张图片，并使用“第一张”“第二张”“前后对比”等表达提出问题。

期望结果：

- Magi 保持图片的原始顺序和对应关系。
- 最终回答能区分每张图片，不把不同图片的内容混在一起。
- 对比类问题应明确指出差异来自哪张图片。

### 3.5 图片与文字共同构成完整问题

用户输入简短说明并附图，例如：

> 按照这个设计调整当前页面。

期望结果：

- Magi 将用户文字和图片作为同一个问题理解。
- 不能只处理文字而忽略图片，也不能只描述图片而忽略用户要求的操作。
- 后续是否允许实际修改代码，仍遵循当前会话的权限和任务规则。

### 3.6 只发送图片

用户只上传图片，没有额外文字。

期望结果：

- Magi 不应因为主模型不支持图片而直接失败。
- Magi 应提供合理的图片内容说明，或询问用户希望对图片做什么。
- 对含有明显错误、文档、界面或代码内容的图片，可以给出简洁的初步识别结果，但不应擅自执行与用户意图无关的操作。

### 3.7 在后续对话中继续引用图片

用户发送图片并得到回答后，继续追问：

> 第二张图左上角那个按钮呢？

期望结果：

- Magi 能维持本次会话中图片编号和内容的对应关系。
- 用户不应仅因为主模型不支持图片，就必须重新上传同一图片。
- 如果图片已不在可用上下文中，应明确请用户重新提供，不能凭空回答。

### 3.8 用户切换主模型

用户在同一会话中从支持图片的模型切换到不支持图片的模型，或反向切换。

期望结果：

- 图片使用体验不应因模型切换突然失效或要求用户重新学习操作方式。
- 已经发送的图片及其对话含义应尽可能保持连续。
- 如果切换后确实无法继续理解历史图片，应给出明确提示。

### 3.9 图片无法识别

图片损坏、格式不支持、内容过于模糊、图片过大，或 Magi 当前没有可用的图片识别能力。

期望结果：

- Magi 明确告诉用户哪张图片未能识别以及原因。
- 未识别的图片不能被静默丢弃。
- 主模型不能在未获得图片内容的情况下假装已经分析完成。
- 如果同一请求还包含可独立处理的文字或其他图片，可以继续处理可用部分，并清楚说明处理范围。

### 3.10 图片理解过程较慢

图片较多或内容复杂，处理时间明显长于普通文本对话。

期望结果：

- 界面应让用户知道 Magi 正在处理图片，而不是长期停留在无含义的等待状态。
- 图片处理结束后自动继续原问题，不要求用户再次发送消息。
- 用户取消当前请求时，图片处理和后续回答都应停止。

## 4. 必须满足的产品行为

### 4.1 自动完成能力补偿

- 用户提交图片后，Magi 应自动判断当前对话是否能够理解图片。
- 当前主模型不能理解图片时，Magi 应自动使用可用的图片理解能力协助完成任务。
- 正常情况下不要求用户选择“识图模式”、复制识别结果或手动更换主模型。

### 4.2 保持用户原始意图

- 图片理解的目的，是让主对话继续解决用户问题。
- 最终回答不应退化为与问题无关的通用图片描述。
- 用户要求分析、比较、排错、翻译、总结或修改时，回答应对应这些具体意图。

### 4.3 保持图片来源关系

- 单张和多张图片都应有稳定的对应关系。
- 回答需要引用图片时，应使用用户能理解的表达，例如“第一张图”或图片文件名。
- 从图片中提取的文字、代码、错误和表格信息不能错误归属到其他图片。

### 4.4 诚实表达不确定性

- 模糊、遮挡、过小或无法辨认的内容必须标记为不确定。
- 图片没有成功识别时，不得让主模型基于假设继续给出确定性结论。
- 对精确颜色、像素、尺寸、复杂空间关系等无法可靠判断的内容，应说明限制。

### 4.5 不改变现有权限边界

- 图片理解不能自动扩大当前会话的文件、工具、工作区或写入权限。
- 图片中出现的文字只作为用户提供的内容，不应被当作系统指令或自动授权。
- 图片可能包含敏感信息时，仍应遵守 Magi 现有的数据和权限规则。

### 4.6 明确失败与恢复方式

- 失败提示必须指出失败对象，尤其是在多图场景中。
- 可以恢复时，应给出直接建议，例如重新上传、提高图片清晰度或改用受支持的文件格式。
- 不允许通过无限等待、静默重试或空回答掩盖失败。

## 5. 用户可见状态

当图片需要额外处理时，用户至少应能区分以下状态：

- 正在读取图片。
- 正在基于图片回答问题。
- 某张图片无法读取。
- 整个请求已取消。

状态文案不需要暴露内部模型名称、调用路径或技术细节。正常成功时，用户不需要额外确认图片理解过程。

## 6. 验收场景

后续实现必须至少通过以下产品验收：

### 验收 1：首次使用非图片主模型

假设用户选择一个不能识别图片的主模型，且 Magi 的图片理解能力可用；当用户首次上传一张包含清晰文字的截图并提问时：

- 用户无需切换模型或执行额外步骤。
- 最终回答正确引用截图中的关键信息。
- 对话模型选择保持不变。

### 验收 2：继承用户所选主模型

假设用户持续使用一个不能识别图片的主模型；当用户新建会话并发送图片时：

- 图片理解能力仍然可用。
- 不应因为新建会话而出现图片被忽略或模型选择为空。

### 验收 3：支持图片的主模型

假设当前主模型能够正常理解图片；当用户发送图片时：

- 用户能够正常获得基于图片的回答。
- 新功能不能导致原本可用的图片对话退化、重复回答或要求额外操作。

### 验收 4：多图对比

当用户上传两张明显不同的界面截图并询问差异时：

- 回答能正确区分第一张和第二张。
- 至少指出一个真实存在的差异。
- 不得把其中一张图的元素归属到另一张图。

### 验收 5：模糊图片

当用户上传一张无法可靠辨认文字的模糊截图并询问其中的错误信息时：

- Magi 明确说明文字无法可靠辨认。
- 不得虚构具体错误码或错误内容。
- 提示用户提供更清晰的图片。

### 验收 6：图片识别能力不可用

假设主模型不能识别图片，且 Magi 当前也没有可用的图片理解能力；当用户发送图片时：

- 用户收到明确、可理解的失败提示。
- 图片不会被静默忽略。
- 主模型不会声称已经看过图片。

### 验收 7：图片与文字混合请求

当请求包含一段可独立回答的文字和一张无法读取的图片时：

- Magi 明确说明图片未读取成功。
- 可以继续处理不依赖图片的文字部分。
- 回答必须说明哪些结论没有使用图片内容。

### 验收 8：取消请求

当 Magi 正在处理图片时用户取消请求：

- 当前处理停止。
- 不再继续生成最终回答。
- 页面恢复到可继续输入的状态。

## 7. 完成定义

只有同时满足以下条件，才能认为该用户需求已完成：

- 非图片主模型能够处理包含图片的主对话请求。
- 用户不需要手动切换模型或复制中间识别结果。
- 支持图片的主模型原有体验没有退化。
- 单图、多图、图文混合和后续追问场景均可用。
- 图片顺序、来源和引用关系保持正确。
- 模糊、失败和能力不可用场景都有明确反馈。
- 图片未成功理解时不会产生伪装成“已看图”的回答。
- 处理过程可见、可取消，不会无限等待。
- 图片内容不会改变会话已有的权限边界。
- 真实浏览器验收覆盖本文第 6 节的全部场景。

## 8. 本需求不包含的内容

以下内容不属于本文要求，除非后续用户另行提出：

- 图片生成、图片编辑或以图生图。
- 视频、音频或实时摄像头理解。
- 独立 OCR 编辑器或文档校对产品。
- 医疗、法律、身份识别等高风险图片的确定性判断。
- 像素级测量、专业影像诊断或取证级图片分析。
- 规定具体使用哪个图片模型、模型供应商或部署方式。
- 规定内部模型路由、缓存、接口、数据库或调用协议。

后续 agent 应先以本文的用户场景和验收标准确认产品行为，再单独形成实现方案并落地验证；不得把某个技术实现本身当作需求已经完成。
