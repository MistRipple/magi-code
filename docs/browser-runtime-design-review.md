> 审阅日期：2026-09-09
>
> 对象：`docs/browser-runtime-design.md` 与当前工作树代码（包含已有未提交改动）。
>
> 状态：修改建议，尚未实施。本文不是新的架构基线或执行账本；最终决策应回写设计文档，执行状态继续记录在 `browser-runtime-product-implementation-plan.md`。

> 归档说明：本文中的 `BaseWindow`、协议 3.4 等描述是审阅时基线，不是当前实现。当前唯一架构以 `browser-runtime-design.md` 为准，执行状态只读取计划文档第 11 节。

## 1. 结论与范围

保留 Electron BaseWindow、可信 App Renderer、右栏内 `<webview>`、BrowserAuthority、SurfaceRegistry 和 Automation Worker 的总体结构。当前问题主要是边界定义不完整、文档与代码不一致，以及关键运行时场景尚需验证，不需要推倒重写。

本次仅产出审阅清单，不修改产品代码，不将风险推断记为已经复现的故障。

问题分类：

- **已确认差异**：源码与设计条款存在直接差异。
- **已确认缺口**：检查的代码路径或文档缺少必要边界。
- **待验证风险**：存在机制上的风险，但尚未通过真实 Electron 复现。
- **待定产品规则**：必须明确预期行为后才能实施。

优先级：P1 为架构定稿及相关功能验收前必须解决；P2 为实现收敛和产品验收前必须补齐。优先级不代表已确认的线上故障严重程度。

## 3. 分项修改要求

### R01：补齐 guest 创建前安全边界

**依据与问题**

- `apps/desktop/src/main/window-manager.ts` 的 `createTrustedView()` 为 App Renderer 开启 `webviewTag`。
- `apps/desktop/src/main/browser-surface-manager.ts` 的 `registerEmbeddedWebview()` 在 guest 已创建后校验类型、宿主、partition、导航代次，再安装 Surface 策略。
- 本次源码检索找到的 `will-attach-webview` 位于 guest 策略中，作用是拒绝嵌套 WebView；未发现可信宿主侧的创建前拦截。
- Renderer 正常使用 `about:blank`，但这个 UI 约定不能替代 Main 的创建入口约束。此项是入口防护缺口，不代表已经证明存在可利用攻击。

**设计文档修改**

- [ ] §3.2 明确两阶段边界：创建前授权与安全配置；创建后物理身份注册。
- [ ] 说明 guest 不得继承可信 App 的 preload 或桌面控制桥。
- [ ] 明确 Main 对初始 URL、partition、Node 能力、隔离、sandbox、嵌套 guest 的强制策略。
- [ ] 明确未注册、注册失败及宿主销毁时 guest 的处理方式。

**代码调整**

- [ ] 在宿主 App Renderer 接受 webview 创建前安装校验，拒绝未经授权的 partition 和创建参数。
- [ ] 强制安全参数，不只信任 Renderer 提交的属性。
- [ ] 保留当前注册阶段的宿主、类型、session 与导航身份校验。
- [ ] 在实施时核实当前 Electron 版本的创建事件与参数语义，避免依赖未经验证的默认值。

**验收**

合法 guest 可以创建；非授权 partition、非预期 preload、安全参数篡改、嵌套 guest 被拒绝或由 Main 强制规范化；关闭和注册失败后没有遗留可控 guest。

### R02：统一固定视口实现，明确大视口如何显示

**依据与问题**

- 设计 §6 强制使用 CDP `Emulation.setDeviceMetricsOverride` / `clearDeviceMetricsOverride`。
- `browser-surface-manager.ts` 的 `applyViewport()` 实际使用 `enableDeviceEmulation()` / `disableDeviceEmulation()`，固定 `scale = 1`。
- `scripts/verify-browser-product-acceptance.mjs` 明确检查 Electron 设备仿真 API，文档与检查要求相反。
- 500 像素内容槽承载 1440 像素固定视口时，“完整可见、不截断、无显示比例处理”不能直接作为同时成立的验收承诺。

**设计文档修改**

- [ ] 将 auto、页面逻辑 viewport、设备像素比、显示比例分开定义。
- [ ] 优先沿当前 Electron 设备仿真路径验证并定稿，不为满足旧文档再增加第二套仿真实现。
- [ ] 明确超出槽位时的唯一产品行为：原尺寸可浏览，或 Chromium 仿真缩放以完整展示；定稿后不保留两套隐式行为。
- [ ] 若保留“完整可见”目标，补充 Chromium 仿真显示比例及其更新职责；禁止截图缩放不等于禁止真实页面仿真缩放。
- [ ] 明确手机快捷模式实际覆盖哪些设备特征，不把宽高设置等同于完整移动设备仿真。

**代码调整**

- [ ] 按定稿规则调整 `applyViewport()`，与 Renderer 自定义尺寸提交保持一致。
- [ ] 验证加载中提交的最新视口最终生效，切回 auto 清理全部相关设备指标。
- [ ] 同步相关测试和静态检查，删除只要求另一 API 名称的冲突断言。

**验收**

小槽位、大视口、窄屏、宽屏、自定义尺寸、窗口缩放、隐藏后恢复、加载中修改均有明确结果；不刷新页面、不串到其他 Surface；显示符合选定策略。

### R03：补充标记与截图的坐标契约

**依据与问题**

- `BrowserTabContent.svelte` 的 `normalizedAnnotationPoint()` 按内容槽矩形归一化鼠标位置。
- `browser-automation-worker/src/runtime.ts` 的 `screenshot()` 按页面 viewport 宽高将归一化 clip 转为截图坐标。
- 当槽位与页面的比例或可见范围不一致时，两个归一化空间不一定等价。当前属于待验证风险。

**设计文档修改**

- [ ] 将“不得通过窗口几何控制原生浏览器 bounds”与“交互需要局部坐标转换”明确区分。
- [ ] 分别定义槽位局部坐标、页面 viewport CSS 坐标、文档坐标、图片像素坐标。
- [ ] 定义仿真缩放、留白、页面滚动、浏览器缩放、设备像素比的转换规则。
- [ ] 明确 clip 的基准和捕获时刻；导航身份变化时拒绝过期截图或选择提交。
- [ ] 明确节点快照内容上限及截断标识；当前协议存在 `outer_html_truncated`，不应无条件承诺无限完整 HTML。

**代码调整**

- [ ] 先复现 auto 与 fixed 的框选截图链路，再按统一契约修改 Renderer、请求结构和 Worker。
- [ ] 必须传递新字段时进入现有 Schema，不新增旁路几何控制 IPC。
- [ ] 保留 Artifact 和消息引用，不把保存的历史标记与当前可操作节点身份混为一谈。

**验收**

在已知页面区域框选，核对截图区域与页面位置；覆盖滚动、不同 DPR、仿真缩放、视口大于槽位以及选择后立即导航。错误应明确返回，不能生成看似成功但区域错误的引用。

### R04：明确多窗口 Primary、租约与关闭语义

**依据与问题**

`browser-surface-registry.ts` 已维护“一个逻辑 Tab、多窗口 Surface、全局唯一 Primary”；Rust `authority.rs` 与 `domain.rs` 将控制租约绑定到物理 Surface。设计 §4 仅描述不同窗口页面独立，未定义仲裁行为。

**设计文档修改**

- [ ] 区分“两个独立 Tab 打开相同 URL”和“同一个逻辑 Tab 出现在两个窗口”。
- [ ] 规定仅哪个 Surface 可以向 Authority 发布 URL、标题和导航事实。
- [ ] 定义取得 Primary 的触发条件，区分窗口焦点、Tab 激活、用户接管和 Agent 请求。
- [ ] 定义 Primary 变更时旧控制租约如何失效，进行中命令如何结束。
- [ ] 区分关闭本窗口 Surface 与全局关闭逻辑 Tab，明确 UI 操作对应哪一种。
- [ ] 固定视口状态若不跨窗口同步，应归属于 Surface 实例，而不是含混的逻辑 Tab。

**建议状态规则，定稿前需与现有行为核对**

| 事件 | 建议行为 |
| --- | --- |
| Secondary 页面导航 | 不直接覆盖全局权威事实；若属于用户接管，先完成 Primary 变更 |
| Primary 变更 | 撤销旧物理 binding 的租约；旧命令不能自动重放到新页面 |
| 关闭一个窗口 | 释放该窗口的 Surface；按定义决定是否提升仍存活的 Surface |
| 全局关闭逻辑 Tab | 关闭全部对应 Surface，拒绝迟到事件复活 |
| Agent 任务结束 | 释放控制、保留当前 Tab 与页面 |

**代码调整与验收**

- [ ] 核对 Registry、Authority、Desktop Control 和右栏关闭路径是否遵守同一规则，只修改不一致处。
- [ ] 验收双窗口不同导航、操作中接管、关闭 Primary、全局关闭后迟到事件、重连后旧命令返回。

### R05：把 Top Layer 与焦点行为写入公共浮层规范

**依据与问题**

设计 §7 以普通 stacking context 描述浮层；`BrowserTabContent.svelte` 和 `RightPane.svelte` 已使用 Popover Top Layer 处理 guest 上方的菜单、标记和提示。普通 `z-index` 不是当前实现的充分条件。

**设计文档修改**

- [ ] 用实际 Top Layer 机制替换“普通 DOM 层级即可保证覆盖”的表述。
- [ ] RightPane 负责公共浮层规则；Browser 内容组件负责自身菜单和标记交互，不复制公共壳。
- [ ] 定义锚点定位、内容槽裁剪、Esc、外部点击、失焦和关闭后的焦点恢复。
- [ ] 非活动 Tab 的浮层必须关闭，不能因进入 Top Layer 而越过父级隐藏状态继续显示。

**代码调整与验收**

- [ ] 检查当前 popover 与 Tab 隐藏、右栏折叠、导航、组件销毁的联动。
- [ ] 存在重复机制时收敛必要共同行为，不为单个菜单建立新的全局管理系统。
- [ ] 验收菜单跨 guest 边界、标记编辑、Esc、切 Tab、拖动宽度，以及关闭后继续在原对话输入框输入。

### R06：明确 Popup 兼容范围

**依据与问题**

当前 `setWindowOpenHandler()` 拒绝创建额外窗口，并将合法 popup URL 导航到当前页。这符合单页产品约束，但不等价于保留完整 popup 语义。

**设计文档修改**

- [ ] 保留单页规则，同时明确依赖 opener、postMessage、命名窗口、脚本创建空白页的流程不保证可用。
- [ ] 列出普通新窗口链接、带提交数据的请求、空白脚本窗口、自定义协议等情况的处理规则。
- [ ] 定义被阻止时的可见提示和工具结果，不将失败宣称为“接管成功”。

**代码调整与验收**

- [ ] 核实当前 popup 导航是否保留必要请求语义，禁止把不同请求无条件转换为普通 GET。
- [ ] 对普通链接、表单新窗口提交、OAuth 弹窗、脚本空白窗口分别验证；不支持的场景返回明确原因。

### R07：补齐各内容类型的生命周期与资源规则

**依据与问题**

`RightPane.svelte` 保留浏览器组件、隐藏非活动项；终端组件按活动内容挂载，卸载时关闭 WebSocket 并销毁 xterm。此事实不能直接推导为后端终端进程会被终止，但说明需要分别验证进程、连接和显示状态。

**设计文档修改**

- [ ] 内容树说明“只有一个活动显示槽，但可存在隐藏且保活的 Browser 实例”，避免被照字面实现成切换即卸载。
- [ ] 增加 Browser、Terminal、Agent 的隐藏、切换会话、关闭 Tab、关闭窗口、Renderer 重载生命周期表。
- [ ] 终端分别约定进程存活、输出缓冲、重连、滚动位置与尺寸恢复。
- [ ] 浏览器明确 guest 释放时点与资源上限策略；需要资源回收时，不承诺未保存的页面内存状态无损恢复。
- [ ] 页面恢复区分逻辑 URL、登录状态、历史记录、表单内容和 DOM 内存状态；不可用一个“恢复成功”涵盖全部。

**代码调整与验收**

- [ ] 先核实后端终端断连和缓冲机制，再决定是否需要保留前端终端实例。
- [ ] 检查隐藏页面焦点、后台任务和 CDP 可用性，关闭后释放监听器、Target 与引用。
- [ ] 验收长时间命令运行时切换内容、反复切会话、多个 Browser Tab 关闭后的资源回收。

### R08：补齐 Worker 调用链和失效恢复矩阵

**依据与问题**

`desktop-control-server.ts` 调用 `AutomationWorker.execute()`；Worker 通过 Main 提供的通道执行 CDP。设计 §5.2 省略了 Worker，容易让后续实现把自动化算法重复放入 Main。

**设计文档修改**

- [ ] 绘制实际链路：Authority → Desktop Control → Worker 自动化执行 → Main 受控 CDP → guest；Main 直接负责的生命周期类命令单独说明。
- [ ] Authority 负责授权和逻辑事实；Main 负责物理生命周期、安全和 CDP 通道；Worker 负责自动化算法、快照与节点引用；Renderer 负责交互显示。
- [ ] 说明 `desktopEpoch`、`workerEpoch`、`surface_revision`、`navigationRevision`、lease fence 分别阻止哪类过期结果。
- [ ] 区分导航、同文档 URL 变化、frame detach、Target detach；按真实生命周期失效节点和会话，不把所有 URL 变化都理解为整个 CDP session 销毁。
- [ ] 定义取消和超时后的命令状态；输入、提交等写操作不能在重连后无条件重放。

**必须补充的恢复矩阵**

| 故障 | 必须说明与验证 |
| --- | --- |
| daemon 重启 | 重建逻辑事实和当前 binding；拒绝旧租约 |
| Worker 重启 | 握手、重新绑定、节点引用失效；物理页面是否保留 |
| guest 崩溃 | 原命令终止、新物理身份注册、视口恢复规则 |
| App Renderer 重载 | 旧 guest 释放、新 guest 注册、旧事件隔离 |
| Desktop 重启 | 新 epoch；只恢复承诺持久化的资料 |

### R09：澄清 Web 客户端与后端工具能力的区别

**依据与问题**

`crates/magi-browser-authority/src/capability.rs` 按浏览器开关、Desktop Host 状态及协议兼容性判定工具可用性；这不同于“当前访问页面的客户端是否为 Electron”。

**设计文档修改**

- [ ] 明确普通 Web 没有本地 guest 和 Desktop Renderer bridge。
- [ ] 明确手机连接一个已有 Desktop Host 的 daemon 时，是否允许会话中的 Agent 操作该 Desktop 的浏览器。
- [ ] 若允许，分别展示“当前客户端无内嵌页面”和“后端存在可授权的 Desktop 工具”；若禁止，应在授权层定义并落实限制。
- [ ] 不能只按前端运行环境隐藏按钮，就认为后端工具权限已被限制。

**验收**

无 Host 的 Web、有 Host 的 Web、Electron Desktop 三种情况分别检查显示、工具目录和执行授权；结果符合定稿规则。

### R10：同步规范和验收门槛

**依据与问题**

- 当前设计文档标为唯一基线，却与设备仿真 API、Top Layer、Primary 模型等代码事实不同步。
- `verify-browser-product-acceptance.mjs` 主要通过源码字符串及结构断言验证，不能证明真实运行行为。
- §11 将真实桌面验收和发布前检查放在“允许打包”之前，需区分验收用构建与正式发布包，避免循环门槛。

**修改清单**

- [ ] 设计文档只记录已定稿架构；待定决策明确列出，不把假设写成既定保证。
- [ ] 执行计划保留唯一状态账本，引用 R01–R10；本文不再维护另一套完成状态。
- [ ] 调整静态验收说明：源码检查证明结构约束，运行测试证明协议和状态行为，真实 Electron 证明显示、焦点与输入。
- [ ] 明确允许先构建候选包用于验收；正式发布仍遵循仓库完整预检、main 同提交 CI、Tag 和发布产物检查。
- [ ] 记录源码提交、未提交差异、build identity、平台、Electron 版本和复现步骤，不能用旧包通过证明新工作树通过。
- [ ] 按已确认根因修改实现，再删除失效实现、断言与文档；不机械删除合法的局部选区坐标计算。
