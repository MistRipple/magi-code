# Magi MCP 服务 · 设计基线

> 状态：本机回环 HTTP、stdio 与网络隧道模式已实现。工具由 daemon 统一执行，权限、审批、审计和持久化沿既有服务。
> 更新日期：2026-11-03。
> 相关文档：[工程约束与运行入口](README.md)、[Browser Runtime 设计](browser-runtime-design.md)。

---

## 0. 定位

Magi 同时提供 MCP 客户端和 MCP 服务端：客户端用于调用下游服务，本文定义服务端如何把 Magi 工具受控开放给外部客户端。

- **价值在治理，不在“又一个文件工具”。** 单纯的文件读写别的 MCP 服务也有。Magi 的差异化是：人工审批、变更账本（待处理变更的批准 / 回退）、快照与恢复、审计、知识与语义检索，以及与 Magi 会话事实的一致性。产品定位与文案围绕这些。
- **默认只本机。** 网络模式（含 Cloudflare 隧道）已实现，但必须显式开启，而且是全案风险最高的部分（§10、§15）。

## 0.1 外部聊天与执行目录

用户流程是“连接一次，每个新聊天首次使用时选择一次目录”。目录不是聊天身份；多个聊天可同时选择同一目录，就像 Magi 项目下的多个普通会话。

- `conversation` 令牌在创建时不绑定项目或目录。客户端使用已有固定 HTTPS/stdio 连接，无需为不同项目重复配置连接器。旧 `external` 令牌不自动扩大权限，继续使用冻结的项目目录。
- 新聊天首次调用 `magi.session.start({conversation_id, title?})`。`conversation_id` 是该客户端提供的稳定聊天 ID；客户端无法取得产品聊天 ID 时，应为该聊天生成一次 UUID 并在重连时复用。服务端按 **token_id + conversation_id** 去重，生成不可猜测的 `magi_session_id`。
- `title` 用简短自然语言概括用户任务，不附加项目名、工作区名、文件夹名、路径、客户端名或会话 ID。项目和目录信息已由上级分组表达。侧栏保持原有单行布局，主标题只展示该聊天名称；客户端来源仅放在悬浮提示和可访问名称中，不增加副标题或换行。没有标题时以客户端名称作为入口。未命名会话不再把 `conversation_id` 写成标题，历史中这类自动生成的 ID 标题在 MCP 概要投影中隐藏，保留用户后来重命名的标题。已存在的冗余标题通过既有会话改名接口修改，UI 不猜测和裁剪用户标题中的项目词语。
- 标准 MCP 的 HTTP `Mcp-Session-Id`、stdio 连接和 JSON-RPC request ID 都不是 Web 聊天身份。不能据此自动推断聊天边界，不能因连接重建而重新选择目录，也不能声称任意 Web Agent 天然会传聊天 ID。客户端必须遵循初始化说明及工具 schema；真实厂商兼容性需要分别验收。
- 尚未选择时返回 `awaiting_directory`，Magi 全局托盘展示客户端与聊天标题，用户从已有项目目录中选择，也可复用现有目录选择器注册其他本地目录。批准只冻结所选源目录，不扩大到项目的其他目录或后续新增目录。未批准前普通工具拒绝执行。
- 选择之后，用同一 `conversation_id` 查询初始化状态，得到 `ready`；之后每次普通工具调用携带 `magi_session_id`。该参数由 MCP 接入层校验并剥离，不传给内部工具。普通调用不会触发目录重选，也不会跟随 Magi 当前活动项目。`ask` 模式的工具执行确认与首次目录选择是两种不同交互。
- 已批准会话的身份与冻结目录持久化在 daemon 管理的 `mcp-conversations.json`；会话及 canonical、快照仍走现有 SessionStore。待选择请求 10 分钟到期，最多 100 个；重启不恢复未批准请求，同聊天重试会重新提出。拒绝记录不会被同 ID 重试自动推翻。删除/清理外部会话后旧执行 ID 失效，重新开始必须再次授权。
- 本机管理接口 `GET /mcp-server/directory-requests` 和 `POST /mcp-server/directory-requests/{session_id}` 只展示、处理未过期且令牌有效的请求，经公网入口一律拒绝。会话绑定不可重写。不同令牌不能借用彼此的会话 ID；令牌吊销、目录失效和会话删除都阻止后续调用。
- 审批及侧栏使用 `sessionId` 定位，审计同时保存客户端和会话 ID。共享目录不会合并会话记录或变更账本，也不引入目录独占锁。
- Cloudflare 命名隧道及固定域名配置与这些会话绑定独立，本次功能调整不更换域名、隧道令牌或端口。

## 1. 固定规则

以下规则是唯一结论源，改动必须先经用户确认并更新本节。

| 编号 | 规则 | 理由与边界 |
| --- | --- | --- |
| M1 | **只有一个 Magi MCP 服务端**，按标准 MCP 协议实现 `initialize`、`tools/list`、`tools/call`（并按需 `notifications/tools/list_changed`）。工具由服务端直接暴露，不做“通用 inventory / call 二次包装”，不做文本协议。 | 客户端能看到真实的参数 schema、说明与只读 / 破坏性标注。 |
| M2 | **每个客户端一份可吊销、可编辑的令牌**，默认以 `conversation` 模式标识客户端，每个外部聊天首次使用时在本机选择目录；已有 `external` 模式仍固定项目，完整工具目录固定开放，授权方式可选每次询问、允许读写或完全访问。校验只用哈希；原文以用户私有权限文件保存，可在设置里重新查看；配置可编辑（§5.3），可设有效期，可随时吊销。 | 连接身份、聊天身份和执行目录分别拥有事实；目录选择只在聊天首次使用时发生，工具审批仍按令牌模式。 |
| M3 | **所有调用都先过：认证 → 完整 MCP 工具目录 → 路径校验 → 审批 → 执行 → 审计。** 没有旁路，本机与网络客户端走同一条链。会话初始化只创建待选择请求，不执行项目工具；目录授权只能由可信本机管理入口提交。 | 网络模式与本机模式只在传输不同，不允许出现两套执行路径。 |
| M4 | **MCP 令牌统一开放完整工具目录；`ask` 模式下每次工具调用都在 Magi 界面询问，`read_write` 模式自动执行普通读写（命令、删除、回退和不透明的下游操作仍询问），`always` 模式自动执行全部工具。** 三种模式都继续经过工作区路径校验与硬性策略（见 §7 授权边界）。 | 默认模式保守，明确选择自动授权范围后减少重复弹窗。 |
| M6 | **外部客户端的调用记录在“外部工具会话”里。** 每个外部聊天对应一个由 Magi 管理的会话（类型为外部工具），同一客户端令牌可拥有多个聊天，复用既有的审批、变更账本、审计与 canonical。不为外部调用另建第二套账。 | Magi 的变更批准 / 回退、快照恢复都以会话为单位。 |
| M7 | **每次调用只对该会话在本机获授的已注册目录有效。** 路径必须规范化并限制在工作区根内，拒绝符号链接逃逸；永远不可访问 Magi 状态目录、个人会话目录、凭据与系统敏感路径。 | 防止越权读写。 |
| M8 | **不暴露管理面：** 设置、模型与密钥、令牌管理、隧道配置、浏览器宿主、子代理，均不作为工具开放；业务 MCP、下游 MCP 工具与 Skill handler 按完整外部工具目录开放，授权方式由令牌的 `ask` / `read_write` / `always` 决定。 | 管理面永不开放，工具调用沿统一的审批策略执行。 |
| M9 | **网络模式必须显式开启，且默认关闭。** 开启前展示风险说明；令牌泄露等价于对该工作区的读写（如已授予写入与执行则等价于远程执行）。提供一键“撤销全部令牌并停止隧道”。 | 明确后果、可立即止损。 |
| M10 | **MCP 服务的监听端口与隧道入口独立于 Magi 主应用。** 不挂到主 app、不共享其鉴权中间件、不暴露任何 `/api/*` 路由；不复用 Magi 现有“远程访问”隧道的用户会话路由与访问令牌。 | 现有远程访问是给 Magi Web / 手机用的，认证与路由边界不同。 |
| M11 | **只做单向数据归一，不保留旧行为分支。** 旧令牌统一升级为完整工具目录；旧 `deny` 授权值映射为默认询问。其他无法读取的令牌仍视为无令牌，daemon 不得因此加载失败。 | 保留既有客户端连接数据，同时收敛到唯一授权模型。 |
| M12 | **所有拒绝与失败都返回明确的 MCP 工具错误**，不得伪造成功，也不得在挂起超时后继续执行。 | 客户端与用户都需要可依据的结果。 |

## 2. 目标与非目标

**目标**
1. 本机：任何 MCP 客户端通过 stdio 或回环 HTTP 使用 Magi 工作区的完整工具目录，默认每次调用都经 Magi 询问；也可选择允许读写或完全访问。
2. 网络：显式开启后，通过 Cloudflare 隧道让远端 MCP 客户端使用同一套完整工具目录，安全边界由令牌、路径、安全策略、审计和撤销保证。
3. 每个客户端的调用可见、可审计、可回退（变更账本）。

**非目标**
- 不做 MCP 客户端的托管与发现（Magi 已有的客户端能力不变）。
- 不开放管理面（M8）与子代理；下游 MCP 与 Skill 以网关目录项开放，并按令牌的三档权限处理。
- 只有用户选择 `read_write` 或 `always` 时才自动普通读写；执行命令及其他操作只有 `always` 自动放行。
- 不承诺兼容所有 MCP 客户端的所有可选特性；核心只依赖标准 `tools/list` / `tools/call`。

## 3. 总体架构

```text
MCP 客户端（Claude Desktop / Cursor / Cline / ChatGPT 连接器 / …）
   │  stdio（本机子进程）        │ Streamable HTTP（回环 127.0.0.1）      │ Streamable HTTP（网络：Cloudflare 隧道）
   ▼                             ▼                                        ▼
┌────────────────────────── Magi MCP 服务（daemon 内，独立监听） ──────────────────────────┐
│ 认证（令牌 / 可选 OAuth）→ 令牌范围（工作区、完整工具目录、归属模式）→ 限流与体积限制      │
│        │                                                                                │
│        ▼                                                                                │
│ 工具目录（按令牌生成，命名空间化）→ 路径与范围校验 → 审批策略 →                          │
│        │                                                                                │
│        ▼                                                                                │
└────────┬───────────────────────────────────────────────────────────────────────────────┘
         ▼
既有执行 owner（tool runtime、权限与安全闸、snapshot 变更账本、audit / canonical）
```

- 服务端是**薄的协议与策略层**，不复制工具实现：调用最终交给现有的工具运行时与 loop 执行，审批走现有审批链，变更进现有变更账本。

## 4. 核心概念

| 概念 | 含义 |
| --- | --- |
| 客户端（client） | 一个被用户创建并命名的 MCP 使用者，例如“Cursor · 笔记本”“ChatGPT 连接器”。 |
| 令牌（token） | 客户端的凭据。校验只用哈希；原文另存于私有文件，可随时重新查看（§5.3）；服务端另存前缀与元数据；绑定工作区、完整工具目录、授权方式、归属模式、有效期。 |
| 工具范围 | MCP 客户端统一使用完整工具目录；工具本身仍受工作区路径和硬性策略限制。令牌记录没有工具范围字段；历史文件里残留的 `profile` 键读取时被忽略，下次保存即不再写出。 |
| 调用确认（approval mode） | `ask`（每次工具调用都询问，默认）、`read_write`（自动允许普通读写，命令及破坏性/不透明操作仍询问）或 `always`（完全访问，自动执行完整工具目录）。这是每个 MCP 客户端令牌的唯一权限选择；旧版本的 `deny` 读取为 `ask`。 |
| 归属模式 | `external`：所有调用归到该令牌自己的外部工具会话。 |
| 外部工具会话 | Magi 为每个 `external` 令牌管理的一个会话，承载该客户端的所有调用、审批与变更。 |

## 5. 认证与令牌

### 5.1 令牌
- 创建：设置页选择工作区、授权方式和有效期；创建后立即展示原文，之后可随时重新查看（§5.3）。
- 存储：校验用的**哈希**（不可逆）、前缀（用于列表识别）、名称、工作区、完整工具目录标记、授权方式、归属模式、创建与最近使用时间、过期时间，与**原文**分开存放：原文在 state root 下的私有文件里（仅当前 OS 用户可读写，0600），只服务于“重新查看 / 复制”，不参与校验。原文不进日志、不进诊断、不进 canonical、不进导出与备份。
- 校验：恒定时间比较；过期、吊销、工作区被移除即失效；失败统一返回认证错误，不区分原因。
- 吊销：认证即时失效，已有连接的后续请求一律拒绝（本地 socket 在下一条请求时关闭连接）；在途调用按 §12.1 通知取消并结算，待审批调用以错误收口。吊销后的令牌只读，不可再编辑或查看原文。

### 5.2 协议层认证
- **本机 stdio：** 客户端启动 daemon 自带的中继：`<daemon 可执行文件> mcp-relay --stdio --endpoint <socket> [--token-file <path>]`（令牌也可由环境变量 `MAGI_MCP_TOKEN` 提供；设置页生成的配置已填好绝对路径）；stdio 进程只是轻量中继，经仅当前 OS 用户可访问的本地 socket 连到 daemon，令牌校验在 daemon 侧完成。
- **HTTP（回环与网络）：** 标准 `Authorization: Bearer <token>`。同时校验 `Origin` 与 `Host`（防止 DNS 重绑定），拒绝无令牌请求。
- **OAuth 2.1：** HTTPS 隧道入口提供 protected-resource / authorization-server discovery、公开客户端动态注册（DCR）、授权码 + S256 PKCE 和刷新令牌。授权网页只显示等待状态，用户在本机设置 → MCP 服务选择一个已有、有效且允许公网的客户端并批准；授权不会创建项目目录权限。OAuth 仅委托该客户端现有权限，之后每次请求重新校验其有效期、公网开关、密钥代次和权限档；每个新聊天仍调用 `magi.session.start` 并在本机首次选目录。
- 网络模式在隧道外再叠加 Cloudflare Access 是**推荐但可选**的一层：只有当客户端能带自定义头（服务令牌）时才可用，不能替代 Magi 自己的令牌。


#### OAuth 持久化与边界

- OAuth 元数据和令牌哈希保存在 `state_root/mcp-oauth.json`（0600、原子提交），不保存 access / refresh 原文。动态客户端注册保持稳定，重启后可继续刷新已有授权。
- 单一 scope `magi` 表示使用本机明确选择的客户端权限，不在 OAuth 内复制目录、会话或工具权限事实。
- access 最长一小时、整次授权最长 90 天且不超过父客户端有效期；刷新不延长整次授权。refresh 单次轮换，重放立即收回同族授权；父令牌吊销、到期、关闭公网或重新生成密钥使 access / refresh 立即失效。降权在下一请求生效。
- 待批准请求五分钟到期，批准后的授权码一分钟到期、只使用一次；client ID、精确回调地址、resource 和 PKCE 必须一致。拒绝与成功回调均带原 state 和准确 issuer。
- OAuth 只在当前运行的 HTTPS 隧道域名上提供；不从任意 Host / Forwarded 头推导 issuer，不将 HTTP 直连升级成可信 TLS。公网监听不包含本机批准接口。
- 公开入口按来源限流，限制正文、注册数、待批准数和授权数；网页禁止缓存、外链资源与嵌入。客户端显示名称仅是其声明，本机批准页展示完整回调与资源地址，未选择权限时不能批准。
- 当前支持公开客户端 `none` + DCR；未声明 CIMD、OIDC 或 confidential client 能力。第三方产品端的可用性需要真实测试，不能由协议测试推断。

### 5.3 重新查看与编辑

> 状态：**重新查看、编辑（名称 / 授权方式 / 有效期 / 允许公网）、重新生成密钥与专属客户端配置已实现**（`mcp_runtime.rs`、`routes/mcp_server.rs`、设置页令牌卡片）。工作区不可编辑，换工作区需新建令牌；工具范围固定为完整目录，不提供令牌级白名单。

客户端卡片、工作区选择和专属配置同时展示绑定工作区的名称与完整路径；连接始终操作 Magi 所在机器上的该工作区，不跟随外部客户端当前项目切换。外部令牌的 MCP `initialize` 返回简短的 `instructions`，说明工作区名称、根目录、相对路径基准与固定绑定规则；不增加会话标识参数或额外工具调用。

**重新查看**
- 令牌属于用户的本地数据，**随时可查看、可复制，没有二次确认，也不分权限档**。令牌卡片上点“查看配置”即取回原文与带原文的客户端配置，收起即丢弃；浏览器端不落任何存储。
- 令牌原文仅允许可信本机来源读取，网络来源不能取回；每次读取记录脱敏审计。私有文件权限限定为当前 OS 用户。
- 旧版本创建的令牌只有哈希，原文无法找回：卡片提示“无法查看”，只能“重新生成”。

**编辑（不换原文，客户端无需重新配置）**

| 可编辑项 | 说明 |
| --- | --- |
| 名称 | 只改展示名。外部工具会话标题在创建时取名，**暂不随改名同步**。 |
| 工具范围 | 固定为完整工具目录；所有调用仍受工作区、路径和安全策略限制。 |
| 有效期 | 可延长、缩短或改为不过期。 |
| 允许公网 | 仅决定令牌能否从公网入口使用，不改变工具目录。 |
| 工作区 | **不可编辑**：使用其他工作区需创建另一份客户端连接。 |
| 调用确认 | 令牌级 `approval_mode` 已实现：`ask` 每次询问、`read_write` 普通读写自动执行、`always` 完全访问自动执行。历史令牌没有该字段，按 `ask` 读取。工作区路径、硬性策略仍会拒绝越界调用。 |
| 并发上限 | 每令牌固定为 8，回环与网络一致，暂不可配置。 |

- **生效时机：** 服务端每次调用都从令牌库取最新记录，所以编辑从下一次调用起生效，已建立的连接不断开。
- **收紧立即生效：** 降权、缩短有效期、关闭公网时，该令牌挂起的审批立即作废并以明确错误收口，不继续等待（升权、改名、延长有效期不影响挂起审批）；重新生成密钥同样作废挂起审批。工具范围保持完整目录。
- **重新生成密钥：** 生成新原文，旧原文从下一次调用起即认证失败（每次请求都重新校验，不依赖连接状态），其余配置不变。
- **审计：** 每次查看原文、编辑（旧值 → 新值）、重新生成都写审计，不含原文。

## 7. 审批与权限

- **审批发生在 Magi 界面**（主窗口对话区 / 系统通知），复用现有审批链与安全闸；MCP 客户端只收到最终结果。
- **令牌权限**：每个令牌有三种方式：`ask` 对每次工具调用逐次询问（含读取），`read_write` 自动普通读写但对命令及破坏性/不透明操作逐次询问，`always` 完全访问并自动执行。询问只作用于当前这次调用：允许一次或拒绝后，下一次调用仍按令牌的方式处理，不存在「本轮允许」。
- **授权边界：** 自动授权只免除人工确认；路径越界、状态目录、HardBlock 和执行访问档禁止等硬性拒绝始终生效。
- **调用挂起：** `tools/call` 在审批与执行期间保持挂起。默认挂起时限 90 秒（必须早于客户端与隧道侧的超时，按需配置）。超时或用户拒绝，在**同一个 `tools/call`** 中返回明确工具错误，不执行、不在稍后补执行。
- **无人值守：** Magi 界面未打开或无人响应时，需要审批的调用只会超时失败；不提供“无人时自动通过”。
- **限流与并发：** 每令牌限制并发调用数与调用频率，请求体与响应体设上限；超限返回明确错误。
- **按会话记录：** 每次审批、执行、拒绝都写入该令牌的外部工具会话与审计。

## 8. 路径与范围限制

- 令牌只对绑定工作区有效；所有路径参数先规范化再校验：必须落在工作区根内，拒绝 `..` 逃逸与符号链接逃逸，写入目标的父目录也要校验。
- 永远拒绝：Magi 状态目录（全局与工作区内的 `.magi/` 运行态）、个人会话目录、凭据与密钥目录（如 `~/.ssh`）、系统敏感路径；具体黑名单集中在一处维护，不散落。
- 工作区不再注册或令牌被吊销后，已有连接的后续调用一律拒绝。
- 结果大小设上限；超限返回带提示的截断，不做静默截断。
- 成功的 JSON 对象结果同时返回 MCP `content` 文本与同值的 `structuredContent`，让 ChatGPT 连接器拿到真实字段；非对象或被截断的文本不伪造结构化内容。两种表示使用同一份执行结果。

## 9. 会话、变更账本与审计

- **外部工具会话（M6）：** `conversation` 模式下每个外部聊天一个，标题体现客户端与聊天；目录首次选择后固定。多个聊天可选择同一目录，canonical 记录和变更账本仍独立。旧 `external` 固定项目令牌维持一个令牌一个会话的原语义。它承载调用记录、审批请求与变更，因此现有的“待处理变更 → 批准 / 回退”“快照与恢复”“审计”自然适用。
- **变更可回退：** 外部客户端写入的文件经同一个变更账本记录；用户可在 Magi 里查看差异并批准或回退，与 Magi 自己 agent 的改动一致。
- **审计：** 每次调用记录令牌前缀、客户端名称、工具名、路径 / 参数摘要、审批结果、执行结果与时间；不记录令牌原文，不记录文件正文。
- **展示（已实现）：** 外部工具会话是一个**真正的会话**：调用写进它自己的 canonical 时间线，和内部对话 同一套事实、同一套展示（工具卡片、diff 卡片、长输出按需加载、历史分页）。侧栏里它是本次会话已选择的工作区下的一行（与普通会话并列，图标和“外部”标记区分；不进用户的会话列表与“最近”），点击就是切换到这个会话，在主对话区打开，输入区换成一条只读提示（“来自 X 的外部会话，只读”）。用户只能查看，不能在其中发起模型对话。
- **被拒绝的调用：** 进入工具之前就被拒绝的调用（权限设置、路径范围、参数上限）也作为一条已拒绝的工具项写进会话，结果是和其他策略拒绝同一种结构（`external_tool_policy_rejected`），工具卡片按拒绝展示。
- **隐私与留存：** 设置 → MCP 服务 → 活动里有两项：“保存调用内容”（默认开；关闭后只保存工具与路径，大段参数省略，读到的内容、命令输出、写入的内容不落库，会话里显示“内容未保存”）和“保留时间”（默认 30 天，可选 7 / 30 / 90 天或不自动清理；到期且没有在途调用的外部会话整体删除，连同变更账本，之后该客户端再调用会建立新会话，每小时检查一次）。设置存在 `mcp-server.json`。审计仍然不含正文，两者的取舍：审计面向长期留存与合规，外部会话面向用户回看过程，所以带正文但可关闭、有期限、只在本机状态目录。
- **接口：** `GET /mcp-server/sessions`（有外部会话的客户端概要，最近的在前）、`PUT /mcp-server/external`（`saveContent` / `retentionDays`）；`DELETE /mcp-server/audit` 清理记录时一并删除对应令牌的外部会话；侧栏入口的刷新由 `mcp.activity` 事件（对所有事件流作用域可见）通知，调用内容本身走会话的 canonical 事件。
- **新消息滚动：** 外部工具卡片沿用普通对话的自动跟随与阅读锚点逻辑。在底部或距底部 40px 内向下阅读时，新调用继续跟随；列表尚未溢出、或已经到底部时，向下输入不能因没有后续原生 `scroll` 事件而永久关闭跟随。主动向上阅读时保持当前位置，点击「回到底部」恢复跟随，不按 MCP 来源强制滚动。
- **来源展示：** 来源只在会话底部固定提示一次（客户端名与只读执行记录）。原始与摘要模式均不把 `noticeKind=external_client` 的活动段开场记录渲染为正文或阶段标题，轮次导航也不再用它作为预览和定位锚点。canonical 原始记录保留，继续承载活动段身份和运行状态；工具调用、审批、错误及结束时间照常展示，不按中文文案或 ID 后缀猜测需要隐藏的消息。

### 9.1 三种展示场景的统一约定（已定案）

Magi 里有三种“有工具被调用”的场景，界面遵循同一条原则：**谁发起，就标明谁；过程都在会话里看；确认都在调用上点。**

| | 发起方 | 过程在哪看 | 来源标识 | 确认在哪点 | 事实源 |
|---|---|---|---|---|---|
| Magi 内部对话 | 用户 → Magi 自己的 agent | 会话时间线 | 无（默认就是 Magi 自己） | 会话内授权托盘 | 会话 canonical 时间线 |
| Magi MCP（外部 agent） | 外部 agent 自己发起，没有 Magi 的 turn | 对应工作区下的外部会话行 → 主对话区（输入区换成只读提示） | 会话标题区分客户端与聊天，侧栏行标「外部」 | 外部会话自己的授权托盘（按令牌的三档权限处理）；全局托盘只在没有打开该会话时提醒 | 外部会话的 canonical 时间线（活动段 Turn） |

- **外部会话归属工作区：** 会话已选择的工作区在侧栏里时，每个外部聊天作为该工作区下的一行（与普通会话并列，图标和“外部”标记区分）；工作区折叠时工作区行出现提示点（有待确认的调用）。移除工作区会立即吊销固定项目令牌；逐会话连接的该项目目录授权失效，但客户端连接及其他项目会话不随之撤销，历史外部会话按保留策略继续保留，重新注册工作区不会恢复旧令牌。
- **确认只有一个入口组件：** 内部对话、外部会话的确认都在会话自己的授权托盘里；全局托盘只是“你不在那个外部会话里时”的提醒，用同一个存储（`external-approvals`），展示绑定工作区名称和路径，并提供「查看调用过程」进入已有外部会话；从设置页点击也会返回主对话。正在查看该外部会话时不重复弹。设置页不再重复展示待确认。
- **待确认的提醒：** 外部调用等待确认而窗口不在前台（失焦、隐藏到托盘）时，前端发一条系统通知（Web Notification，带客户端名称与操作摘要；macOS 点击通知会激活应用并显示窗口，同时打开对应的外部会话）。待确认只有 90 秒，错过就超时，所以全局托盘浮层保留为窗口在前台、但不在该外部会话里时的提醒。只对应用打开之后新出现的待确认提醒，启动时已存在的不重复通知；浏览器（非桌面）模式没有通知权限时不发。
- **设置页只留审计：** 「调用记录」是长期留存的审计（工具与路径摘要，无正文）；想看过程时提示用户打开外部会话，选中某个客户端时提供「查看调用过程」直达。

> 当前执行合同：外部调用经 `external_tool` / `external_approval` 进入外部工具会话，复用 canonical、审批、变更账本与审计；不得增加旁路执行入口。

## 10. 传输与网络模式

### 10.1 三种传输

| 传输 | 用途 | 监听 / 入口 | 认证 |
| --- | --- | --- | --- |
| stdio | 本机客户端由配置直接拉起 | 无监听；经本地 socket 连 daemon | 令牌文件 / 环境变量 |
| 回环 HTTP | 本机支持 HTTP 的客户端 | 仅 `127.0.0.1` 随机高端口，写入 `state_root` 端口文件 | Bearer 令牌 + Origin / Host 校验 |
| 网络 HTTP（隧道） | 远端客户端（含 ChatGPT 连接器） | 回环端口经隧道对外 | Bearer 令牌（可选 OAuth、可选 Cloudflare Access） |
| 网络 HTTP（内网／公网直连） | 内网可达或有公网 IP / 端口映射的用户，不经隧道 | 同一个 HTTP 入口改为监听用户指定的地址（如 `0.0.0.0`），见 §10.4 | Bearer 令牌 + 对端地址判定 + Host 白名单 |

### 10.2 Cloudflare 隧道方案（网络模式）

| 方案 | 特点 | 定位 |
| --- | --- | --- |
| Quick Tunnel | 无需账号；地址每次启动都变；无法做稳定连接器配置 | **默认、已实现**：零配置，适合临时或偶尔的远程使用；网络模式开关**不持久化**，daemon 重启后关闭 |
| **命名隧道** | 用户自己的 Cloudflare 账号与域名；稳定地址；令牌（隧道 token）按文件引用，不进命令行、日志、settings | **已实现**，见下 §10.2.1 |

- 复用现有 `cloudflared` 托管能力（sidecar 检测、启动、监控），但**入口规则独立**：隧道只转发到 MCP 服务的独立回环端口，不转发到 Magi 主应用端口（M10）。
- 隧道状态、公网地址、启动 / 停止、复制地址都在设置页；停止隧道或“撤销全部令牌”不影响本机模式。

#### 10.2.1 命名隧道（已实现）

- **设置呈现**：页首显示当前 API 服务地址及 `stateRoot`，只展示当前实例事实，不推断另一个实例的状态。网络页优先显示地址类型、公网 MCP 地址与真实运行状态；域名与检查连接入口保持可见，编辑表单按需展开并预填已存域名，取消或保存后清空隧道令牌。OAuth 指引独立于默认折叠的手动令牌配置；只有展开手动配置才请求含令牌片段，关闭后丢弃。未启用的高级网络直连默认收起。
- **配置**：设置页「固定公网地址（命名隧道）」填域名与隧道令牌（粘贴整条 `cloudflared service install <令牌>` 命令也行，Magi 取其中的令牌）。接口 `PUT/DELETE /mcp-server/named-tunnel`、`POST /mcp-server/named-tunnel/verify`，仅本机入口。域名与令牌格式在保存前校验（令牌须是含 `a`/`t`/`s` 的 base64 JSON；拒绝 `trycloudflare.com`、IP、非法域名）。
- **存储**：`state_root/mcp-named-tunnel.json`（0600，原子写），与令牌原文同级别保管；不进主配置、状态接口、日志与审计。状态只返回 `mode`（`quick`/`named`）与 `namedHostname`。
- **运行**：`cloudflared tunnel --no-autoupdate run`，令牌只通过环境变量 `TUNNEL_TOKEN` 传入（不进命令行）；看到 `Registered tunnel connection` 才算就绪，公网地址就是配置的域名。令牌对应的隧道不存在或被撤销时（日志 `Failed to get tunnel`）立即报 `tunnel_token_invalid` 并结束进程，不无限重试。Cloudflare 侧由用户把公共主机名转发到 `http://127.0.0.1:<MCP 端口>`；该端口已持久化固定。
- **重启恢复**：只有命名隧道会持久化网络模式开关（`mcp-server.json` 的 `network`）。上次开着、仍有有效的网络令牌时，daemon 启动后自动恢复，地址不变；Quick Tunnel 永不恢复。这是一个刻意的取舍：用户为固定入口显式配置并开启过，重启不应让远程客户端静默失联；用户关闭网络模式后不再恢复。
- **变更**：网络模式运行中保存新配置会立即切换到新隧道；删除命名隧道会同时关闭网络模式，不会悄悄退回随机地址。
- **连通性检查**：从公网请求 `https://<域名>/mcp`（不带令牌），401 表示 DNS、Cloudflare、隧道与 Magi 入口整条链路都通；530/1033、502/503/504、解析失败分别给出具体提示。
- **配置向导（内置 Skill）**：`magi-cloudflare-tunnel`，随 Magi 发布，用内置浏览器协助用户完成 Cloudflare 一侧的步骤（见 §10.2.2）。

#### 10.2.2 内置 Skill 与向导边界

- 内置 Skill 与用户安装的 Skill 走同一套机制：说明文件写入 `state_root/builtin-skills/<id>/SKILL.md`，并在 `skillsConfig.instructionSkills` 登记普通条目（可停用、可在输入框用 `/` 唤起），条目带 `builtin: true`。**可以停用，不能删除**：`/settings/skills/remove` 拒绝移除内置条目，整体保存配置时漏掉的内置条目会被补回，启动时也会补齐，设置页不显示删除按钮而显示“内置”标记。安装记录在 `builtin-skills/.installed.json`，版本不变就不重写说明文件；Magi 升级带来新版本时才刷新说明文件并保留用户的启停选择（`crates/magi-api/src/builtin_skills.rs`）。
- 向导**不代做**：注册账号、邮箱与人机验证、登录与双重验证、付款方式、把域名 NS 交给 Cloudflare，都由用户本人完成。
- 向导**不接触令牌**：Cloudflare 隧道页面会显示带令牌的安装命令，Skill 明确要求不截图、不读取页面文字、不复制，由用户自己复制后粘贴到 Magi 设置页，令牌因此不进入模型上下文和会话记录。
- 向导的页面导航依赖 Cloudflare 控制台当前的界面，改版后需要更新 Skill 文字；命名隧道的后端逻辑不依赖页面结构。
- **未验证**：本机没有 Cloudflare 账号，真实域名下的端到端连通（令牌有效、公共主机名转发、`verify` 返回 401）尚未验证；已用真实 cloudflared 验证了启动参数、令牌不上命令行、无效令牌立即报错。

### 10.3 网络模式的额外要求
- 默认关闭，开启前展示风险说明（M9）。
- 隧道模式仅接受 HTTPS（由隧道终结 TLS）；直连公网是明文 HTTP，见 §10.4；服务端仍校验 `Host` 与 `Origin`。
- 每令牌限流、请求体上限、并发上限；连续认证失败按来源退避。
- 网络令牌同样绑定完整 MCP 工具目录；开启公网和创建网络令牌仍需要用户显式操作。
- 交付前必须完成一次专门的安全评审（§14 后续验证范围）。

### 10.4 网络直连（内网／公网，已实现）

不经隧道，HTTP 入口直接监听 `0.0.0.0` 或某块网卡的 IP。支持内网 IP、公网 IP 或域名；客户端必须能路由到该地址。公网 IP 在路由器上时需要端口映射。内网接入同样要求令牌允许网络访问。

- **配置**（设置 → 网络访问 → 网络直连；`PUT /mcp-server/direct`，仅本机入口）：监听地址（默认 `0.0.0.0`，必须是 IP 且属于本机）、客户端访问地址（域名或内网／公网 IP，不含端口，最多 8 个，同时是 `Host` 白名单）、可选固定端口（防火墙需要放行的端口，默认沿用已持久化的端口）。配置持久化在 `mcp-server.json` 的 `direct`。
- **开启条件**：必须显式确认风险；至少有一个有效且允许网络使用的令牌；客户端访问地址不能是 `0.0.0.0`、回环、组播或 `localhost`。监听失败（端口被占用、地址不属于本机、无权限）时原样回滚到原配置并报错。
- **对端地址决定“本机请求”**：HTTP 层取连接的真实对端 IP（`ConnectInfo`）。对端不是回环地址的连接，无论 `Host` 写什么，都按网络请求处理——`Host` 必须在客户端访问地址白名单里（自称 `127.0.0.1` / `localhost` 一律 403）、只接受 `network` 令牌（本机令牌与“令牌不存在”不可区分，401）、受限流与认证失败退避约束，且限流来源取真实对端地址，**不信任** `X-Forwarded-For` 等请求头。回环对端（本机客户端、Cloudflare 隧道、同机反向代理）保持原规则；同机反向代理用公网域名作 `Host` 时同样按网络请求处理，来源取 `CF-Connecting-IP` / `X-Forwarded-For`（此时只有本机进程能写这些头）。
- **传输是明文 HTTP**：令牌在网络上不加密。页面在开启前、在配置里都明确写出；要在公网上使用，应在前面放一个终止 TLS 的反向代理（Nginx、Caddy 等）并只暴露它。这是与隧道模式（Cloudflare 终止 TLS）的关键差别。
- **收回**：吊销、过期（在撤销 / 改令牌时检查）最后一个允许网络使用的令牌时，直连立即关闭并回到仅回环监听；重启时也会检查。stdio 本地 socket 与本机回环端口不受影响。
- **重启恢复**：开着时重启后自动按上次配置恢复监听（用户为固定入口显式配置过）；没有网络令牌或监听失败时退回仅本机，失败原因显示在状态里，不影响本机服务。
- **已验证**：在本机局域网 IP 上用 `0.0.0.0` 监听，从非回环地址连接——网络令牌 200，本机令牌 401，自称 `Host: 127.0.0.1` / `localhost` / 未知主机均 403，无令牌 401；回环对端的本机令牌 200。未验证：真实公网 IP、NAT / 云安全组放行。

## 11. 设置与界面

设置 → “MCP 服务”（或“对外工具”）：
面板按用途分为四个分组：**连接**（总开关、通用配置模板）、**客户端**（令牌列表与新建；已失效的令牌默认折叠，新建表单默认收起）、**公网访问**（网络模式、添加到远程客户端、命名隧道）、**活动**（待确认调用与调用记录，待确认数显示在分组标签上）。分组只是界面状态，不持久化。

1. **总开关**与状态：本机服务是否运行、端口、活动连接数。
2. **客户端与令牌列表**：每个客户端一张卡片，显示名称、工作区、授权方式、归属模式、有效期、最近使用；支持创建、重新查看 / 复制令牌、编辑、重新生成密钥、吊销（§5.3）。每张卡片的“查看配置”给出**专属客户端配置**（stdio 与 HTTP JSON、Claude Code 一行命令；开启公网时还有远程配置）：服务名取 `magi-<工作区名>-<客户端名>`，令牌原文已填入，可直接粘贴（页面底部保留带占位符的通用模板）；stdio 命令指向 daemon 自带的 `mcp-relay` 绝对路径，用户不需要另装任何可执行文件。多个客户端的配置可以同时放进同一个客户端配置文件。
   - **令牌来源要说清楚**：“连接”分组的配置卡片先说明“配置里的令牌来自‘客户端’分组，每个 MCP 客户端一个令牌，可随时在令牌卡片上重新查看”，并让用户直接选一个客户端，令牌自动填进 HTTP / stdio / Claude Code 命令（默认选第一个能填入的客户端）；选“保留占位符”时说明 `MAGI_MCP_TOKEN` 是环境变量名、值就是令牌，HTTP 里则写在 `Authorization: Bearer` 后。还没有令牌时直接给“去创建客户端令牌”按钮（跳到“客户端”分组并展开新建表单）；公网访问缺少网络令牌时同理。旧版本创建的令牌没有原文，选项里标明并提示去重新生成。
3. **公网访问**：网络模式（隧道）的开关、风险说明、隧道方案与状态、公网地址、启动 / 停止，凭据只显示引用与状态；以及**直接对公网开放**（§10.4）。
   - **隧道就绪后显示“添加到远程客户端”**：选一个允许公网且可查看原文的令牌（默认优先选能直接复制的），给出填好公网地址与令牌的**表单字段**（服务器地址 / 请求头名称 `Authorization` / 请求头值 `Bearer …`，各自可复制）、**JSON 配置**与 **Claude Code 命令**，一键复制。命名隧道时注明地址固定；Quick Tunnel 时提示地址每次开启都会变。旧版本创建的令牌没有原文，只提示重新生成。
4. **一键撤销**：撤销全部令牌并停止隧道。
5. **活动与审计**：待确认的外部调用，以及调用记录。记录由 daemon 分页返回（`GET /mcp-server/audit?limit&offset&tokenId`，含总数；每页最多 200 条，界面每页 20 条），可按客户端过滤，可清理（`DELETE /mcp-server/audit[?tokenId]`，界面二次确认；整体清空或只清某个客户端，文件按剩余内容原子重写）。记录只用于回看，清理不影响令牌、授权和变更账本；查看原文、编辑、重新生成也记在这里，显示为可读名称。内存与文件各保留最近 2000 条。
6. 审批请求出现在主窗口对话区与系统通知，并标明来源客户端。
   外部调用活动与审批通知属于用户级事件，SSE 和 Desktop App Server 均不按当前工作区或会话过滤；切换到其他会话仍须收到提醒，普通会话内容继续按订阅范围隔离。

### 管理页状态与历史恢复

管理接口由 daemon 返回令牌状态（有效、过期、吊销、工作区不可用）和独立的工作区可用标志，前端不按本机时钟猜测有效性。过期令牌可通过编辑有效期续期；吊销不可撤回。移除工作区仍会吊销其固定项目令牌并使相关会话目录授权失效；重新添加原目录只恢复工作区和历史入口，外部客户端需要新建令牌。

连接统计区分 HTTP 传输会话与已认证本地 socket 连接。HTTP 会话在终止、令牌失效或闲置 30 分钟后不计入，在途调用仍保留取消范围；本地连接断开后移除。无会话 HTTP 调用不计入，统计不能解释为在线 agent 数。设置页可见时定期刷新 daemon 状态，配置片段只在配置入口或令牌元数据变化时重取。

外部会话概要保留已移除工作区的历史并标记不可用，侧栏给出恢复原目录的提示。回看继续走现有工作区校验，不将历史重新归入个人会话或其他工作区。

## 14. 验证与后续范围

外部令牌使用完整目录加 `ask` / `read_write` / `always`：询问模式逐次确认，读写模式只预授权普通读写，完全访问模式免人工确认；三者都不能覆盖路径越界、HardBlock 等拒绝。

| 改动面 | 验收口径 |
| --- | --- |
| 本机传输与身份 | stdio/回环 HTTP 使用同一工具执行入口；无令牌、过期、吊销、越权路径和符号链接逃逸明确拒绝 |
| 授权与副作用 | ask 包括读取在内均询问；read_write 允许普通读写并询问命令及破坏性/不透明操作；always 跳过人工确认但保留硬性策略；拒绝/超时不执行，写入进入对应会话账本 |
| 网络入口 | 只有显式开启且令牌允许公网才可调用；撤销令牌/停止隧道立即失效；主应用管理路由不暴露 |

OAuth 协议和本机批准入口已实现；第三方客户端兼容矩阵、真实命名隧道环境需要单独取得对应构建的运行证据。协议、测试通过与真实上游可用性分别记录，不用一次性 fixture 结果替代。

## 15. 风险与待定项

| 风险 / 待定 | 影响 | 处理 |
| --- | --- | --- |
| **令牌泄露 = 对工作区的读写，授予执行时等价远程执行** | 网络模式下最严重的风险 | 默认本机；网络显式开启；限流、审计、一键撤销；交付前专项安全评审 |
| **令牌原文可找回（§5.3）** | 同机读取私有文件即得令牌 | 0600 私有文件、不进日志与备份、取回仅限本机桌面端并审计；本地数据，用户查看不设二次确认；与 API 密钥同级保管 |
| 编辑令牌与挂起审批、外部会话的关系 | 降权后仍有旧策略的审批在等 | 收紧立即重新评估挂起审批；工作区固定，使用其他工作区需新建连接；每次编辑审计 |
| 多客户端同时改同一文件（§9） | 后写覆盖先写；普通回退会抹掉别人的修改 | 回退前校验文件仍处于该会话的最后状态，否则拒绝并提示；每令牌并发上限对回环请求也生效 |
| 外部工具调用的执行与终态 | 外部会话或挂起审批未正确结算 | 复用 external_tool/external_approval，验证成功、拒绝、取消与重启收口，不另建执行路径 |
| 客户端超时短于审批耗时 | 写操作经常超时失败 | 挂起时限可配置；需要无人值守时可把令牌切换为 `always` |
| MCP 客户端差异（OAuth、Header、重连、`list_changed`） | 部分客户端接入受阻 | 核心只依赖标准 `tools/list` / `tools/call`；以重连兜底目录刷新；OAuth 使用 DCR + PKCE |
| Cloudflare 命名隧道需要用户自己的账号与域名 | 网络模式门槛高 | 内置 Skill `magi-cloudflare-tunnel` 协助配置（§10.2.2）；账号、登录、付款与域名托管仍由用户完成；Connect 就绪后优先采用 |
| 外部会话在会话列表里造成噪音 | 用户困惑 | 独立类型呈现，可折叠 / 归档 |
