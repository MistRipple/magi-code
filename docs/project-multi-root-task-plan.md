# 项目与多源文件夹改造任务计划

制定日期：2026-10-27。

状态：仅完成任务规划，尚未开始功能改造。本文供后续独立会话接手，不代表多目录能力已交付。本轮上下文用量面板、侧栏布局等已有变更属于其他工作，接手时先检查工作树并保留它们。

## 1. 任务目标与范围

将 Magi 当前“一项工作区对应一个根目录”的产品模型演进为“以项目组织会话，一个项目关联多个本机源文件夹，并指定一个主要文件夹”。同一会话能够按授权跨目录读取、搜索、修改和执行任务，主代理、子代理、文件预览与变更审阅使用一致的目录归属。

首版完成：

- 项目创建、重命名、移除、源文件夹增删与主要文件夹设置。
- 项目下统一会话列表，保留无项目个人会话及全局最近会话。
- 多目录文件树、检索、文件操作、Shell/终端、预览和附件引用。
- 多仓库 Git 归属、会话隔离、子代理执行与产出合入。
- 项目规则、记忆、知识索引、MCP 与 GPT Web 工具调用的目录边界。
- 旧数据迁移、取消、中断恢复、重启恢复及废弃单目录路径清理。

首版不做：远程目录、跨设备同步、云端项目、跨仓库原子提交、Magi CLI、独立移动端、具体外部 Executor。手机继续访问现有响应式 Web。不引入任务预算，也不扩大子代理自动派发范围。

## 2. 当前代码基线

以下是制定计划时核对的源码入口；新会话必须重新核对实际版本。

| 当前入口 | 已确认事实 | 改造关注点 |
| --- | --- | --- |
| `crates/magi-workspace/src/models.rs`、`registry.rs` | `WorkspaceRecord` 拥有单个 `root_path`、`root_path_ref`；注册与持久化沿现有 Store | 从单根记录演进，避免新增并行项目注册表 |
| `crates/magi-session-store/src/models.rs` | Session 通过可选 `workspace_id` 关联项目；空值表示个人会话 | 保留会话身份、历史归属和个人会话边界 |
| `crates/magi-api/src/scope_binding.rs` | 请求绑定解析为 Personal 或单个已注册工作区路径 | 统一项目身份、资源根和实际执行目录的解析 |
| `crates/magi-api/src/routes/workspaces.rs` | 注册、移除和会话目录使用既有 API | 项目管理与旧入口兼容；移除入口还涉及 MCP 吊销 |
| `crates/magi-tool-runtime/src/policy.rs` | 默认目录范围和工具参数路径沿工作目录解析 | 多目录授权必须与实际执行路径同时更新 |
| `crates/magi-git/src/lib.rs`、`crates/magi-api/src/git_tool_runtime.rs` | 已有仓库身份、执行上下文、租约、漂移检查和子代理 worktree | 复用既有机制，核对所有单仓库索引与调用方 |
| `docs/session-isolation.md` 及对应实现 | 会话隔离已有复制、变更账本、恢复与合入链路 | 多根映射、部分创建失败、依赖符号链接和合入边界 |
| `web/src/web/WebWorkbenchShell.svelte`、`InputArea.svelte`、`ProjectFileTree.svelte`、`RightPane.svelte` | UI 消费工作区与会话投影 | 项目组织、目录选择、文件及变更定位 |

`runtime_workspace_roots` 等数组字段的存在不代表已经支持完整多目录项目，必须核对其生成、执行和恢复语义。既有文档中单目录场景的实现结论也不能直接当成多目录验收证据。

## 3. 产品概念与所有权

| 概念 | 产品语义 | 唯一权威 |
| --- | --- | --- |
| 项目 | 名称、源文件夹成员、主要目录、项目设置和会话归属 | daemon 现有工作区领域与持久化入口演进 |
| 源文件夹 | 有稳定身份的本机资源根；可以是 Git 仓库或普通目录 | 项目记录与统一路径解析 |
| 主要文件夹 | 新会话默认执行目录、未显式指定目标时相对路径的默认起点 | 项目配置；已开始任务使用其原绑定 |
| 会话 | 项目下的对话与任务，或无项目个人对话 | SessionStore |
| 执行副本 | 源文件夹到当前会话/任务实际执行目录的映射 | 现有隔离与 Git 执行上下文拥有方 |
| 侧栏与目录选择 | 业务事实的展示、导航和编辑草稿 | Web 投影，不另建业务持久化 |

实施原则：

1. 复用现有项目归属身份。旧 `workspaceId` 与会话 ID 不因改名或增加目录而改变，不为同一逻辑项目同时维护两份可写身份。
2. 源文件夹需要稳定 ID，路径和显示别名不能代替身份；主要目录按 ID 引用。名称冲突、Windows 路径、符号链接和目录重叠由服务端规范化与校验。
3. 项目状态与会话归档的位置必须稳定，切换主要目录只改变默认执行起点，不能令历史数据“搬家”或消失。先审计原 `.magi` 与全局状态根的加载关系，再确定唯一存储定位方案。
4. 一个会话可使用多个源文件夹；选中目录不改变会话所属项目。运行中任务、排队输入和恢复任务必须保留明确的目录与授权绑定，不能跟随当前侧栏选择漂移。
5. 目录增加不隐式扩大已有 MCP 令牌、子代理或在途任务的授权；移除目录不能通过旧快照继续获得已撤销的权限。
6. 项目级规则和记忆共享，各源目录的 `AGENTS.md` 等规则按对应目录生效。项目共享规则的位置和优先级在第一阶段明确，不把主要目录的专属规则全局套用。
7. 根据协议现有兼容规则修改 schema 并生成类型。旧单根入口只兼容其可准确表达的单目录场景，无法表达多目录作用域时明确拒绝，不静默选择第一个目录。

## 4. 用户流程

- 创建项目：填写项目名称 → 添加一个或多个本机文件夹 → 指定主要文件夹 → 创建并进入项目草稿。
- 侧栏：以项目为一级项，展开后直接显示会话。源文件夹由项目设置和文件面板管理，不增加“项目 → 目录 → 会话”的固定层级。
- 项目设置：编辑名称、添加/移除源文件夹、切换主要文件夹；涉及运行任务和未合入产物时展示实际影响并由服务端阻止不安全变更。
- 对话输入：显示所属项目，默认主要目录，可按需选择本轮执行目录；该选择沿统一提交入口传递。
- 文件与检索：按源文件夹分组；文件引用携带目录身份，相同相对路径能够区分。
- 变更与 Git：按源文件夹/仓库分组，明确实际执行副本、分支和产物归属；分别查看和合入。
- 项目移除：明确历史数据和磁盘文件保留策略，沿原入口结算任务及外部授权，不触发磁盘项目删除。

沿用已有下拉交互与弹出方向，组件遵循共享设计系统，不顺带重做模型设置、主题或代理卡片。

## 5. 分阶段执行与退出条件

必须依次推进；每阶段记录替换了哪些旧路径、删除了什么、验证证据及剩余限制。阶段之间保持可构建，完整能力交付前不暴露可用的多目录项目创建入口。

### P0：完整调用链审计与合同定稿

- [ ] 搜索工作区身份、单根路径、项目状态目录、相对路径和 Git 上下文的全部实际消费者。
- [ ] 列出 daemon、HTTP/App Server、Web、Desktop、MCP/GPT Web、插件和恢复链路的影响清单。
- [ ] 定稿领域字段、目录 ID、主要目录、默认 cwd、项目修订和任务目录绑定的语义；字段名称以最终 schema 为准。
- [ ] 定稿数据存储定位、迁移版本、旧入口兼容和旧版程序读取新数据时的保护策略。
- [ ] 定稿源目录重叠、同一物理目录被多个项目引用、缺失目录、主要目录移除及运行期成员变更的处理规则。

退出条件：以源码为依据完成字段与调用方映射、迁移步骤和验收用例；明确单一拥有方，不留下会影响后续执行安全的未决项。更新本文记录决策后进入实现，无需再次进行同一轮需求确认。

### P1：领域、持久化与迁移

- [ ] 沿现有 Store 增加项目名称、多源目录成员和主要目录管理，保持唯一持久化写入口。
- [ ] 旧工作区一对一迁移为单源目录项目，保留会话 ID、归属、历史事件及数据文件。
- [ ] 迁移可重复执行；写盘失败、进程中断后不出现半迁移状态，不删除原始数据。
- [ ] 项目改名或切换主要目录后，历史、记忆、索引及执行副本仍可定位；单目录身份不能被多个副本文件抢占。

退出条件：旧数据夹具、真实落盘/重启、故障注入通过；主要目录变化不改变历史归属与存储定位。

### P2：统一目录解析、权限和执行入口

- [ ] 文件、搜索、Shell、终端、附件、下载、HTML 预览共用项目/会话/源目录到实际执行路径的解析入口。
- [ ] 相对路径按显式目标或任务默认目录解析，跨根路径明确携带目标身份；同名路径无歧义。
- [ ] AccessProfile、审批、允许/拒绝路径和符号链接检查覆盖全部访问根，不能靠改变 cwd 绕过。
- [ ] Turn 接纳、排队、重试、显式继续和恢复使用原目录绑定，核对当前授权及目录有效性；移除目录后不回落到其他目录。

退出条件：双目录同名文件、第三方未授权目录、路径穿越、外部符号链接、目录缺失及成员变化均有真实执行回归。

### P3：多仓库 Git、会话隔离与子代理

- [ ] 执行上下文、基线、租约及变更账本按项目/会话/目录/实际仓库正确归属，避免同一仓库被别名路径重复建锁。
- [ ] 定义多仓库资源获取顺序、取消与释放，避免两个会话分别持有不同仓库后相互等待。
- [ ] 隔离模式为本次允许访问的各源目录建立执行映射；初始化部分失败时保留明确状态并清理自有残留，不退回原目录继续写。
- [ ] 审计既有复制降级的依赖符号链接；多目录隔离下仍不得借共享链接意外修改原目录。
- [ ] 子代理继承父任务的实际目录映射与权限子集，保留按需创建副本及当前委派门槛。
- [ ] 子代理产出按目录/仓库记录，合入检查基线和冲突；跨仓库部分成功如实展示，不伪造整体原子成功。
- [ ] 验证 Git 与普通目录混合、linked worktree、同仓库多工作树、dirty 文件和未合入成果保留。

退出条件：主线与子代理跨双仓库执行、隔离副本读写、按仓库合入、冲突与重启恢复完整通过，原目录和其他会话成果未受意外修改。

### P4：规则、记忆、知识与外部调用

- [ ] 项目共享上下文与目录专属规则使用同一解析合同，索引结果携带源目录身份并正确去重。
- [ ] 主代理与子代理提示词说明项目、目录映射和默认 cwd；保留目录专属规则的适用边界，不整项目无限制注入文件。
- [ ] MCP 令牌沿原拥有方明确授权目录范围；添加成员不自动扩权，移除、吊销和等待审批按既有入口结算。
- [ ] GPT Web/插件工具沿原 owner session、active turn 和调用权限解析目录，不另建一套项目状态。
- [ ] 项目改名、切换主要目录、成员变化后，共享知识和历史外部调用仍能正确回溯。

退出条件：跨目录知识定位、规则适用、外部只读/读写范围、审批恢复和令牌吊销回归通过。

### P5：完整 GUI/Web 产品入口

- [ ] 创建/编辑项目、源目录管理、主要目录选择和错误反馈接入 daemon 权威入口。
- [ ] 侧栏、最近会话、输入区、文件树、检索结果、预览、变更及 Git 面板统一项目和目录展示。
- [ ] 项目重名、目录重名、长路径、目录离线及迁移失败均可理解和恢复；移除操作说明实际影响。
- [ ] 目录选择不改变已有会话归属；刷新、SSE 重连和多窗口事件后列表与详情一致。
- [ ] 验证 Desktop、Web 及窄屏布局，保留触控和键盘操作能力。

退出条件：通过 GUI 创建多目录项目，完成一次跨目录任务，查看全部变更并按仓库合入；重启后项目、会话、预览和执行副本可恢复。

### P6：清理、整体回归与交付

- [ ] 删除已替换的单根业务假设、重复路由/转换、影子缓存、失效 UI、旧文案和仅验证废弃入口的测试。
- [ ] 保留必要的旧格式单向迁移读取，不保留两套业务写入与执行系统。
- [ ] 更新相关权威设计文档和验证入口，将本文的目标与真实交付证据区分记录。
- [ ] 检查净代码增长和脚本数量，合并重复夹具，新增测试必须验证真实边界或恢复行为。
- [ ] 完成整体验收矩阵、实际安装包验收及最终风险记录。

退出条件：下列必需场景通过；未验证平台单独标注，不用 macOS 结果替代 Windows/Linux。发布另按既有发布流程执行，本任务计划不自动授权打 Tag 或发布。

## 6. 最小完整验收矩阵

| 场景 | 必须核对的结果 |
| --- | --- |
| 旧单目录项目、个人会话升级 | ID、历史、审批、归属、文件和最近列表保留；迁移重试幂等 |
| 单项目包含两个 Git 仓库和一个普通目录 | 同一会话可按实际授权跨目录操作；默认 cwd 可预测 |
| 多目录都有 `src/index.ts` | 搜索、读取、编辑、预览和差异均定位到正确源目录 |
| 主目录切换、项目重命名 | 新请求使用新默认值，已有任务与历史仍保持原绑定 |
| 项目成员增删与任务/审批并发 | 不误扩权、不越界写入、不把原任务移到其他目录 |
| 同一物理目录关联多个项目或路径重叠 | 按 P0 规则明确处理；仓库锁、账本、规则及持久化互不串用 |
| 两个会话跨仓库并发 | 无资源死锁，取消可释放占用，其他会话正常推进 |
| 主线隔离、可写子代理、多目录产出 | 所有已授权写入落到正确副本，按真实目录基线审阅和合入 |
| 副本创建/提交/合入部分失败 | 保留成果及可核对的部分结果，不清理用户目录或已存在副本 |
| Windows、符号链接、linked worktree、普通目录 | 路径身份、Git 元数据授权和复制降级边界正确 |
| MCP/GPT Web、插件、目录专属规则 | 原会话归属、目录权限与规则作用域正确，旧令牌不获新增目录权限 |
| daemon 重启、网络重连、任务中断继续 | 原目录映射恢复，副作用不重放，缺失或被撤销的资源明确报错 |
| 项目移除、会话删除 | 授权和资源按拥有方结算；磁盘项目、其他会话及未合入成果按既有保护策略保留 |

验证选择：

- 修改前读取对应局部 `AGENTS.md`、[工程约束](README.md)、[个人会话](personal-session-architecture.md)、[Git 工作流](session-git-workflow.md)、[会话隔离](session-isolation.md)、[代理委派](subagent-delegation-design.md)与[验证入口](validation.md)。
- Rust 按受影响 crate 运行编译检查和定向回归；Web 运行 `npm --prefix web run check` 与对应会话导航、工作区、权限、文件、隔离等现有脚本，避免每个阶段重复跑全仓测试。
- 修改 App Server 合同后运行 `npm run protocol:generate` 与 `npm run protocol:check`；其他 schema 按所属目录规则验证。
- 复用现有真实 daemon/App Server/Chromium 验收设施，使用隔离状态根与本地确定性 Provider；夹具目录放在状态根外，不注册到用户日常 daemon。
- 真实产品页面始终通过 daemon 主入口。安装包验收使用本机实际宿主；跨平台文件、进程与路径行为分别取得对应平台证据。
- 本地模型替身只验证执行合同，不能据此宣称真实外部模型自主选择目录、委派质量或外部服务兼容性已验证。
