## 0. 一句话

在 Magi 内置浏览器里登录 ChatGPT；用户在 Magi 发消息，就是把这条消息原样放进当前 GPT Web 对话的输入框并发送；网页自己维护上下文，Magi 不给网页任何上下文，只把网页的回复读回来显示并存进会话。GPT Web 支持两种模式：**临时对话**与**已保存对话**。**GPT Web 本身不实现工具**：网页需要用 Magi 的工具时，在 ChatGPT 侧把 [Magi MCP 服务](./magi-mcp-server-design.md) 配置成连接器，模型通过标准 MCP 原生调用；没有配置或通道不可用时，GPT Web 仍可正常聊天，只是没有项目工具。

**为什么做**：ChatGPT 网页使用账号订阅额度而不是 API token。**只做 ChatGPT**，不为其他厂商预留抽象。

### 0.1 参考实现与边界

参考项目：[miuuyy/codex-chatgpt-web](https://github.com/miuuyy/codex-chatgpt-web)。它只作为 ChatGPT Web 页面驱动、临时对话和回复读取的交互参考，不是 Magi 的状态、权限、工具或传输实现。Magi 必须继续以 daemon、BrowserAuthority、canonical、现有审批链和 Magi MCP 服务为唯一事实源；不得直接复制参考项目的存储、认证绕过或多会话模型。

### 0.2 最终链路

```text
Magi 对话框
    │ 仅发送本次用户原文；不附带 Magi 历史、不附带工具文本
    ▼
magi-daemon / WebSlot（单槽位、单 WebView、单进行中 turn）
    │ 受控页面驱动
    ▼
ChatGPT Web（临时多轮 or 已保存 conversation_id）
    │ 模型需要项目能力时，通过 MCP Connector 发起标准 tools/call
    ▼
OpenAI Tunnel（正式通道；Magi 的 Cloudflare Quick Tunnel 只服务外部 agent，见 MCP 文档 §10）
    ▼
Magi MCP 服务（独立通用扩展，见《Magi MCP 服务设计》）
    │ 认证 → 令牌范围 → 权限档 → 路径校验 → 审批 → 执行 → 审计
    │ 令牌归属模式 follow_web_slot：调用归到槽位拥有者进行中的 turn
    └────────────── 工具结果回到同一 tools/call，再由 Web 在同一回复继续
```

Magi 与 Web 之间的对话消息链路和工具链路是两条不同链路：前者只做页面输入 / 输出同步，后者只做 MCP 调用。任何一条链路都不能把另一条链路的上下文或协议文本塞进用户消息。

MCP 调用和结果不写入 ChatGPT composer，也不作为普通用户消息回填到网页；它们由 Web 原生 Connector 消费、由 Magi loop 执行，并作为 canonical 的工具项展示在 Magi。Magi 从网页读取的是最终可见回复 / thinking，工具调用与结果以 Magi 自己的执行事实为准。

## 1. 固定规则

以下规则是唯一结论源，改动必须先经用户确认并更新本节。

| 编号 | 规则 | 理由与边界 |
| --- | --- | --- |
| W1 | **网页自己管理上下文。** Magi 只发送用户本次输入的原文，不重放历史、不发增量封装、不重锚、不做压缩后重建，也不计量网页对话的占用。 | 上下文在网页里，Magi 无法也无需替它管理；一切“让 Magi 与网页上下文保持一致”的机制都不需要。 |
| W2 | **会话转换只有一个方向：GPT Web 会话 → 本地会话。** 本地会话永远不能转为 GPT Web；Web 会话可以随时切到本地模型继续。 | Web 的每条用户消息与回复都写入 Magi canonical，本地模型读它就是完整历史；反过来，网页没有本地那段历史，且 W1 决定了 Magi 不会去补。 |
| W2a | **GPT Web 会话的消息一律走普通对话路由，原样交给网页。** 不经过任务 / 工具意图分类：命中「工具」「文件」之类的文本也不会被改写成任务、更不会带上任务上下文、多代理规则或工具意图（那会让网页模型按这些规则行事：反复重做、串话）。实现位于会话 Turn 的意图决策入口：目标会话的编排引擎是 GPT Web（已有会话读会话设置，新会话首条消息读请求里的引擎配置）即固定为 `Chat`。 | Web 自己维护上下文；项目工具由 ChatGPT 侧经 Magi MCP 使用，Magi 不替网页规划任务。 |
| W3 | **会话的起点类型在第一条消息发出时固定。** 空白会话可以选择 GPT Web 或本地模型；一旦发出第一条消息，本地会话的模型选择器里不再出现 GPT Web；Web 会话切到本地后也**不能再切回 Web**。 | 切走之后网页对话不再收到新消息，上下文已经不完整。 |
| W4 | **同一时间只允许一个 Magi 会话拥有 GPT Web 对话（单槽位）。** 槽位被占用时，其他会话（含空白会话的第一条消息）请求使用 Web 一律拒绝，不提供接管。 | 只有一个网页对话页面；抢占会让原会话的上下文丢失。 |
| W5 | **临时对话不能依赖保存。** 同一 Magi 进程里，Tab 关闭只是隐藏，重新显示仍使用原页面；但 Magi / daemon 重启、页面真实重新加载、WebView 被重新物化或“停止并释放”后，临时对话一律视为不可恢复。发送前必须核对网页仍是同一条对话，核对不通过就把会话判为“网页对话已失效”，拒绝发送。 | 不能悄悄把消息发进一段失忆的新对话，让用户以为对话仍连续。 |
| W6 | **临时模式的存活判定：网页里最后一条消息的展示文本，与 Magi 该会话最后一条消息一致。** 用归一化后的摘要比对，一致才允许发送；已保存模式按 `conversation_id` 和远端消息同步判定。 | 判据只依赖两侧已有事实，不引入临时上下文持久化状态。 |
| W7 | **关闭 GPT Web 视图只是隐藏。** 页面、对话与拥有者都保留。只有“设置里的停止并释放”、被占用提示上的“释放并使用”或用户明确执行“切换到本地并结束 Web”才是真实释放：销毁页面、释放槽位、Web 会话变为失效；普通折叠、Tab 关闭、项目 / 会话切换都不是关闭。 | 防止用户误点 × 就丢掉对话，同时保证单槽位可以被明确释放。 |
| W8 | **工具只通过 Magi MCP 服务提供，GPT Web 自己不实现工具。** 工具目录、认证、审批、审计、路径限制与传输都属于《[Magi MCP 服务设计](./magi-mcp-server-design.md)》；GPT Web 只是它的一个客户端：在 ChatGPT 侧配置该服务为连接器，模型原生调用。不做文本协议，不往消息里塞工具清单或调用格式。MCP 不可用时该 Web 会话没有项目工具，并说明原因，聊天不受影响。 | 工具能力是通用扩展，不绑定 GPT Web；消息里只有用户原文。 |
| W9 | **GPT Web 连接器使用的令牌归属模式为 `follow_web_slot`：** 调用只在槽位拥有者有一个进行中的 turn 时才接受，并作为普通工具项内联写入该 turn 的 canonical；没有进行中的 turn、槽位已释放或被其他会话占用时一律拒绝。其余认证、权限档与审批规则完全由 MCP 服务决定。 | 消息里不携带令牌，由“单槽位 + 进行中的 turn”确定归属；令牌属性的定义见 MCP 文档 §4、§12。 |
| W10 | **子代理不继承 Web 引擎。** 子代理只使用其角色自己配置的引擎；角色未配置且会继承到 Web 时，创建前直接拒绝并提示。 | 一个会话只有一条网页对话，子代理无法共用。 |
| W11 | **Magi 不替临时 Web 对话落盘，且不把 Web 页面复制成第二个运行时事实源。** 临时对话不写 ChatGPT 历史；已保存模式使用 ChatGPT 自己的远端保存能力，但 Magi 只保存 `conversation_id`、标题、同步指针和展示到 Magi 的 canonical 记录，不向 Web 反向写历史。登录态放在持久分区里。 | canonical 是 Magi 的展示 / 执行事实源；临时 Web 页面丢失属于正常路径。 |
| W12 | **不做兼容。** 不迁移、不双读双写、不保留旧格式运行期分支。唯一硬要求：可重建状态（浏览器 durable state、右栏 Tab 指针）的加载路径必须是全函数，读不出来就重建，绝不让 daemon 起不来。 | 沿用既有基线。 |
| W13 | **兼容临时对话与已保存对话，但两者不混用。** 临时模式从空白 Web 对话开始且不继承任何 Magi 或其他 Web 上下文；已保存模式绑定 ChatGPT Web 的稳定 conversation id，允许读取标题、消息与更新时间并在 Magi 中同步。 | 临时模式强调不留 Web 记录；已保存模式强调可重新绑定与可管理。 |
| W14 | **已保存对话的 Magi 记录名称以 Web 标题为准。** Magi 保存远端 conversation id、标题和同步状态，不自行生成另一套名称；**Magi 不提供删除 Web 对话的功能**：用户要删除长期对话，自己在 ChatGPT 网页里删除；删除 Magi 会话只删本地记录，不触碰 Web。 | Web 是已保存对话的远端事实源；Magi 不替用户做破坏性的远端操作，少一条写入路径。 |
| W15 | **Magi MCP 服务是独立于 GPT Web 的通用扩展。** GPT Web 与它互不依赖：没有它，GPT Web 照常收发；没有 GPT Web，它照常服务其他 MCP 客户端。GPT Web 不得为工具能力自建目录、令牌或传输。 | 避免把通用能力绑死在某一个入口上。 |
| W16 | **临时对话是同一网页对话内的多轮对话，不是每轮新建。** 只要页面、槽位和上下文仍存活，后续消息都继续写入同一临时对话；同一进程内隐藏再打开不改变它。Magi / daemon 重启、页面 reload、WebView 重新物化或显式停止后，临时上下文不可恢复。 | Web 自己维护上下文；Magi 不能用本地历史伪造恢复。 |
| W17 | **GPT Web 连接器令牌的工作区范围在槽位建立时由拥有者会话的项目决定，槽位释放即失效。** 切换 Magi 项目不会改写正在运行的 Web 会话的工具范围；要在另一个项目使用 Web，必须先结束当前 Web 会话，再新建 Web 会话（此时重新生成令牌）。 | “跨项目可用”指应用级登录态和入口可用，不指多个项目共享同一个活跃 Web 上下文；防止误用另一个项目的文件。 |
| W18 | **未登录不展示 Web 引擎。** 登录并完成状态探测后只展示一个固定的“GPT Web · 来自 Web”入口；不把 ChatGPT 网页的模型菜单复制成 Magi 模型列表，具体模型和强度由网页自己选择。 | 登录态是使用前提，避免展示无法发送的伪模型；不维护第二套模型发现协议。 |

## 2. 目标与非目标

**目标**
1. 登录一次，跨项目、跨会话、跨 Magi 重启，登录态仍在。
2. 在 Magi 里创建临时 GPT Web 对话，或选择一个已保存的 GPT Web 对话；回复流式回到 Magi 对话，并存成普通消息。
3. 已保存对话可读取 Web 标题、消息摘要与更新时间；Magi 记录名称直接使用 Web 标题；删除 Web 对话不由 Magi 负责。
4. 网页可以通过 Magi MCP 服务调用 Magi 的工具（读改文件、执行命令等，具体范围以 MCP 文档为准），审批与事实仍在 Magi。
5. 任何异常都有明确状态与主行动：未登录、被风控、选择器失效、临时对话失效、保存对话不存在、槽位被占用、额度用尽。

**非目标**
- 不接入 ChatGPT 以外的厂商。
- 不在 Web 或手机 Web 上提供真实内置浏览器（只有 Magi Desktop 有）。
- 不发现或管理网页模型菜单：模型和强度由用户在网页里自己选，Magi 不介入。
- 不管理网页对话的上下文长度，不做压缩，不做上下文压力提示。
- 不使用任何规避风控、验证码或额度限制的手段。
- 不把临时对话写入 ChatGPT 历史记录；已保存模式明确使用用户已有或新建的 ChatGPT 保存对话。
- 不把本地 Magi 历史反向导入 Web；已保存对话的历史只能沿 Web → Magi 方向同步。
- 不允许一个 Web 槽位同时绑定多个 Magi 会话，也不提供排队或抢占。

> **“临时”只针对 ChatGPT Web 侧。** 临时对话不会出现在 ChatGPT 历史、不会在 Web 侧落盘；但 Magi 已经展示给用户的用户消息、助手回复、thinking、工具调用和结果仍按普通会话写入 canonical，便于本地查看、刷新和切换本地模型。Magi 重启后这份本地镜像仍在，但不能据此恢复 Web 临时上下文。

## 3. 状态所有权

| 状态 | 唯一 owner | 持久化 | 说明 |
| --- | --- | --- | --- |
| 登录态（cookie / 存储） | Electron 持久分区 `persist:magi-web-model` | 是 | 分区名固定，不随会话变化 |
| 应用级 GPT Web 浏览器宿主、主页 Tab | daemon BrowserAuthority（App owner） | 是 | 不属于任何 Magi 会话或工作区，不被孤儿回收；登录态和宿主可恢复，临时对话正文不可恢复 |
| 网页临时对话（页面与内容） | 内置浏览器里的 ChatGPT 页面 | **否** | 不可保存；丢失属于正常路径（W5） |
| 已保存 Web 对话绑定（conversation id、标题、同步状态） | Magi 会话级配置 / canonical 元数据 | 是 | 保存远端引用与展示元数据；canonical 可保存已展示的消息，但不保存另一份可驱动 Web 的上下文；远端删除后标记失效 |
| **槽位拥有者**（哪个 Magi 会话拥有当前网页对话） | daemon 进程内存 | **否** | 重启即清空；临时 Web 会话不得凭旧页面重新占用（W4、W5） |
| 用户消息、助手回复、thinking、工具调用与结果 | daemon canonical 事件日志 | 是 | 展示即落盘：UI 看到的每一条内容都来自 canonical |
| 会话的引擎类型（Web / 本地） | 会话级配置里的 `engineId` | 是 | 第一条消息发出时固定（W3） |
| 会话的“网页对话是否有效” | **推导，不存储** | 否 | = 是槽位拥有者 且 存活判定通过（W6） |
| 右栏“存在哪个 Tab” | App Renderer（窗口级 `appTabs`） | 仅窗口内 | 只存指针 |
| 工具调用的挂起表 | Magi MCP 服务（daemon 内存） | 否 | daemon 重启即失效；细节见 MCP 文档 §7 |
| GPT Web 连接器令牌与工具目录 | Magi MCP 服务 | 令牌元数据是；目录否 | 令牌绑定槽位建立时拥有者会话的项目；槽位释放即失效，禁止跨项目复用 |
| Web 槽位的模式 / 远端会话引用 | daemon 内存 + 会话元数据 | 模式与已保存引用是；临时活动状态否 | 临时模式重启后失效；已保存模式可用远端 `conversation_id` 重新绑定 |

### 3.1 最小绑定数据

会话级 Web 元数据只需要表达绑定，不复制一套 Web 会话状态：

```text
WebConversationBinding {
  mode: temporary | saved,
  engine_id: plugin/openai.chatgpt-web/default,
  remote_conversation_id?,
  remote_title?,
  last_synced_remote_message_id?,
  remote_updated_at?,
  sync_state: unbound | pending | active | stale | deleted | conflict,
}
```

`temporary` 模式的 `remote_conversation_id` 必须为空；已选择“新建已保存对话”但 Web 尚未返回 id 时，暂时使用内存中的 `pending` 状态，第一条消息被接受并读取到远端 id 后才提交 `saved` 绑定。`remote_title` 只能由 Web 读取结果写入，不能由 Magi 的自动标题器覆盖。`last_synced_remote_message_id` 只用于已保存模式拉取缺失尾部，不用于重建发送上下文。临时模式的活动页面身份、槽位 owner、页面代次和进行中 turn 永远只在内存中存在。

## 4. 用户流程

### 4.1 首次登录
1. 右栏“新增 → GPT Web”，打开应用级会话的主页，未登录进登录页，用户自己登录。
2. 登录态写入持久分区。重启 Magi 后再打开，直接是已登录页面。
3. 弹窗式登录（Google、Microsoft、Apple 等）受现有 popup 规则限制；被阻止时，在主页叠加持久提示条，列出可用登录方式，直到登录成功。不为登录放宽 popup 规则。
4. 该 GPT Web Tab 属于 Magi 应用而不是当前项目 / 会话；切换项目或会话只改变中间对话区，不创建新的登录页或新的 WebView。

### 4.2 发消息（新的 Web 会话）
1. 用户在空白会话的模型选择器里选“GPT Web”（“来自 Web”分区，只有这一项），再选择“临时对话”或“已保存对话”。已有本地消息的会话不显示该入口。
2. 临时模式：检查槽位（无占用）→ 导航到 ChatGPT 临时对话入口 → 确认页面没有旧消息 → 写入输入框并回读确认 → 提交 → 确认被站点接受。每一轮都继续使用这一页，不会重新创建临时对话。
3. 已保存模式：可从已登录的 Web 历史中选择已有 `conversation_id`，或打开普通新对话让 ChatGPT 保存；读取远端标题和已有可见消息后绑定 Magi 会话，再写入本次输入。已有历史只从 Web 同步到 Magi，不会反向发回 Web。
4. 第一条消息被站点接受后，会话成为该槽位的拥有者，引擎类型和对话模式固定；回复流式读回，Magi 对话里实时显示并写入 canonical。

### 4.3 继续对话
- **临时模式**：每次发送前做存活判定（W6），通过则把用户消息原样写入同一条网页对话并提交，不携带任何历史。多轮期间不新建页面、不新建临时会话。
- **已保存模式**：先读取 Web 的最新可见消息并把缺失尾部同步到 Magi；确认远端 `conversation_id` 仍存在后，把本次用户消息原样提交到同一远端会话。不把 Magi 历史重放给 Web。

### 4.4 各类异常

| 情形 | 行为 |
| --- | --- |
| 槽位被其他会话占用 | 拒绝发送，提示“GPT Web 正被会话 X 占用”；先在占用会话里停止或让其切到本地才能换 |
| 临时页面被重新加载、WebView 被重新物化、Magi / daemon 重启 | 临时上下文一律视为丢失，不尝试用最后一条消息恢复；重建宿主后只打开登录态主页，不自动回到旧临时 URL；会话进入“网页对话已失效”，发送入口禁用，提示可切换本地模型继续（Magi 历史完整）或新建 GPT Web 会话 |
| 已保存页面被重新加载、Magi / daemon 重启 | 不恢复临时上下文；使用持久的 `conversation_id` 重新打开远端保存对话，拉取缺失消息后再允许继续；远端不存在则标记“保存对话已失效” |
| 未登录或登录过期 | 明确状态，主行动“登录”；不静默重试 |
| 风控 / 验证页 | 主行动“打开主页处理”，不自动重试 |
| 选择器失效 | 明确状态，主行动“运行诊断”；不猜测页面结构 |
| 账号额度用尽 | 明确状态；可切换本地模型继续 |
| 已保存 Web 对话被用户在网页侧改动 | 重新读取并按远端事实同步；无法判断为同一条对话或出现分支冲突时停止发送，提示在 Web 中处理 |
| 用户在临时对话页面里手动操作 | 下一次发送前的存活判定会发现页面最后一条消息与 Magi 不一致，判为失效；不自动覆盖用户在 Web 中的操作 |
| 用户在已保存对话页面里手动操作 | 按 §6.2 拉取远端尾部并同步；只有出现无法安全映射的分支 / 远端删除 / 账号变化才判冲突 |

非拥有者会话打开 GPT Web Tab 时可以查看当前应用级页面，但页面只读并显示当前 owner；从该会话发送消息仍返回 `web_session_busy`，不会接管或改写槽位。

### 4.5 关闭与停止
- 点右栏 Tab 的关闭按钮：只隐藏视图，页面、对话、槽位、进行中的推理都保留；Tab 条与菜单显示“后台推理中”；Tab 标题栏只有只读地址、连接状态和“检查连接”，不放破坏性动作。
- 设置 → 浏览器 → GPT Web 的“停止并释放”，或被占用提示条上的“释放并使用”：取消进行中的推理，销毁页面，释放槽位；该会话变为失效。登录态仍保留。
- “清除 Web 数据”是显式的另一个操作：同上，并清理持久分区。它只清理本地登录态和页面数据，不替用户删除 ChatGPT 已保存对话；所有已保存绑定标记为待重新登录 / 待重新绑定，Magi 已有的 canonical 镜像保留。
- 同一进程内再次点击“新增 → GPT Web”或 Tab 条入口只是重新显示原宿主，不是重新登录，也不是新建临时对话；只有“停止并释放 / 释放并使用 / 清除数据”才会销毁页面。

### 4.6 Web → 本地
- 在同一会话里选择本地模型，即时生效：清除会话里的 Web `engineId`，释放槽位并关闭页面，下一轮由本地 client 读取 canonical 历史继续。之后该会话不能再选回 Web（W3）。
- 这是用户显式结束 Web 绑定的操作，语义等同于释放槽位；不能因为右栏隐藏、切换项目或普通 UI 重绘而触发。

## 5. 发送与接收

### 5.1 发送（一次 turn）
1. **槽位检查**：槽位空闲，或拥有者就是本会话；否则 `web_session_busy`。
2. **模式检查**：临时模式只能绑定空白临时页面；已保存模式必须有稳定的 `conversation_id`，且远端账号与当前登录态一致；“新建已保存对话”在第一条消息被接受前允许短暂 `pending`。模式不匹配直接拒绝，不自动转换。
3. **存活判定**：临时模式按 §6 的最后一条一致性判定；已保存模式读取远端最新消息和会话存在性。选择“新建已保存对话”且尚未拿到远端 id 时允许一次 `pending` 首条发送；其他判定不通过分别返回 `web_context_lost` 或 `web_saved_conversation_unavailable`。
4. **取页面**：本会话已拥有页面则复用同一个 WebView；否则按模式打开临时入口或已保存的远端会话。一个槽位只有一个页面，不创建“每轮一个页面”或“每会话一个页面”。
5. **写入**：把用户原文写入输入框，回读确认是原文且没有被转成附件；不一致则不提交，`web_write_not_confirmed`。回读按段落读取文本节点，跳过不可编辑 / 隐藏的装饰控件，不用 `innerText`：输入框会把文本里的 URL 自动变成「链接徽章」控件，`innerText` 会在徽章前后插入换行，使带链接的消息永远回读不一致。行首的 `#`、`-`、`1.`、`>` 和代码围栏不会被输入框转换，原样写入。
6. **提交并确认被接受**：以“页面里出现新的用户消息或进入生成中状态”为准，不以命令返回成功为准；被接受前失败视为无副作用。
7. 输入框字符上限只做一次保护：超过站点上限直接报错，由用户缩短，不截断、不分片、不压缩。Magi 不因为 Web 上下文长度未知而自行压缩或重建。

### 5.2 接收
1. 短周期轮询读取助手回复，把累积快照交给流式回调；隐藏推理区块映射为 thinking。**回复由页面 DOM 还原为 Markdown**（标题、粗体 / 斜体、行内代码、代码块与语言、有序 / 无序 / 嵌套列表、表格、引用、链接与引用来源），不压平成纯文本：Magi 会话本身渲染 Markdown，链接在内置浏览器打开、文件引用走工作区预览。转换规则：字面的 Markdown 符号转义；只保留 `http(s)` / `mailto` 链接，并去掉站点追加的 `utm_source=chatgpt.com`；链接文字等于地址时输出自动链接；站点标注为“复制时排除”的区域（复制按钮、代码块头、表格操作栏）、`aria-hidden`、`hidden` 和读屏专用节点不进入正文。公式取站点放在 `data-math-source` 上的 TeX 源码，行内输出 `$…$`、独立输出 `$$…$$`（站点的 MathML 与排版副本不进正文）；Magi 的会话渲染用 KaTeX 显示它们（`web/src/components/MarkdownRenderer.svelte`），金额一类的 `$5` 不会被误判。**图片**：站点生成的图是 `blob:` 地址（只在网页里有效），回复里先还原为 `![alt](blob:…)`；收口时 daemon 经 `web_read_image`（按 768 KiB 分块，控制通道单条消息有上限）把字节读出来，保存到会话所属项目的 `generated-images/web-<内容摘要>.<ext>`（与 Magi 自己的生图工具同一位置，同一张图幂等），并把引用改写成项目相对路径，会话里按工作区文件显示。多张图按出现顺序各存一份；单张失败只在该处留一句说明，不让整轮失败。流式阶段不显示这些引用，同步已保存对话历史时也只带文字。没有图片落地能力时引用被去掉。图片回复的页面结构与文字回复不同（助手内容没有 unit 包装、停止按钮不出现）：用画廊节点识别助手消息，并且画廊里还有没加载完的图片就算仍在生成，否则会在骨架阶段过早收口。转换在站点适配层完成，Magi 其他层只拿 Markdown 文本。
2. 完成判定由站点适配层给出（生成控件消失、文本稳定、有新的助手消息）并叠加超时上限（超时 `web_turn_timeout`，可重试）。
3. 完成后返回助手消息并**保留同一 Web 对话**，同一会话的后续 turn 继续复用；临时模式的“完成”只代表本轮完成，不代表新建或销毁临时对话。
4. 观察必须是短轮询，不能用长 `wait_for` 占住该页面的命令通道。
5. 已保存模式同时读取远端消息标识、标题和更新时间；Magi 只把缺失的可见消息增量写入 canonical，不把同步内容再次提交给 Web。

### 5.3 取消
- 用户取消 Magi turn：触发站点“停止生成”（尽力而为），应答全部挂起的 MCP 调用，turn 以取消收口，不重放。
- 取消后网页里可能留有半截回复：下一次存活判定会发现不一致，判为失效。这是保守但安全的行为。
- 已保存模式若取消后远端已经形成完整消息，下一次发送前可先同步该远端消息；临时模式不猜测半截内容，仍按失效处理。

## 6. 存活判定与远端同步（W5、W6、W13、W14）

### 6.1 临时模式：只认最后一条

**输入**
- 网页侧：最后一条消息的角色与展示文本（新增读取能力，见 §10）。
- Magi 侧：该会话最后一条镜像自网页的消息（用户消息或助手回复）。

**比对**：两者都用 `normalize_composer_text` 归一化后再计算摘要。Magi 里存的回复来自同一套 DOM 读取，因此同口径。

| 情形 | 结果 |
| --- | --- |
| 会话从未发过 Web 消息 | 不需要判定；要求网页为空的临时对话 |
| 页面最后一条 = Magi 最后一条 | 通过 |
| 页面为空、缺失，或最后一条不同 | 失效 |
| 上一轮在页面接受用户消息后失败，Magi 最后一条是用户消息，页面最后一条是同一条用户消息 | 通过（还没有回复） |
| 上一轮失败，页面上出现了 Magi 没存下来的半截回复 | 失效（保守） |

### 6.2 已保存模式：远端是事实源

已保存模式不因为 Magi 本地摘要不同就把历史重发给 Web。发送前按 `conversation_id` 从 Web 读取最新可见消息：

1. 远端存在且只是 Magi 尚未同步的尾部：按远端消息标识增量写入 canonical，再允许发送。
2. 远端不存在：返回 `web_saved_conversation_unavailable`，保留 Magi 已同步历史并标记绑定失效。
3. 远端出现无法映射的分支、删除或账号变化：停止发送，返回 `web_saved_conversation_conflict`，要求用户在 Web 中处理；不猜测、不覆盖远端。
4. 已保存对话的本地记录永远不能反向改变 Web 上下文；同步只负责展示与绑定。

**边界**：临时模式只做“最后一条一致”这一个判据，不做条数、不做全文比对；两个会话恰好最后一条文本完全相同的极端情况，不为它增加额外机制。已保存模式使用远端消息标识和 `conversation_id` 做绑定，不把标题作为身份。

## 7. 槽位与状态机

进程内单个记录：

```text
WebSlot {
  owner_session_id,
  owner_project_id,
  mode: temporary | saved,
  page_id,
  remote_conversation_id?,
  page_generation,
  active_turn_id?,
  claimed_at,
}
```

只有一个 `WebSlot`。`active_turn_id` 仅用于 daemon 内存中的归属和取消，不进入 canonical、provider_context、日志或任何持久化文件。

| 事件 | 迁移 |
| --- | --- |
| 临时会话首条消息，槽位空，页面为空 | 占用，槽位 = 本会话，模式 = `temporary` |
| 已保存会话绑定远端 `conversation_id`，槽位空 | 占用，槽位 = 本会话，模式 = `saved` |
| 会话发送，槽位 = 本会话，存活 / 远端同步通过 | 保持，复用同一页面和模式 |
| daemon / Magi 重启后尝试恢复临时会话 | **拒绝恢复**，标记 `web_context_lost`；不凭最后一条消息重新占用 |
| daemon / Magi 重启后尝试恢复已保存会话 | 以持久 `conversation_id` 重新打开并同步；远端不存在则标记绑定失效 |
| 会话发送，槽位 = 其他会话 | 拒绝 `web_session_busy` |
| 会话发送，存活判定不通过 | 拒绝 `web_context_lost`；拥有者若是本会话则释放槽位 |
| 会话切到本地 / 会话被删除 | 释放槽位，关闭页面 |
| 设置“停止并释放”/ 被占用提示“释放并使用”/ 清除数据 | 取消进行中推理，关闭页面，释放槽位 |
| 右栏折叠 / Tab 关闭视图 | 不改变槽位、页面或进行中的 turn，只改变可见性 |

槽位没有排队，也没有“接管”：**被占用就拒绝**。

## 8. 工具（通过 Magi MCP 服务）

GPT Web 自己不实现工具能力。工具目录、令牌、审批、路径限制、审计、传输与通道，全部由《[Magi MCP 服务设计](./magi-mcp-server-design.md)》定义；本节只写 GPT Web 作为它的一个客户端**特有**的部分。

### 8.1 定位
- 工具能力是可选增强：没有配置连接器、通道不可用或令牌失效时，GPT Web 的收发同步完全不受影响，只是该 Web 会话没有项目工具，并在界面说明具体缺什么。
- 消息里只有用户原文：不出现工具清单、调用格式或令牌；不使用文本协议；不向网页回填工具结果消息。
- GPT Web 宿主自身不是可调用目标：MCP 服务不向 Web 暴露该 WebView、登录 / 停止并释放、连接器配置或隧道凭据，也不允许模型通过工具重入自己的页面（见 MCP 文档 M8）。

### 8.2 GPT Web 特有的三件事

1. **连接器自动配置。** Magi 在托管的浏览器会话里，通过站点适配层：探测账号是否支持自定义连接器 → 把 Magi MCP 服务的地址与令牌按当前通道写入连接器 → 回读确认已启用 → 记录连接器身份与配置版本。只写连接器设置，不动用户其他设置。失败（套餐不支持、站点改版、校验不通过）显式报告，不假装可用。连接器配置成功不等于某个 Web turn 已授权：没有槽位拥有者时不返回项目工具。 站点适配层的实现约束：资料菜单与设置分区只响应完整的指针事件序列（单独 `click()` 打不开）；窄视口（右栏）下站点会收起侧栏，需先展开才能点到资料入口；站点已把“连接器 / 应用”分区改名为“插件”，该分区会跳到独立的 `/settings/` 页面；只读检查结束后必须还原到进入前的页面。账号等级只读资料行里文本恰好等于套餐名的节点，不从用户名或对话内容推断；识别不到就不显示，不展示 `unknown`。
2. **归属：`follow_web_slot`（W9）。** 连接器经 OpenAI Tunnel 拉起 `magi-daemon-app mcp-relay --stdio --slot`（daemon 自己的子命令，不另外分发 `magi-mcp`），连到 daemon 的**槽位端点**（本地 socket，不签发、不接受令牌）；身份与归属每个请求都从槽位表派生，归属模式固定为 `follow_web_slot`，工作区取自拥有者会话的项目（W17），权限档由用户在配置时选择（默认 `edit`，没有 `exec`）。`initialize` 与 `tools/list` 可以在 Web turn 之前执行；`tools/call` 只归属槽位拥有者**唯一进行中的 turn**，其余一律拒绝。同一槽位同一时间只有一个进行中的 Web turn，一个 turn 内的多个调用按请求顺序串行收口。
3. **槽位生命周期联动。** 槽位释放（停止并释放 / 切到本地 / 会话删除 / 清除数据）即令槽位身份消失、已建立连接的下一条请求失败并取消待审批；再次使用 GPT Web 时重新回读目录，只有回读成功才显示“工具可用”。项目切换或权限变化同样使旧连接失效；如果连接器无法可靠刷新目录，直接禁用工具，不复用旧目录。

### 8.3 通道
ChatGPT 连接器需要一个从 OpenAI 云端可达的入口。可用形态（详见 MCP 文档 §10）：

| 通道 | 定位 |
| --- | --- |
| **OpenAI Tunnel**（`openai/tunnel-client`） | **正式通道**。配置数据的来源与 Magi 的承接见下表；用户只需要在 OpenAI 平台创建 Tunnel 与仅含 Tunnels Read + Use 的运行时 API 密钥，然后在 Magi 设置里粘贴，**不需要下载或安装任何第三方工具** |
| Magi 网络模式（Cloudflare Quick Tunnel） | 只服务**外部 agent** 的 MCP 入口（地址每次开启都会变，由用户自行更新）；不作为 GPT Web 连接器入口 |

**通道配置数据的来源与 Magi 的承接**（原则：Magi 生成的由 Magi 生成，Web / 平台创建的由 Magi 提供配置入口，用户不碰文件和命令行）：

| 数据 | 来源 | Magi 的承接 |
| --- | --- | --- |
| Tunnel id | 用户在 OpenAI 平台创建（用 CLI 创建需要管理员密钥，权限过大，Magi 不代劳） | 设置里粘贴；保存时格式校验；提供「打开 OpenAI 平台 Tunnels 页面」入口 |
| 运行时 API 密钥（仅 Tunnels Read + Use） | 用户在 OpenAI 平台创建（只能在平台页创建） | 设置里粘贴；Magi 写入 `state_root/web-model/tunnel-api-key`（用户私有权限、原子写），之后永不回显、不进 settings / 日志 / 命令行（只传文件路径）；界面只显示「已保存」 |
| `tunnel-client` 可执行文件 | OpenAI 官方发布包 | **Magi 自动下载并校验**：固定版本，发布包的 SHA-256 固定在代码里，校验通过才解压到 `state_root/web-model/tunnel-client/v<版本>/`，并记录解压后文件的摘要供每次启动复核；失败 fail closed 并说明原因；首次启用时在后台完成。已对照 v0.0.15 的真实命令行核对：`runtimes connect` 的参数不变，`runtimes cleanup` / `stop` 不再接受 `--profile` / `--profile-dir`，身份边界只剩 Magi 独占的 runtime 别名（精确匹配，缺失或重名按未就绪） |
| stdio 中继 | Magi 自己 | daemon 可执行文件的 `mcp-relay` 子命令，随 daemon 分发 |
| 槽位端点、profile 目录、runtime 别名 | Magi 生成 | 自动生成，用户不可见 |
| 工具权限档 | Magi 设置 | 设置里选择（没有 `exec`） |
| ChatGPT 侧的 MCP 应用（连接 = 隧道） | 在 ChatGPT 里创建 | 用户显式点击后，Magi 在托管浏览器里自动完成。daemon 用 Host 的导航命令依次去到设置里的「插件」页（`/settings/plugins-settings`，读已安装列表）和 `/plugins` 目录页，页面脚本只在已打开的页面里读或点、**不做路由跳转**（命令执行期间路由换代会让 Desktop 把结果判为过期）：添加 → 创建 MCP 应用 → 连接选「隧道」→ 填名称与 Tunnel id → 身份验证选「无需身份验证」→ 勾选风险确认 → 创建，最后回到已安装列表按名称回读确认。已存在同名应用时不重复创建 |
| Developer mode / 工作区与 Tunnel 的关联 | ChatGPT 与 OpenAI 平台的账号 / 工作区策略 | Magi 不能也不应代改；创建失败或看不到入口时显示具体原因与去哪里处理 |

现有 Magi 的“远程访问”Cloudflare 通道面向 Magi Web / 手机访问，不能直接作为连接器地址；其 sidecar 托管与监控可复用，但不得复用用户会话路由、访问令牌，也不得把 `/api/*` 暴露给 ChatGPT。

前置条件（Developer Mode、工作区策略、Tunnel 与 API 密钥是否就绪）不由 Magi 保证：任一不满足即 fail closed，**该会话无工具能力**，并在界面说明具体缺哪一项。

### 8.4 一次工具往返（GPT Web 视角）
1. ChatGPT 在回复中调用某个具体工具 → MCP 服务按 §8.2 校验归属与权限 → 转成 Magi 的工具调用，`tools/call` **保持挂起**。
2. 审批与执行在 Magi 主窗口完成（WebView 隐藏时通过对话区 / 系统通知）；结果交回后应答，模型在**同一条回复**里继续写完。
3. 挂起时限、超时、拒绝与断连的行为完全由 MCP 服务决定（MCP 文档 §7）：超时或拒绝在同一个 `tools/call` 中返回明确工具错误，**不向网页追加回填消息**，不重放用户输入。
4. turn 进入终态时应答所有仍挂起的调用；超时后晚到的结果只写审计。
5. 工具调用与结果作为 Magi 自己的执行事实写入 canonical 并在该 Web 会话里展示；Magi 从网页读取的仍只是最终可见回复与 thinking。

## 9. 引擎与设置

- **固定入口**：只有一个 Web 引擎条目，`engineId = plugin/openai.chatgpt-web/default`，`apiProtocol = chatgpt_web`，不写 `llm`、不写 baseUrl / apiKey，来源标注“来自 Web”。不做模型菜单发现，不保存强度取值域，模型与强度由用户在网页里选。
- 会话内主模型选择器：未登录或登录探测未完成时**不显示** Web 入口；登录成功后空白会话可见并可选这一项；已有本地消息的会话不显示；Web 会话可切到本地模型（W2、W3）。不把网页里的 GPT 模型名称追加为 Magi 的独立模型条目。
- 选择 Web 引擎后显示模式选择：临时模式直接开始新的多轮临时对话；已保存模式显示 Web 历史选择器和“新建已保存对话”。已保存模式的 Magi 会话标题只接受 Web 返回的标题，标题读取失败时显示明确的未同步状态，不自行猜标题。
- 全局 `orchestrator` 保存入口拒绝 `chatgpt_web`；Web 引擎只能作为会话级绑定存在。
- 引擎状态（可用 / 需要登录 / 站点被拦 / 需要桌面 / 额度用尽）由 daemon 投影，UI 只展示，前端不自造结论。未登录时不显示 Web 引擎。
- 退出登录或清除 Web 数据后，Magi 既有 Web canonical 记录仍可读；临时绑定不可恢复，已保存绑定必须在同一账号重新登录并重新校验 `conversation_id` 后才能继续。
- 设置 → 浏览器 → GPT Web：登录状态、打开主页、**停止并释放**、清除 Web 数据、T3 通道状态与配置、当前槽位拥有者、临时 / 已保存模式、后台推理中的指示。不再有“连接 / 刷新 Web 模型”与上限标定。
- 额度只按**实际发送条数**计数展示，不折算 token，不进 token 聚合。

## 12. 错误与状态（精简）

| 错误码 | 含义 | 用户主行动 |
| --- | --- | --- |
| `web_session_busy` | 槽位被其他会话占用 | 到占用会话里停止，或先切到本地 |
| `web_context_lost` | 网页对话已失效 | 切换本地模型继续 / 新建 GPT Web 会话 |
| `web_saved_conversation_unavailable` | 已保存对话在远端不存在、账号不匹配或无法重新绑定 | 刷新 Web 历史 / 新建已保存对话 / 切换本地 |
| `web_saved_conversation_conflict` | 已保存对话在 Web 侧发生无法安全映射的分支、删除或外部修改 | 打开 Web 处理后重新同步 |
| `web_login_expired` | 未登录或登录过期 | 登录 |
| `web_site_blocked` | 风控 / 验证页 | 打开主页处理 |
| `web_selectors_drift` | 站点改版，选择器失效 | 运行诊断 |
| `web_desktop_unavailable` | 无可信 Desktop 连接 | 了解更多 |
| `web_send_rejected` / `web_write_not_confirmed` | 写入回读未确认或提交未被接受（无副作用） | 重试 |
| `web_turn_timeout` | 已接受提交但回复未在时限内完成 | 重试 |
| `web_quota_exhausted` | 账号额度用尽 | 切换本地模型 |
| `web_tunnel_unavailable` | T3 通道不可用（不是 turn 失败，该会话无工具能力） | 配置通道 |
| `magi_tool_timeout` | MCP 工具在同一 `tools/call` 等待窗口内未完成 | 处理当前 Web 回复或重试 |
| `magi_tool_denied` | Magi 项目权限或用户审批拒绝工具调用 | 调整权限 / 批准或取消 |
| `magi_tool_unavailable` | Magi MCP 服务、工具目录或通道不可用 | 修复通道 / 工具后重试 |

不再有：`ContextLengthExceeded`（Web 侧）、`web_tool_protocol_invalid`、`web_tool_round_limit`、`web_queue_full`、`web_queue_timeout`、任何 T2 文本协议错误码。

所有失败都不得静默降级到其他模型。这些错误码是 daemon 内部类型，不进入对外 schema 与 App Server 生成物。

## 13. 实施阶段与验收

### 阶段 0：真实站点验证（先于一切）
在隔离状态根、真实 Electron、真实 ChatGPT 上确认，并记录日期与证据：
1. 持久分区下登录态跨完整重启保留。
2. 各登录方式（邮箱 / Google / Microsoft / Apple）在现有 popup 规则下是否可用。
3. 写入输入框并回读确认、提交、被接受判定在真实页面上可用；输入框字符上限与超限表现。
4. 流式读取回复与 thinking、完成判定。
5. 读取“页面最后一条消息”的稳定性；页面重新加载、WebView 重新物化、应用重启后临时对话确实不可恢复。
6. 已保存对话的列表、标题、`conversation_id`、消息增量是否可用；远端不存在和账号切换是否能 fail closed。
7. 临时对话下连接器是否可用（T3 的前提）；`tools/list` 是否返回具体工具，`tools/call` 是否能在同一回复内挂起并续接。
任一不成立回到本文 §1 重新决策。

### 阶段 1：单槽位收发链路（无工具）
槽位与存活判定、发送与接收、取消、错误映射、失效状态；用假页面 fixture 做自动化，用真实站点做手动验收。
**验收**：登录一次后发送至少三轮消息且始终使用同一 Web 页面；Magi canonical 刷新后本地记录仍在；刷新 GPT Web 页面后临时会话被识别为失效；第二个会话在槽位被占用时被拒绝；取消后页面停止生成。

### 阶段 2：会话规则与界面
引擎类型固定、单向转换、选择器过滤、占用与失效提示、停止并释放 / 清除数据、后台推理指示、设置分区精简。
**验收**：未登录时模型选择器看不到 Web；登录后只出现一个“GPT Web · 来自 Web”入口；本地会话不能切 Web；Web 会话可切本地且不能再切回；关闭视图不丢对话，停止并释放才丢；重启后临时 Web 会话进入失效且切本地可继续；已保存 Web 会话可以按 `conversation_id` 重绑。

### 阶段 3：工具（GPT Web 接入 Magi MCP）
前置：Magi MCP 服务已按其文档完成本机阶段（令牌、审批、变更账本）。本阶段只做 GPT Web 特有部分：连接器自动配置（显式用户动作）、`follow_web_slot` 槽位端点、槽位生命周期联动、OpenAI Tunnel 正式通道。**先做 spike**：真实通道上 ChatGPT 连接器对 `tools/list`、挂起 `tools/call` 与审批耗时的实际行为。
**验收**：Web 会话能读文件、改文件（走审批）、执行命令（如权限档允许）；无进行中 turn 时调用被拒；同一调用超时不生成下一条回填消息；通道不可用时明确降为无工具并说明缺哪一项；切换项目不会改变当前 Web turn 的工具范围；槽位释放后旧令牌与旧连接立即失效。

### 阶段 4：打磨
诊断（登录、站点结构、通道连通性）、额度展示（发送条数）、文档与代码索引同步。

### 当前交付状态（与源码核对）
已实现并有自动化覆盖：单槽位（占用即拒绝、结束 / 释放钩子）、临时 / 已保存模式、发送前只写本轮原文、存活判定与 `web_context_lost`、取消、登录过期 / 站点被拦等错误上报到引擎可用性投影、已保存对话的绑定（单向导入）/ 发送前尾部同步 / 同步指针前移、停止 / 释放（切本地、会话删除、清除数据）、重启后自动恢复探测、选择器固定入口与对话方式 / 历史选择、设置分区（登录与可用性、占用与停止、OpenAI Tunnel 与权限档、连接器检查 / 显式配置、清除数据）、槽位端点网关（内置 + 下游 MCP + Skill，审批、规范工具条目）。

**尚未用真实环境验证**（需要登录的真实 ChatGPT、真实 Electron 与 OpenAI Tunnel 凭据，自动化不能替代）：阶段 0 的七项站点事实；站点适配层对已保存列表 / 标题 / 连接器配置的选择器；ChatGPT 连接器经 Tunnel stdio 的握手与单次 `tools/call` 挂起上限；已保存对话新建后 `/c/<id>` 的出现时机。旧的假页面 Electron 验收脚本已随旧设计删除，新的端到端脚本需要打包产物（`target/electron-dist`）后再补。

## 14. 风险与待定项

| 风险 / 待定 | 影响 | 处理 |
| --- | --- | --- |
| **合规与账号风险** | 程序化驱动网页版可能违反使用条款，账号有被限制的风险 | 需要产品与法务在阶段 0 之前给出结论；本文不替产品判断 |
| 站点 DOM 改版 | 发送、读取、连接器配置直接失效 | 选择器只在站点适配层；失败进入 `site_blocked`；用录制的真实 DOM 快照做回归 fixture |
| 额度与限流 | 每个用户消息、失败重试和多步工具任务都可能消耗账号消息条数 | 界面显示实际发送条数；工具结果必须在同一 `tools/call` / 同一回复内返回，不做下一条回填 |
| 归属不再由消息里的令牌绑定（W9，`follow_web_slot`） | 别处同账号调用可能被误归到进行中的 turn | 审批不可绕过；写入类默认需要确认；记录为已知取舍（MCP 文档 §12） |
| ChatGPT Connector / MCP 能力差异 | 自定义连接器可能不支持某些 Resource、Prompt 或长挂起行为 | 核心交付只依赖标准 `tools/list` / `tools/call`；阶段 3 真实通道验证，不用文本协议兜底 |
| 已保存对话的 DOM 变化 | 列表、标题和历史映射可能随站点改版失效 | 全部收敛在站点适配层；失败时保留本地镜像、停止写入，不猜测远端身份 |
| 网关暴露面大于“文件 / 搜索”工具 | Skill 与下游 MCP 工具也经同一条通道可被模型调用，影响面更大 | 它们按 `Destructive` 处理，每次调用都需要用户确认；依赖会话上下文的工具与管理面永不暴露；GPT Web 不为它们另做通道 |
| 单槽位限制体验 | 用户想同时开多个 Web 会话时被拒绝 | 这是刻意取舍（W4）；提示清楚如何释放 |
