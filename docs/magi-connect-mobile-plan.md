# Magi Connect 与移动端方案

> 状态：方案基线
> 更新日期：2026-08-03
> 适用范围：Desktop、Android、iOS、Magi Connect 服务及远程访问链路

## 1. 决策摘要

Magi 的核心执行能力继续运行在用户 Desktop 本地。Android/iOS 定位为远程控制与会话客户端，不在移动设备内复制完整的本地执行环境。

产品同时保留两种使用方式：

| 模式 | 是否需要账号 | 连接范围 | 适用场景 |
| --- | --- | --- | --- |
| 本地模式 | 否 | Desktop 本机、同一局域网 | 隐私优先、无需云服务 |
| Magi Connect | 是 | 跨网络、移动端、推送通知 | 普通用户的完整体验 |

账号是远程设备管理能力的入口，不是 Desktop 本地使用的前置条件。

Magi Connect 初期只建设控制面和连接编排能力，不保存用户代码、模型密钥和完整对话，不把 Magi 变成云端代码执行平台。

## 2. 产品目标

### 2.1 用户目标

- Desktop 安装后可以直接本地使用，不强制登录。
- 手机登录后可以看到自己的 Desktop 设备。
- 首次通过二维码完成一次配对，后续不重复扫描。
- Desktop 重启、IP 变化或 Tunnel 重连后，手机可以自动恢复连接。
- 手机可以查看对话、运行态、错误、审批和文件变更。
- 用户可以在任一端查看并撤销其他设备的访问权限。
- 局域网可用时优先使用局域网连接，外网时自动切换远程连接。

### 2.2 工程目标

- Desktop daemon 仍是本地状态和执行的权威来源。
- Web、Desktop、Android、iOS 共用业务 API 契约和前端领域模型。
- 设备身份、账号身份、连接地址和访问凭据分离管理。
- 远程连接断开不影响 Desktop 本地任务继续执行。
- 移动端恢复后通过状态快照和事件游标补齐状态，不依赖页面临时内存。
- 远程连接默认具备过期、轮换、吊销和最小权限能力。

## 3. 非目标

第一阶段不做以下内容：

- 不在 Android/iOS 上执行任意 Shell、Git、MCP 本地进程或完整 daemon。
- 不把用户代码、模型 API Key 或完整对话持久化到 Magi 服务。
- 不要求用户自行注册 Cloudflare、配置域名或维护 Tunnel。
- 不建设云端代码执行、云端工作区或云端模型代理。
- 不用移动端替代 Desktop 的本地文件系统和开发工具链。
- 不为了移动端复制一套独立的会话状态管理实现。

## 4. 总体架构

```text
                         ┌──────────────────────────┐
                         │      Magi Connect        │
                         │  账号 / 设备 / 配对 /     │
                         │  凭据 / 在线状态 / 推送   │
                         └───────────┬──────────────┘
                                     │ 控制面
                   ┌─────────────────┴─────────────────┐
                   │                                   │
             手机 App                              Desktop Connector
          Android / iOS                         主动出站连接、心跳
                   │                                   │
                   └───────────加密连接───────────────┘
                                     │
                              本地 Magi daemon
                                     │
               Workspace / Session / Model / Tool / Git / MCP
```

### 4.1 控制面

Magi Connect 负责：

- 用户账号和登录会话。
- Desktop、Android、iOS 设备注册。
- 一次性二维码配对和设备确认。
- 设备在线状态和最后心跳时间。
- 短期连接凭据签发、刷新、轮换和吊销。
- Desktop 连接实例与逻辑设备 ID 的映射。
- 移动端推送任务完成、异常和审批提醒。

控制面不负责执行用户任务。

### 4.2 数据面

数据面负责手机与用户 Desktop 之间的实时通信：

- 请求、SSE、WebSocket 或其他实时通道统一由连接层封装。
- Desktop 本地状态由 daemon 提供，移动端不维护第二个真相源。
- Desktop 断网时继续本地执行，重新连接后通过快照和事件游标同步。
- 远程连接服务只做转发和路由，不负责解析业务内容。

正式版本应在传输层 TLS 之外增加设备级身份校验。对于高敏感内容，预留端到端加密能力，避免连接基础设施成为代码和对话的长期存储方。

## 5. 身份与配对模型

### 5.1 三类身份

```text
Magi 用户账号
  ├── Desktop 设备身份
  ├── Android 设备身份
  └── iOS 设备身份
```

- 用户账号：用于登录、设备列表和授权管理。
- 设备身份：每台安装实例独立生成的密钥对和设备 ID。
- 连接凭据：针对某一设备、某一用户和某一权限范围签发，可独立吊销。

### 5.2 首次配对

1. Desktop 生成或恢复本地设备密钥。
2. Desktop 显示短期有效二维码，二维码只包含配对地址、设备 ID 和一次性配对挑战，不包含模型密钥。
3. 手机登录 Magi 账号后扫描二维码。
4. Desktop 展示待授权设备名称和权限范围。
5. 用户在 Desktop 明确确认。
6. Connect 服务签发手机设备凭据，Desktop 保存授权设备公钥和权限。
7. 手机后续只使用设备凭据连接，不再重复扫描。

### 5.3 权限

移动端默认使用受限访问：

- 查看会话和运行态。
- 发送对话消息。
- 查看错误、工具结果和文件变更。
- 处理低风险审批。

以下能力默认需要 Desktop 或用户额外授权：

- Shell 执行。
- 文件批准、还原和删除。
- Git 推送、重置和其他高风险操作。
- MCP 配置、密钥和连接管理。

## 6. 连接策略

连接层对用户隐藏具体传输方式，统一展示设备连接状态。

### 6.1 局域网

- Desktop 广播 `_magi._tcp` 服务。
- 广播信息包含逻辑设备 ID、协议版本和临时局域网端口，不广播访问凭据。
- 手机按设备 ID 自动发现，使用设备公钥完成身份校验。
- Desktop IP 变化不影响绑定。
- 移动端需要处理 Android 局域网权限和 iOS Local Network 权限。

### 6.2 远程连接

- Desktop Connector 主动建立出站连接，不要求用户开放入站端口。
- Desktop 重启后自动重新注册连接实例。
- 手机通过逻辑设备 ID 获取当前连接，不依赖随机 URL。
- Tunnel 或边缘连接变化由 Connect 服务对手机屏蔽。
- 当前 Quick Tunnel 仅保留为开发、诊断和临时分享能力。

### 6.3 自动切换

```text
设备绑定
  ↓
尝试局域网发现与连接
  ├─ 成功：使用局域网
  └─ 失败：查询 Connect 当前远程连接
                ├─ 成功：使用远程连接
                └─ 失败：展示设备离线和最后在线时间
```

连接切换不能创建新会话，必须复用已有的 workspace、session、turn 和事件游标。

## 7. Desktop 改造边界

当前 Desktop 宿主会直接启动 daemon，并注册托盘、单实例、更新和运行态恢复能力。移动端不能复用这套宿主。

建议拆分为：

```text
apps/desktop
  └── Desktop 宿主 + 本地 daemon + 桌面专用插件

apps/mobile
  └── 移动端宿主 + 连接管理 + 移动生命周期适配

web/src/shared
  └── API 契约、传输层、会话模型、主题和通用 UI 领域逻辑
```

Desktop 专属能力必须通过目标平台条件编译或保持在 Desktop crate 内，不允许移动端为了编译通过而挂载空实现。

移动端需要单独处理：

- 前后台切换和连接恢复。
- 网络变化。
- 屏幕尺寸和触摸操作。
- 安全存储。
- 推送点击后恢复对应 workspace/session。
- 长任务运行时的状态展示。

## 8. 服务端最小组成

第一版 Magi Connect 只需要以下服务：

| 服务 | 职责 |
| --- | --- |
| Account | 登录、会话和账号注销 |
| Device Registry | 设备注册、名称、在线状态和最后心跳 |
| Pairing | 一次性配对挑战、确认和凭据签发 |
| Connection Broker | Desktop 出站连接登记和手机连接路由 |
| Credential Service | 短期令牌、刷新、轮换和吊销 |
| Push Gateway | APNs/FCM 推送，不承载业务正文 |

服务端数据库只保存账号、设备公钥、授权关系、连接元数据和审计记录。默认不保存代码、模型密钥、对话正文和工具输出正文。

## 9. 现有实现的收敛方向

当前 `crates/magi-api/src/tunnel.rs` 使用 Cloudflare Quick Tunnel：

- Desktop 本地启动 `cloudflared`。
- 隧道地址随机生成。
- 访问 token 随隧道启动生成。
- `tunnel_token` 目前通过 URL 参数传递。

后续应收敛为：

1. 将 Quick Tunnel 标记为临时访问能力，不作为移动端正式连接基础。
2. 新增永久 Desktop 设备身份存储。
3. 将设备授权从 Tunnel token 中解耦。
4. 建立 Desktop Connector 出站连接和心跳协议。
5. 移动端使用逻辑设备 ID 查询当前连接。
6. 逐步将 URL token 替换为设备级 Authorization 和挑战签名。
7. 保留旧链路仅用于本地开发和迁移验证，完成迁移后清理旧双轨实现。

## 10. 分阶段推进

### 阶段一：连接内核抽象

- 抽象 `ConnectionManager`，统一局域网、远程和断线恢复状态。
- Desktop 生成并持久化设备身份。
- 连接状态、设备 ID、会话绑定和事件游标进入持久化模型。
- 不改变现有 Desktop 本地使用体验。

### 阶段二：本地一次配对

- 实现 mDNS 发现。
- 实现二维码一次性配对。
- 实现设备公钥校验、设备列表和撤销。
- 手机浏览器先完成局域网真实场景验证。

### 阶段三：Magi Connect 控制面

- 实现账号、设备注册、凭据刷新和连接 Broker。
- Desktop Connector 主动出站连接。
- 手机跨网络自动恢复。
- 不保存业务正文。

### 阶段四：Android 客户端

- Tauri 2 独立 mobile 宿主。
- 移动端导航、触摸交互和连接恢复。
- Android APK 内测包。
- 真机网络切换、后台恢复和权限验证。

### 阶段五：iOS 客户端

- iOS Simulator 验证。
- Apple Developer 签名后进行真机、TestFlight 验证。
- APNs 推送、后台恢复和本地网络权限验证。

## 11. 验收标准

### 账号与设备

- 本地 Desktop 未登录时仍可正常使用。
- 登录后同一账号的设备列表稳定可见。
- 手机首次配对后，Desktop 重启不要求重新扫码。
- 设备凭据可单独吊销，吊销后立即无法访问。

### 连接

- 局域网 IP 变化后可以自动重新发现。
- 从局域网切换到外网不会创建新会话。
- Desktop 重启期间手机显示离线，恢复后自动上线。
- Tunnel 断开后不会导致 Desktop 本地任务停止。

### 数据与安全

- 服务端日志不包含模型密钥、代码正文和完整对话正文。
- URL、日志和错误通知中不暴露长期凭据。
- 每台手机拥有独立凭据和权限范围。
- 高风险操作仍经过现有 Magi 权限、治理和审批链。

### 移动端

- Android 真机支持前后台切换和网络切换。
- iOS 真机支持本地网络权限和连接恢复。
- 推送点击可定位到正确 workspace 和 session。
- 移动端不展示无法执行的 Desktop 专属操作。

## 12. 关键风险

| 风险 | 处理策略 |
| --- | --- |
| Connect 服务不可用 | Desktop 本地继续运行；手机展示离线；恢复后按游标同步 |
| 远程连接被劫持 | 设备公钥校验、短期凭据、挑战签名、凭据吊销 |
| 服务端隐私风险 | 最小化存储，业务正文不落库，预留端到端加密 |
| 移动端后台被系统挂起 | 推送唤醒、连接重建、状态快照补偿，不依赖持续连接 |
| Desktop 版本不兼容 | 连接握手携带协议版本，服务端拒绝不兼容版本并提示升级 |
| 连接切换导致状态丢失 | workspace/session/事件游标由 daemon 权威管理，客户端只做投影 |
| 连接服务成本增长 | 第一阶段只转发在线连接，不保存正文，不做云端执行 |

## 13. 明确结论

1. 不要求用户自行配置 Cloudflare。
2. 不强制 Desktop 本地用户注册账号。
3. 移动远程能力使用 Magi Connect 账号和设备配对。
4. Magi 服务负责控制面和连接编排，不负责执行用户任务。
5. Desktop 继续作为本地代码、模型、文件和工具的唯一执行端。
6. Quick Tunnel 只用于开发和临时访问，不能作为正式移动端连接方案。
7. Android/iOS 必须使用独立移动宿主，不能直接复用 Desktop 宿主。
