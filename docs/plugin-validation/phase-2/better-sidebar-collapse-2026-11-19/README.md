# Better Sidebar 编辑期间折叠右栏

在 macOS arm64、Magi 3.0.62、Electron 45.0.0 的独立状态目录中，从 Magi 设置页在线安装固定的 `dsh-better-sidebar@0.32.1`。修复前，输入未保存的文本后折叠并展开右栏，原包编辑器文档被重新创建。原因是工作台在折叠时卸载整个右栏，标签仍在现有会话页签状态中。[修复前回执](baseline.json)

修复后，工作台在同一会话内保留已打开的插件文档。隐藏期间文档不参与布局，鼠标点击折叠按钮后焦点留在原生按钮。重新展开时验证原文档身份和未保存文本，磁盘仍为原内容。点击原包保存按钮后，文件写入新内容。随后折叠右栏并停用插件，隐藏文档被释放，旧实例路由失效。完整应用重启后，原包读取到已保存文件和已提交会话历史。[修复后回执](result.json) · [固定依赖锁](../sdk-admission-2026-11-19/dsh-better-sidebar-package-lock.json)

同一修复构建的原生右栏链接验收通过 16 项，覆盖初始未挂载、链接打开浏览器、同 URL 复用、会话归属和资源关闭。设置页也实测显示原包登记的会话头部与标签标题未挂载，右栏编辑时 Magi 的消息和输入区可用。标题组件需要和正文共享实时客户端状态，目前仍使用原包登记的静态标题文字。

复现时在修复构建上运行 [Better Sidebar 原包验收脚本](../../../../scripts/verify-electron-dsh-better-sidebar.mjs) 与 [原生右栏链接验收脚本](../../../../scripts/verify-electron-right-pane-links.mjs)。本批只验证桌面同一会话内的折叠与重开。切换会话时的未保存草稿、正式标题组件和 Web 工作台未做真机验收。
