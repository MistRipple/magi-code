# 来源值与重新分组合同

本批修复正式加载服务公开前已复现的来源编辑错误，仍是内部来源后端与领域执行验证。公开 `ctx.loader`、Mgr 页面业务及阶段 1 尚未通过。

## 问题与修复

- 新建组或将普通条目转换为组时，收纳已有成员会在旧位置留下同一 ID。现在候选先移除旧位置，再交给新组的完整数组所有者；失效的旧子项覆盖一并清退。
- 完整组配置已有覆盖所有者时，后续子项覆盖可能继续改写新数组。完整替换现在回到该所有者，并清退已由新数组表达的旧子项覆盖。
- 某个来源的最后一条覆盖移除后，其身份随覆盖丢失，空文件没有保存。序列化现在核对修改前后来源集合，明确保存空数组。
- 运行时的 nullable 等价被用于来源比较，显式 `null` 可能漏写。来源使用严格数据比较及字段差量，不改变上游运行时的比较语义。
- 清除最后一个字段覆盖会露出旧的继承值。字段清除现在处理实际来源的贡献定义，再沿原 journal 和最终来源重编译校验保存。

上述修改均为纯候选操作，仍由 `PluginManager` 的原 `pendingEdit`、文件保存和配置 CAS 提交；没有第二个配置所有者、逐行提交或原包改写。已删除不再使用的生成 helper 导出并重新生成。
