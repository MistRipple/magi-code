# Include 来源发现与恢复

在真实 Node 宿主和 Rust 插件管理领域中验证增删 Include 引用。基础文件和补丁层沿原入口读取，其他文件由有效引用决定。运行图应用前，daemon 将来源正文、图和执行实例描述作为同一配置修订提交。[版本、摘要和结果](result.json)

- 外部编辑新增了缺失的 `modules/managed.yml` 引用。接纳保留修订 1，诊断给出缺失文件。随后只创建该文件，实际文件通知触发修订 2，业务夹具在启动时读到已持久化的修订 2。
- 正式编辑入口移除并重新添加同一引用。修订 3 回收实例并从已接纳来源中移除该文件，文件正文保留。修订 4 接纳后重新启动实例并分配新身份。修改该新来源本身触发修订 5 并回收实例。
- 进程中断后只保留了已写入的父文件和编辑意图。新增依赖被外部修改时，重开管理器后明确拒绝恢复，并保留用户正文与修订 1。恢复已捕获的内容后，原事务提交修订 2。

固定 `dsh-plugin-mgr@0.2.13` 的原包文件与依赖锁摘要复核一致。原包启停函数写入候选文件后，文件通知和修订接纳仍能撤除、重建配置实例。重建后的原包仍等待 `loader` 和 `webServer`。本次未运行 Mgr 的界面、HTTP 路由、列表、安装、更新、卸载和自身更新任务，阶段 1 继续推进。
