# 旧插件路径清退（2026-11-18）

## 产品路径

插件搜索与安装沿 npm 原包或归档进入 daemon 的原包平台，安装、升级、启停和卸载由同一插件管理领域提交。插件列表为旧安装记录提供「需要重新安装」及显式卸载。旧记录中的设置页面、命令和 Skill 不再接入当前会话或设置导航。

- 删除安装期翻译、扫描、源码包装、版本豁免与旧译包管理过程。删除旧目录签名和发布工具、SDK 2 示例、旧作业与安装回执调度、旧 HTTP 资源和设置接口。
- 删除每插件一进程的 Node 宿主、旧页面资源消息桥、自动消息附加视图与输入框代提交入口。Magi 继续通过共享宿主桥接原包页和后端。
- 用户显式选择的插件命令由正在运行的 DSH 命令目录准入。宿主执行前核对命令所属插件，已退役的 SDK 2 注册数据无法提交新命令。
- 共享 Cordis 宿主通过实际 Include 路径读取加载来源。启动和恢复停止创建 `profiles/web`、`profiles/magi` 别名。正式的 SDK 私有数据放在 daemon 分配的独立目录。
- 旧数据文件保留。旧作者指南和内部协议历史可由仓库版本查阅。冻结的 App Server wire DTO 继续按已发布的 schema 处理。

## 验证范围

同一 macOS arm64 目录包使用随包 daemon、Node 和 SDK，在独立状态根依次在线安装五款固定原包。Mgr 从 0.2.12 升级到 0.2.13，原包设置页渲染，原包列表返回其他四款的精确版本。手动重启共享宿主后，五款均在新代次运行。Mgr 的旧页面请求和旧资源请求返回 409，新页面和资源请求返回 200。旧目录安装返回 404，独立状态根未创建 profile 别名。[目录包复测结果](packaged-smoke.json)

API 定向回归覆盖资源传输、PNG/SVG、下载、发布包完整性和作者指南。共享宿主、插件领域及 Mgr 原包的跨进程用例覆盖两版安装与升级、实际列表管理、启停、网关撤权和宿主监管。Node 用例覆盖所属插件命令执行及已撤权身份拒绝。

Web 类型、插件列表与安装、输入框和斜杠命令回归通过。`test:fixed-properties` 仍要求工具设置页展示此前已移除的 MCP 工具数节点。`test:ci-workflow` 因保留的根 DSH 清单版本 `0.2.2-rc.3` 与 Magi 的 workspace 预期不同而失败。

## 发布门槛

本轮验证范围是旧路径清退。阶段 1 同一构建的业务矩阵、并发配置和在途升级取消，以及阶段 2 右栏与会话事件仍分别验收。根 npm 清单与 CI 入口的已知不一致另行处理。未进行正式发布。
