# Magi UX/UI 设计与开发规范

更新日期：2026-10-30。适用于 Electron 桌面 GUI、Web 工作台，以及手机和平板通过 Web 访问的同一套界面。

本文是后续界面设计、文案、优化、修复和验收的共同基线，整理自已确认的产品要求。文中的“必须 / 禁止”是实施约束，“推荐”是默认设计选择；尺寸基准必须结合控件用途和可用空间使用。本文不代表全项目已经完成合规审查，也不把尚未实现的要求描述为已交付能力。

## 1. 使用方式与产品边界

每次 UI 工作按以下顺序推进：读取本文及改动目录的 `AGENTS.md` → 核对源码、调用方和状态所有者 → 解释问题根因 → 提出三条具体修复 → 沿共享组件实现最小完整修改 → 按改动面验收 → 清理废弃实现。

- 用户当轮明确要求优先，后续修正需同步本文；不凭外部参考资料覆盖已确认的产品交互。
- 本文定义设计要求；源码与真实运行链路用于判断当前实现。发现差距应如实说明并在本次授权范围内修复，不能把源码中的问题当作豁免理由。
- 不为语言、桌面和手机分别维护一套业务界面。复用组件、语义、业务入口，以容器空间和输入能力适配布局。
- Magi 不新增 CLI 或独立移动应用；不借 UI 优化扩大外部 Executor 的实施范围。
- 不改变现有弹出方案的入口、位置和方向，不自行引入弹窗、底部上滑面板等替代交互。
- 保留现有下拉交互，不因少选项就擅自改为单选、开关或平铺按钮。主对话权限模式、模型选择、推理等级继续使用既定下拉方案。
- 紧凑通过信息取舍、行高和留白实现，不能靠缩小触摸热区、裁切关键信息或限制卡片宽度实现。
- 业务事实由 daemon 拥有；UI 不复制会话、任务、权限、模型选择和持久化权威，不从动画或文案推断业务成功。

参考资料：[desktop-agent-ui](https://github.com/Ludi-Herry/desktop-agent-ui) 可用于核对适用于 Magi 的非弹窗设计思路；它不是 Magi 的权威规范，也不代表已完整采纳。更具体的业务合同见[对话展示设计](conversation-display-modes.md)、[模型推理能力](model-reasoning-capabilities.md)、[Browser 设计](browser-runtime-design.md)。

## 2. 布局、自适应与密度

### 2.1 宽度与对齐

- 卡片、通知展开详情、代理记录等跟随所在内容区域宽度；禁止无依据地增加独立固定宽度上限，留下大面积侧边空白。
- 内容区域对齐由父布局控制，不逐个子组件补不同宽度、负边距或定位偏移。
- 正文阅读列、设置页和浮层可以有明确用途的最大宽度，但内部内容必须跟随该列伸缩。设置页保留 `web/AGENTS.md` 定义的内容列规格。
- Flex/Grid 的可收缩内容设置 `min-inline-size: 0`；长标题、模型名、路径不能把状态、操作和页面撑出视口。
- 单行任务名、标题可省略，保留完整可访问名称及详情入口；错误原因、权限说明等关键内容允许换行，不能全部藏在 tooltip 中。
- 变更、知识库、MCP、模型配置等面板的标题、字段、说明和操作使用一致对齐轴；多个短参数在空间允许时采用两列，窄容器退回单列。

### 2.2 高度与滚动

- 所有文本域禁止用户拖动调整宽高，统一由共享样式设置 `resize: none`；局部组件不得重新开放原生缩放，也不另设文本输入区拖动手柄。尺寸由布局、行数或内容自适应控制，长内容保留内部滚动和键盘编辑能力。
- 可伸缩面板必须建立完整的高度链路；内容区使用剩余高度，不能继续被内部固定 `height` / `max-height` 截住。
- Flex/Grid 滚动子区域设置 `min-block-size: 0`、`overflow: auto`；头部和底部操作区按内容占高。
- 固定高度仅用于有明确用途的元素，例如缩略图；菜单限高、编辑器初始预览等限制应标明用途，不能传播到整个内容区。
- 优先一个主要滚动区域，避免多层嵌套滚动让用户找不到内容。
- 软键盘、横屏、安全区和浏览器动态工具栏出现时，输入区和关键操作仍可到达；不要只按静态 `100vh` 验收。

### 2.3 分栏与覆盖

- 拖动分栏时在右侧预览上覆盖透明交互遮罩，避免 iframe / Browser 内容吞掉指针事件。
- Esc 恢复本次拖动前比例；双击恢复既定默认比例（双栏为 50/50）；左栏超过约定的 82% 边界时收起右栏。
- 容器不足以容纳并排最小宽度时，沿现有布局逻辑进入覆盖模式；不增加第二套断点或并行布局状态。
- 覆盖面板必须遮住后方正文。并排面板的半透明背景不能直接用于覆盖状态。
- 复用 `data-magi-surface` 及现有主题材质：本层以不透明主题底色承接自己的壁纸与材质，不透出后方文字。不得靠提高 `z-index` 或加大模糊掩盖透明问题。

## 3. 视觉、文案与状态

- 使用现有设计令牌和共享组件。侧栏、主对话、输入框、右栏具有可辨认的层次，浅色与深色均需验收。
- 同一视觉容器只保留一层主要边界。容器内工具按钮使用无边框外观，以悬停、按下和焦点态反馈。
- 描边优先使用 inset box-shadow，避免选中、错误或悬停时改变布局尺寸；焦点标识必须清楚。
- 嵌套圆角按“外圆角＝内圆角＋内边距”设置，使用同一组 CSS 变量计算；规则适用于等距嵌套的圆角表面，非等距布局按相邻边的实际距离校准，胶囊和圆形保留自身形态。
- 标题、正文、辅助信息、状态和错误应有明确层级。用户消息正文沿用正文前景色，链接及状态另按语义着色。
- 产品文案先说明动作和对象，移除重复协议说明、装饰标签和无意义内部术语；内部标识只在必要的诊断位置出现。
- 状态必须同时有可读文字或形状，不能只靠红绿颜色。运行、等待、完成、失败、停止和结果未确认按业务合同区分。
- 空内容、加载、可重试错误、禁用和恢复过程均需明确展示；不能用无限加载掩盖错误或缺失数据。
- 不从“派发成功”“请求已发送”推断代理执行成功或权限已生效。旧请求、旧会话和迟到事件不能污染当前视图。
- 工作区与会话目录按数据归属及时加载、更新；不要求用户先点击某个工作区才收到其列表更新。具体同步行为沿现有数据入口实现。

### 3.1 五项视觉细节与实施边界

| 细节 | 可执行要求 | 验收方法 |
| --- | --- | --- |
| 等宽数字 | 计数、耗时、用量、百分比和时间戳使用 `font-variant-numeric: tabular-nums`，保留原字体，不把全部文字改成等宽字体。优先继承全局设置，组件使用 `font` 简写后核对是否重置。位数增长仍可能改变宽度，需要稳定对齐时按预期位数保留 `ch` 空间，不能截掉有效数字。 | 对照 `11` / `88`、`09:59` / `10:00`、`9` / `10`；同位数字不抖动，跨位数不挤掉操作。 |
| 同心圆角 | 等距嵌套表面用 `calc(var(--inner-radius) + var(--inset))` 计算外圆角；修改 padding 时同步计算，不逐层堆放任意圆角。 | 检查菜单选中底、内卡片与外容器四角的间距；焦点环不被裁切。 |
| 拆分错峰入场 | 新进入的页面或详情按标题 → 内容 → 操作分组，推荐相邻延迟 30–40ms、总时长不超过约 220ms。只动画 opacity / transform；含 fixed 浮层的祖先只用 opacity，避免改变定位参照。复用共享组件，内容更新不重复播放，不逐条延迟长列表或流式消息。 | 首次打开、返回、切页和异步加载均可立即操作；`prefers-reduced-motion: reduce` 关闭装饰入场，关键运行反馈仍遵循第 7 节。 |
| 平衡标题换行 | 可换行的短标题使用 `text-wrap: balance`，辅助说明可用 `pretty`；保留技术标识与单行省略的既有规则。不硬插 `<br>`、不为各语言单独切行，不承诺 CSS 在所有语言中绝对消除孤词。 | 用窄容器及 2–3 倍长译文观察行长；标题不溢出，按钮与正文不受牵连。 |
| 多层柔和阴影 | 浮层和需要抬升的表面复用共享 `--shadow-*`，以近处接触阴影＋远处低透明度环境阴影表达层次，替换浓重单层投影和多重硬边。必要轮廓保留一层轻微 inset 描边，输入、焦点、错误、选中等语义边界保持可辨。平铺设置分区继续遵循 `web/AGENTS.md` 的无外阴影结构。 | 浅色、深色和壁纸背景下边界清楚；无黑晕、重复描边、裁切和布局跳动；不改变弹出位置。 |

全局审查先核对已有共享实现，再针对真实缺口修改。已满足的等宽数字、圆角关系不重复加样式；不能用全局强制动画或删除所有边框代替逐项判断。

## 4. Select 与 Dropdown

| 类型 | 用途 | 展示与行为 |
| --- | --- | --- |
| Select（选择器） | 填表、筛选、状态或配置数据选择 | 选中值体现在控件中；按现有合同保存或提交，不能将选择误当成命令 |
| Dropdown（下拉菜单） | 多个命令或跳转入口 | 图标或文字触发，点击项执行操作；不把操作名称回填成选中值 |

- 筛选与“更多操作”必须在视觉、可访问语义和需求描述中明确区分，不统称“下拉框”。
- 只有两个或少于五个选项时，可评估是否更直观，但不覆盖第 1 节保留下拉的产品要求。
- 超过十个选项的选择列表必须提供搜索。长列表面板以 264px 为默认高度上限，超出滚动，并服从实际视口空间。
- 用户熟悉且适合直接填写的数据，如手机号、日期信息，优先输入；日期解析和校验仍需沿字段语义处理。
- 键盘、焦点、选中态、禁用态和关闭行为一致。沿用现有弹出方向，不因本规范引入新的移动端弹出方案。

## 5. 多语言、文字膨胀与方向

### 5.1 同一组件适配所有语言

- 中文短词译成欧洲语言时，以 2–3 倍长度作为早期压力测试基准；十个字母以内的短词尤其需要检查。该比例不是每条真实译文的固定换算规则。
- 文字按钮、标签禁止写死像素宽度。普通文字操作按钮的最小宽度采用 88–96px，增加水平内边距，允许内容撑高或按用途截断降级。
- 上述下限不机械应用于图标按钮、紧凑状态标签和所有工具栏控件；触摸目标另见第 6 节。
- 多按钮空间不足时优先换行或重排；关键动作、错误和授权后果不可截断成无法理解的文案。
- 文案先精简为准确动词；仍放不下且有明确通用图标时才考虑图标＋tooltip，保留本地化可访问名称。触屏关键操作不能只靠悬停解释。
- 使用现有 i18n 字典与插值，不硬编码产品文案、不拼接面向用户的句子、不在 JSX/Svelte 中为各语言复制布局。

### 5.2 底部操作栏档位

- 对具有“辅助区＋主操作”结构的底部栏，辅助区可用 `0% / 13% / 28% / 43% / 72%` 档位，主操作填满剩余空间。
- 档位按控件用途与容器可用宽度决定，不按语言单独设置；`0%` 时辅助区及其间距均移除。
- 高占比辅助区必须保留主操作的最小空间，不足时上下排列；不能把主按钮挤成窄条。
- 这套比例不套用到主对话、工作区侧栏、全部表单或现有输入工具栏，也不替换分栏拖动合同。

### 5.3 字形与 RTL

- 自然语言正文、可换行按钮使用相对行高 1.5–1.6 并预留上下内边距。代码和其他专用排版保持自身可读规格。
- 泰语、越南语、阿拉伯语的上下音标不能被固定高度与 `overflow: hidden` 裁切；字体回退必须覆盖字形。
- 布局优先使用 `inline-start / inline-end` 等逻辑属性，RTL 页面沿同一结构镜像。
- 仅镜像返回、前进等有方向语义的图标；搜索、关闭、品牌等图标不做无差别翻转。
- 按产品要求，进度条、数字、电话号码、时间戳保持 LTR；代码、模型标识、URL 和路径使用独立 LTR 区域。
- 动态混排使用 `bdi` / 方向隔离，验证括号、标点、负号、数字顺序与复制结果。
- 可用伪本地化及德语、荷兰语、阿拉伯语、越南语和泰语样例做压力测试，不据此宣称新增了正式支持语言。

## 6. 移动端触摸交互

### 6.1 尺寸标注

Web 统一使用 CSS px 表达逻辑尺寸，不按 DPR 再乘一次设备像素。视觉图标可以精致，热区必须容易命中。

| 元素 | 视觉尺寸 | 目标热区 | 透明 padding / 相邻间距 |
| --- | --- | --- | --- |
| 普通图标按钮 | 16px | 推荐 44×44px，常规至少 40×40px | 44px 容器四周各 14px；40px 各 12px |
| 发送、确认等主要操作 | 16–20px 图标或文字 | 推荐 48×48px | 按内容增加内边距；与相邻热区不重叠 |
| 极受限、低频非关键操作 | 可保持 16px | 底线 28×28px | 16px 图标四周各 6px；不得作为默认规格 |
| 头像＋名称等同源入口 | 沿用现有视觉 | 连续区域，至少 44px 高 | 元素间视觉间隔属于同一个可点击容器 |
| 滑动区域边缘的独立按钮 | 沿用视觉 | 常规至少 40×40px | 与发生手势竞争的边缘留至少 20px 缓冲 |

- 设计与交付必须分别标注：视觉尺寸、热区尺寸、透明 padding、相邻热区间距、滑动缓冲带。一般相邻操作以 8px 间距为起点，按密度与误触风险调整；破坏性操作与高频操作增加隔离。
- 优先扩大真实按钮容器，禁止将 16px 图标直接做成 16px 热区；避免绝对定位伪元素覆盖相邻按钮。
- 优先按 `(hover: none)` / `(pointer: coarse)` 适配触控，不把窄桌面窗口直接等同手机；混合输入设备还需检查实际触摸行为。
- 空间不足时重排或沿现有菜单入口收敛，不能继续缩小热区。

### 6.2 连续热区与手势隔离

- 同一目标的头像、名称、说明放进一个连续按钮或链接；允许视觉间距，但中间不能成为点击死区。
- 不同命令使用相邻独立按钮；禁止按钮嵌套按钮、同源元素分别绑定重复事件、独立命令冒泡触发整行。
- 优先原生滚动和 `click`；不能在 `pointerdown` 时直接执行提交、删除等业务操作。
- 自定义拖动必须处理位移阈值、`pointercancel`、捕获释放与点击抑制，拖动结束不得多执行一次点击。
- 滑动 Tab、横向列表与独立按钮有手势竞争时留至少 20px 缓冲；缓冲不能是挡住用户输入的透明覆盖层。
- 不全局拦截 `touchmove`、不全局使用 `touch-action: none`；保留纵向滚动和缩放。

### 6.3 反馈闭环

| 时机 | 必须/推荐行为 |
| --- | --- |
| 手指按下 | 必须立即提供底色、描边等可见按下态，不等网络返回 |
| 有效激活 | 支持的触摸设备推荐约 30ms 轻震动，一次操作最多一次 |
| 请求执行与结果 | 根据真实事实显示 pending、运行、成功或失败；震动不能冒充业务成功 |

- 禁用、滑动取消、重复点击被拦截时不震动；键盘与鼠标不强制震动。
- 触觉反馈集中复用共享入口；本规范不要求新增持久化偏好、原生桥或一套移动应用。
- Web 标准振动接口只支持时长和节奏，不能设置 Taptic 强度、锐度；iOS Safari 等不支持时保留完整视觉反馈。不得承诺所有设备都能震动。
- 减少动态效果时减少缩放、位移与旋转，仍保留清楚的按下与运行状态反馈。

## 7. 对话输入、滚动与关键动画

- 输入区发送/停止共用一个主操作位置：响应中草稿为空显示停止，有内容切换为发送，清空或成功提交清空后恢复停止；空闲显示发送，不能同时出现发送与停止两个主按钮。附件及其他可提交输入沿现有草稿规则判定；不可提交时禁用发送，不通过切回停止改变用户意图。发送继续使用现有排队链路，不隐式中断当前任务；队列编辑、继续及明确的替代操作保留各自语义。
- 中文输入法组合态（`isComposing` 或 `keyCode === 229`）按回车不能发送；选字结束后 500ms 内的回车继续保护，使用现有 IME 边界覆盖相关提交入口。
- 换行快捷键、斜杠菜单与发送按现有输入合同协调；不能因保护发送而禁止正常输入或组合选字。
- 距底部约 40px 内才自动跟随新消息；用户主动滚动时停止抢占位置，回到底部或点击“跳至最新”后可恢复跟随。
- 距底部超过约 120px 显示“跳至最新”；流式更新、加载历史和展开卡片不能无故把阅读位置拉走。
- 等待 Agent 响应的三点动画、加载、压缩、运行、上传等关键持续状态必须有反馈；不能通过全局禁用动画让运行看起来冻结。
- 动画与业务状态绑定，完成、失败和停止后结束对应动效。沿现有 `prefers-reduced-motion` 策略将关键持续反馈降为缓慢明暗变化，装饰动效可关闭。

## 8. 代理记录与信息分层

- 详细模式按时间顺序保留过程与角色信息，摘要模式突出最终回答、收敛过程，保留原代理任务入口。
- 两种模式共用 Task 身份、实际状态、点击行为、模型与推理等级快照。UI 不能从当前角色设置补造历史执行信息。
- 代理选择先确定合适角色，再消费该代理绑定的模型；展示优化不能反向变成按模型质量擅自创建代理。
- 每个运行按 Task 身份确定稳定识别色，用于细色线、淡底与图标；主对话、运行中心、详情标签一致，重绘或继续后不换色。有限色板可能复用颜色，仍需依靠名称和状态识别，不能承诺绝对唯一。
- 识别色与状态色分别表达；停止不伪装失败，创建成功不伪装执行完成。
- 长模型名可截断，但实际推理等级保留可见；完整信息可查看。任务名保持单行，具体失败诊断可换行。
- 任务卡片随内容列铺满，不另设 560px 等独立上限；紧凑通过纵向留白和信息排版实现。
- 主对话不重复嵌入完整子代理 transcript，也不复制详情、运行中心的管理操作。业务细节以[对话展示设计](conversation-display-modes.md)为准。

### 9.4 可选触觉反馈

在已有有效激活处理器通过禁用/重复请求检查后调用，不在每个子元素上重复调用。浏览器 click 未提供触摸指针类型时可以不震动，不凭屏幕窄或 `event.detail` 猜测触摸。

```ts
function lightTouchFeedback(event: MouseEvent): void {
  if (!('pointerType' in event) || event.pointerType !== 'touch') return;
  if (typeof navigator !== 'undefined' && typeof navigator.vibrate === 'function') {
    navigator.vibrate(30);
  }
}
```

自定义手势复用已有点击/拖动判定。普通按钮不能为调用震动另建一套手势识别或原生 IPC。

## 10. 验收清单与交付
