# Magi 插件系统：需求与方案设计

> 状态：插件合同、安装/升级/授权/激活、工具/工作流/设置/隔离视图、GPT Web/MCP 第一方插件壳与官方插件中心已接入。Windows Worker OS 限制按 §5.1 定案不做；三平台安装版、异步 SDK 取消结算和通用 Browser surface 仍是明确交付边界。各能力状态以 §10.1 为准。
> 日期：2026-10-11。
> 本文统一记录插件系统的产品需求、目标架构与验收条件。已进入源码的插件字段和 DTO 以 App Server schema 及生成物为准；尚未实施的部分仍以方案约束为准，不得据此伪造可用入口。正文中标注“当前实现”的段落记录与目标设计的已知差距。
> 现有功能继续遵循当前架构文档；插件化切换时同步修订相关基线，不保留相互冲突的两套实现说明。

## 1. 产品目标与范围

用户可以自行编写、安装、启用、配置和卸载插件，为 Magi 增加功能、界面和工作方式，无须修改 Magi 源码或重新构建安装包。

插件是统一的分发和生命周期单元。一个插件可以贡献工具、命令、设置页、主页入口、右侧面板、数据资源、原生能力配置或工作流核心，也可以只贡献其中一项。

### 1.1 已确认的需求

| 编号 | 需求 | 产品结果 |
| --- | --- | --- |
| R1 | 保留原生能力 | Skill、Subagent、MCP、内置浏览器仍由 Magi 提供；插件通过正式接口使用它们 |
| R2 | 可选功能独立安装 | GPT Web 等可选功能以插件交付；未安装时不启动其功能逻辑，也不注册其入口 |
| R3 | 多来源安装 | 支持插件中心、指定地址和本地插件包；个人插件不必先上架 |
| R4 | 设置集成 | 已启用插件可在设置面板显示对应功能 Tab，配置由统一入口保存 |
| R5 | 工作台集成 | 插件可声明主页入口、主内容区页面和右侧 Tab，内容支持自定义交互界面 |
| R6 | 自定义功能 | 用户可实现自己的数据看板或其他功能，并决定是否向模型开放工具 |
| R7 | 同步展示 | 插件页面可持续展示实际数据和操作结果，无须等待整轮对话结束 |
| R8 | 工作流替换 | 用户可提供自己的决策和编排逻辑，并为新运行选定工作流核心 |
| R9 | 唯一执行链路 | 默认实现和插件实现使用同一合同；每个插件只有一个事实所有者和写入入口 |
| R10 | 完整退出 | 禁用、升级、卸载和崩溃有明确行为，及时撤销注册和释放资源 |

用户此前提出的特定专业领域只是用于说明扩展能力的假设，不纳入本项目的业务范围、示例插件或验收要求。本文使用通用数据资源和界面操作描述同步能力。

### 1.2 方案建议与范围限制

以下是本草案建议的设计决策，并非用户已经逐项确认的实现细节：

- 首个交付目标是 Desktop 安装版；纯 Web/无头入口按宿主能力启用可用贡献，不能伪造桌面能力。
- 插件中心与地址安装使用同一种包格式、校验流程和安装服务。
- 安装与启用分开记录；依赖和授权满足后才允许激活。安装工作流不自动替换当前工作流。
- 按用户安装、全局启用，对所有工作区一致（见 §5.3）。工作区中的普通文件不能自动安装或启用代码。
- 首期不实现插件市场收费、云端托管执行、多人实时协同编辑，也不兼容其他产品的插件包。
- 不开放任意修改 Magi 内部对象、审批界面、canonical 日志或 TaskStore 的接口。

“禁止兼容和补丁”在本方案中指不保留旧功能执行分支、影子实现或静默兜底。新插件仍须声明支持的 SDK 契约版本；不受支持时明确拒绝加载，不尝试另一种解释执行。

## 2. 当前实现入口

本节记录已接入的唯一入口；未关闭的设计与平台边界见第 10、12 节。

当前已接入的实现入口：`magi-plugin-system::PluginManager` 由 daemon 恢复并通过 `/api/plugins/*` 提供唯一安装、升级、授权、启用、激活、停用、禁用和卸载入口；`PluginResourceStore` 由同一管理器持有，资源键包含插件、作用域（固定为 `application`）和资源 ID，并执行版本冲突检查；插件设置使用同一版本化资源服务并按声明 schema 校验；激活插件的工具贡献全局进入 `ToolRegistry`，模型调用和实际执行使用同一工具目录与插件 Worker。`/api/plugins/{id}/ui/{path}` 只服务已激活包内的 `ui/` 资源，隔离 iframe 通过受控消息桥读取和提交资源。Web 右栏对 active manifest 的 `rightPane` 视图提供隔离 iframe 承载，设置页展示插件声明的权限后再执行授权激活。未声明的贡献仍不会注册到任何目录或入口。

GPT Web 现在也有第一方插件包入口：`/api/plugins/bundled/openai.chatgpt-web/install` 生成并送入与用户 ZIP 相同的校验和 `PluginManager` 安装链；其原生宿主适配器只有在该插件的应用作用域激活、且模型与浏览器权限均获授权后才接受会话引擎调用。未安装或未激活时，模型选择器、浏览器页面运维入口和 GPT Web 右栏入口均保持关闭。引擎身份为 `plugin/openai.chatgpt-web/<family>`，不为更早的引擎身份保留任何迁移或读取兼容；插件未安装时绑定该引擎的会话显示引擎不可用，安装并激活后恢复。GPT Web 的站点逻辑按 §9 的定案留在 Magi 内部，插件是它的安装与激活壳。

必须延续的基线：

- [整体架构](README.md)：daemon 是唯一业务内核，Electron Main 托管物理桌面资源。
- [Turn 与任务架构](conversation-response-core-architecture-redesign.md)：统一接纳，conversation/task profile 不在运行中隐式转换，日志与 TaskStore 各有唯一所有者。
- [浏览器架构](browser-runtime-design.md)：BrowserAuthority 拥有逻辑浏览器状态，Main 拥有物理 guest，右栏公共壳只维护布局。
- [GPT Web 开发基线](web-model-browser-development.md)及 [MCP 服务设计](magi-mcp-server-design.md)：现有上下文方向、槽位归属和工具授权语义，不能借插件化悄悄改变。

## 4. 统一包与贡献模型

### 4.1 包身份

插件包声明以下信息，所有资源使用 `pluginId + contributionId` 命名，不能覆盖原生或其他插件的 ID。

| 信息 | 用途 |
| --- | --- |
| ID、名称、版本、作者、说明 | 稳定身份与展示；显示名称不能作为授权身份 |
| SDK 契约版本、宿主能力要求 | 加载前判断是否可执行 |
| 平台和架构 | 判断是否包含当前系统所需资源 |
| 执行产物格式、执行入口、前端资源入口 | 加载第 4.1 节固定格式的已构建资源，不在用户机器上编译源码 |
| 贡献清单 | 声明工具、页面、设置、命令、工作流等可见能力 |
| 权限声明 | 文件范围、网络目标、原生能力和可选外部进程需求 |
| 依赖 | 首期支持 SDK、原生能力以及包内资源；插件间依赖首期不开放 |
| 数据 schema 版本 | 插件配置、私有数据、检查点的格式校验 |

运行时依赖应随插件构建打包，Magi 扩展运行环境随产品安装包提供。插件安装不依赖用户安装 Node.js、npm、Python 或其他开发工具，也不执行任意安装后脚本。

插件包只能包含选定的受限执行产物、前端静态资源、schema 与声明文件。后台执行基线确定为 QuickJS 引擎下的 UTF-8 JavaScript ESM bundle：一个入口、所有作者依赖在构建时打包、无宿主外部 import；包内不接受预编译 QuickJS 字节码或 WASM 后台组件。正式产品只维护这一种后台加载器，加载失败明确拒绝，不尝试其他格式。浏览器端脚本属于视图资源，不能充当第二条后台执行入口。

包内禁止携带宿主原生可执行程序、动态库或 Node.js 原生模块，也禁止安装后下载并执行这些程序。选定的 JavaScript 产物只交给扩展运行时执行，不能作为系统进程启动；任何贡献都不能引用包内路径作为外部程序。解包时校验产物结构和资源类型，运行时继续限制进程调用与下载执行，不能仅靠后缀或作者声明保证这一边界。执行引擎和原生 Worker 由 Magi 安装包提供，不是插件可替换或自行下载的资源。

需要独立外部程序的插件必须声明该依赖及平台限制，并显示明确的就绪状态；不能把用户机器上偶然存在的程序当作可交付能力。

### 4.2 贡献类型

| 贡献 | 职责与约束 |
| --- | --- |
| 工具 | 提交工具 schema 和处理器，经现有工具目录、治理和执行记录调用 |
| 命令 | 注册显式用户动作；需要模型或任务时回到现有接纳入口 |
| 设置 | 声明配置 schema；可选自定义配置界面，保存仍经过 daemon 校验 |
| 页面与视图 | 声明主页入口、主内容区页面、右侧面板；同一份视图资源可用于多个位置 |
| 数据资源 | 声明资源身份、读取快照、变更订阅和受控操作，供 UI 与工具共享 |
| Skill 工作流 | 提供面向用户目标的说明、步骤、模板、参考资料和资源；Skill 本身不获得隐式副作用权限，所需工具仍通过显式的工具或 MCP 贡献调用 |
| MCP 服务声明 | 声明工具 schema、结构化输入输出、认证和远端服务端点；仍进入 Magi 的 MCP 注册、用户确认、权限和审计入口。配置不能指向插件包内文件，也不能借此让 Magi 拉起插件自带进程 |
| 原生能力资源 | 提供角色定义或其他 Magi 原生能力配置，仍进入各原生注册与调用入口。Skill 和 MCP 不绕过第 4.1 节对外部程序的限制 |
| 工作流核心 | 实现下一步决策、阶段、等待和完成条件，不拥有权限和终态事实 |
| 会话引擎适配 | 为 GPT Web 等可选引擎提供发送、流式结果、取消与就绪接口，遵循已选 execution profile |
| 事件订阅 | 观察授权范围内的已提交事件；额外副作用必须显式请求执行服务 |
| 生命周期事件 | 订阅 Magi 明确定义的安装、激活、运行、禁用和释放事件；每个事件声明可用数据和副作用权限，不提供任意脚本钩子 |

会话引擎负责消息传递和结果获取；工作流负责 task 运行的决策编排。两者不能互相伪装，也不能为绕过 task 权限把工具执行塞入 conversation profile。

插件清单是贡献定义来源，daemon 激活注册表是当前可用性来源，UI 只读取其投影。安装清单、模型工具目录和前端菜单不能各自计算不同的启用状态。

插件可以按最小形态组合贡献：仅 Skill、仅 MCP 服务、Skill 加 MCP 服务，或在前述形态上增加 UI 和生命周期事件。没有必要的 UI 不得生成空面板；有 UI 的插件仍须让工具和结构化结果在无 UI 时可用。MCP 工具返回的结构化结果由 daemon 保留并投影给模型和界面，插件不能通过隐藏文本协议维护第二份结果事实。

## 5. 运行架构和所有权

```text
插件中心 / 指定地址 / 本地包
                 │
                 ▼
       daemon 插件管理服务
       校验 → 安装 → 激活 → 释放
                 │
          贡献与实例注册表
          ┌──────┴──────────────┐
          ▼                     ▼
 daemon 管理的扩展执行宿主     UI 贡献投影
          │                     │
       受控 SDK              现有工作台壳
          │                     │
 Magi 原生执行/存储/浏览器服务  隔离插件视图
          ▲                     │
          └────受控请求与事件─────┘
```

上述服务是责任划分，具体 crate 拆分随实现确定，不据此另建会话或任务内核。

| 状态或行为 | 唯一所有者 |
| --- | --- |
| 安装版本、来源、摘要、启用范围、授权、激活状态 | daemon 插件管理服务 |
| 插件实例、调用身份、进程和资源租约 | daemon 扩展宿主管理器 |
| Session、Turn、任务树、审批、工具审计 | 现有 daemon 领域服务 |
| 工作流下一步决策 | 本次运行固定的工作流实现 |
| 工作流检查点与待执行动作记录 | 现有任务持久化边界下的扩展数据 |
| 插件配置与私有持久数据 | daemon 提供的插件命名空间存储；插件定义内容语义 |
| 领域资源语义和操作规则 | 插件资源服务；不得存另一套 Magi 任务状态 |
| 文件或远端资源的原始内容 | 声明的文件/远端系统；插件缓存是派生数据 |
| 页面缩放、选中、滚动等瞬时展示状态 | 视图实例；业务编辑通过资源操作提交 |
| 右栏布局、活动 Tab、窗口焦点 | 现有工作台与桌面宿主 |
| 逻辑浏览器与物理页面 | 现有 BrowserAuthority 与 Electron Main |

### 5.1 执行环境

建议第一版只公开一种面向 JavaScript/TypeScript 作者的 SDK，发布产物遵循第 4.1 节选定的唯一后台格式。作者语言与发布格式分别定义，不能因为都使用 TypeScript 就认为构建链和加载协议相同。执行逻辑由 daemon 管理的隔离扩展宿主承载，不能运行在可信 App Renderer 或任意取得 Electron Main 对象。

执行环境不提供任意 Node.js、文件、网络和进程 API；插件通过宿主 SDK 请求这些能力。限制必须由选定的执行引擎和宿主边界强制执行，不能只靠约定插件使用 SDK，也不能把“独立进程”宣称为沙箱。

执行基线选定 QuickJS（Rust 绑定 `rquickjs = 0.14.0`）和 daemon 管理的独立受管 Worker，每次调用创建独立引擎实例。作者将 TypeScript/JavaScript 构建为第 4.1 节规定的 ESM bundle；SDK 不承诺 Node.js、DOM 或未注册的原生模块能力。Worker 的默认导出接收输入与宿主 SDK，返回 JSON 或可结算的 Promise；跨调用状态通过宿主检查点/命名空间存储传递，不能依赖 JavaScript 全局变量保活。调用模型、工具等业务请求必须经过原生服务；这个执行边界不拥有业务状态。

限制由 QuickJS 的内存/栈上限和中断回调、宿主请求/响应与能力调用数量上限、覆盖排队和 SDK 等待的期限与取消、以及现有 `magi-process` 进程结算共同执行。SDK 能力处理器须传播取消，不能在请求 future 被丢弃后留下脱离原生运行记录的副作用。

Worker 已接入开发/发行构建、Desktop 资源哈希、许可证收集及解包后的实际 preflight，维护入口见 [`magi-plugin-runtime`](../crates/magi-plugin-runtime/README.md)。Windows 实际执行、三平台正式安装器及业务 SDK 权限/取消结算仍需对应源码与构建的验证证据；运行时 preflight 不代替插件授权与激活，也不能用不受限 Node.js 兜底。历史选型实验与一次性制品结果通过 Git/CI 追溯。

**Worker 进程级限制。** QuickJS 逃逸或引擎漏洞不应直接获得 daemon 用户的全部权限。受管 Worker 在读取任何调用报文之前对自身施加不可撤销的操作系统级限制，失败则拒绝执行：macOS 使用 `sandbox_init` 默认拒绝的 profile，Linux 使用 `no_new_privs` 加 seccomp 系统调用白名单（架构不符直接终止进程）。两者都禁止打开新文件、写入、联网和派生/替换进程，Worker 只通过已建立的 stdio 与 daemon 交互。`magi-plugin-worker --sandbox-selftest` 在施加限制后逐项尝试读文件、写文件、建目录、联网和启动进程，并要求全部失败；该自检进入 macOS/Linux CI 与 Desktop 发行校验。**Windows 的 Worker 级 OS 限制按下文取舍不实现**，自检如实报告 `enforced=false`，daemon 侧 Job Object 只管理进程生命周期；Windows 实际执行与安装器仍需对应验证，不得表述为已隔离。

**Windows 的取舍（已定案）。** Windows 上 Worker 不施加操作系统级沙箱，第三方插件照常运行：防护只剩 JS 层不暴露文件/网络/进程 API，加上超时、内存、报文与调用次数上限，以及授权、作用域和资源版本检查。已接受的风险是——QuickJS 若出现可被利用的引擎漏洞，恶意插件在 Windows 上没有进程级兜底。接受的理由是该场景需要“用户安装了恶意第三方插件，且插件利用了引擎漏洞”，而 Magi 开源、安装前展示来源与权限、不提供静默升级，实际暴露面有限。这一取舍不改变事实陈述：Windows 的自检仍报告 `enforced=false`，文档与界面不得把 Windows 表述为已隔离；若将来补齐（Job Object 禁止派生加受限令牌/AppContainer 禁止文件与网络），再翻转 `ENFORCED`。

原生可执行扩展另有操作系统级权限边界，首期不默认开放。已有原生 MCP/进程能力保持当前授权语义；未来开放插件自带程序时，应明确其宿主权限和生命周期，不能承诺 JavaScript 隔离自动覆盖子进程。

### 5.2 权限与调用身份

新操作仅在插件已启用且实例就绪时准入；已接纳运行在排空期间凭宿主签发的有效运行租约继续，不能因此接纳新运行。两者都必须通过当前有效权限校验。有效权限由插件声明、用户授权、工作区策略和本次调用上下文共同限制。插件声明权限不等于获得权限，插件中心来源也不等于信任。启用状态由 daemon 执行校验，隐藏界面入口不能代替拒绝请求。

宿主为每次请求绑定插件实例、版本、工作区、资源和调用 ID；涉及任务时补充 Session、Turn、TaskRun、attempt。身份来自注册和连接绑定，不能信任插件自行填入的工作区或任务 ID。

UI 操作和模型工具操作进入同一应用服务方法及权限入口。只读页面查询不必虚构 Turn；涉及模型、工具或长任务时仍进入对应原生执行服务。插件不能自行批准审批或发布工具成功事件。

权限被撤销时失效涉及该权限的 SDK 句柄、订阅和租约，实例被销毁时失效该实例全部句柄，停止相应后续调用；对已发生的外部副作用记录实际结果，不声称取消可以撤销一切。

### 5.3 全局生效（已定案）

**插件是全局的：** 安装版本属于用户，启用、授权、激活和数据都只有一份，对所有工作区一致；不存在“按工作区启用”或“按工作区授权”，界面上也只有一个启用开关。这样用户装一次、授权一次就能在任何工作区使用，也避免“某个工作区忘了启用”这类难以排查的状态。daemon 内部仍用一个固定的作用域键 `application` 标识这唯一的一份（API 的 `scope` 字段只接受它，工作区键一律拒绝），生命周期、排空、资源版本都按它记录。权限声明里的 `scope`（`application` 或 `workspace`）表示权限覆盖的对象类型，与启用范围无关；授权时按清单声明一次性授予。每次请求仍重新校验当前授权，调用上下文里的工作区身份由宿主签发，插件无法自报。

停用、禁用、升级和卸载针对整个插件：停用等待在途运行结算（第 8.2 节），升级与卸载必须先完成同样的排空。

宿主维护共享资源的使用租约；插件实例、视图、运行和资源租约分别管理生命周期。单次运行取消只撤销该运行的调用句柄和租约，不能直接销毁仍服务其他运行的共享实例。最后一个合法使用者释放后，按资源合同停止实例或后台资源；持久配置和登录数据不因资源停止而自动删除。

## 6. 界面扩展与数据同步

### 6.1 设置、主页和右侧面板

- 有设置贡献的插件自动显示对应设置 Tab；没有配置项的插件只需要插件管理详情，避免生成空页面。
- 主页允许注册功能入口和显式声明的卡片；完整页面在主内容区打开，不任意替换整个工作台。
- 右侧面板沿用公共 Tab 栏、宽度、折叠、关闭和焦点管理。只新增通用插件内容承载类型，不为每个插件增加专用分支。
- 视图身份至少包含插件、贡献和实例键。同一资源可复用已有视图。
- 开启某个插件不代表强制打开全部页面；入口出现与面板打开分别管理。

普通配置由 schema 生成表单，复杂页面使用隔离的 Web 视图。两种展示共用设置读取和保存服务，不形成两套配置写入路径。

### 6.2 隔离视图

自定义 UI 使用带 `sandbox="allow-scripts"` 的独立 iframe，加载插件包内静态资源，允许其自行选择界面框架和图形渲染方式。该 sandbox 使文档使用 opaque `null` origin，因此宿主向 iframe 发送消息时使用 `targetOrigin="*"`，同时严格绑定精确 `contentWindow`、实例代次和一次性通道身份；宿主接收消息仍校验 origin（资源 origin 或 `null`）、frame、实例代次、操作类型和载荷大小。插件不能访问父页面 DOM、daemon 凭据或 Electron preload；网络和敏感操作经受控消息桥处理。

宿主校验消息来源、frame、实例代次、操作类型和载荷大小；视图重建后旧通道立即失效。外链导航、下载和弹窗由宿主规则处理。主题、语言、尺寸和可访问性信息作为只读宿主参数提供。

**宿主响应约束。** 视图资源由 `/api/plugins/{id}/ui/{path}` 仅在插件已激活时提供，并带固定响应头：`default-src 'none'`、`connect-src 'none'`、`object-src 'none'`、`base-uri 'none'`、`form-action 'none'`、`frame-ancestors 'self'`，脚本与样式仅允许同源和内联，图片与字体允许同源及 `data:`，另设 `nosniff`。视图不能直接发起网络请求，所有数据经消息桥。保留 `unsafe-inline` 是因为打包后的单文件视图依赖内联脚本，其风险由 `sandbox="allow-scripts"` 与 `connect-src 'none'` 约束；是否收紧为 nonce/hash 随消息桥 schema 一起定案。

这种视图承载插件 UI，不替代内置浏览器。需要真实网页登录或浏览器自动化的贡献申请原生 Browser surface，由现有 BrowserAuthority/Main 管理；不允许插件自行创建第二套 Chromium guest 管理器。

**原生 Browser surface 贡献。** 该贡献为 GPT Web 这类需要原生登录页的功能声明挂载意愿（§9 定案其实现留在 Magi 内部）。合同已进入 App Server schema 的 `contributions.browserSurfaces`（`id/title/description/scope/persistence/keepMounted/closeAction/backgroundInference`），清单校验要求每个 surface 有同作用域、同目标的 `browser` 权限，应用级 surface 需声明应用级实例，后台推理要求保持挂载。声明项含义如下：

| 声明项 | 含义 |
| --- | --- |
| 作用域 | 目前只支持 `application`：用户级唯一实例 |
| 持久性 | 持久分区或临时分区；Cookie 与秘密始终由 Main 保管，插件只拿到资源引用 |
| 挂载策略 | 是否在折叠右栏时保持 guest 挂载；关闭按钮是隐藏视图还是销毁 surface |
| 后台推理 | 视图不可见时关联运行是否继续 |
| 所属租约 | surface 绑定的资源租约与禁用/卸载时的释放顺序 |

这些声明只表达意愿，挂载、权限和释放由 BrowserAuthority 与 Main 执行；右栏公共壳只维护布局。**当前实现：** 宿主只实现了一种语义——应用级唯一实例、持久分区、保持挂载、关闭只隐藏；其他合法组合在激活时被明确拒绝（`宿主尚不支持…`），不会接纳后静默按此语义运行。GPT Web 第一方清单已声明 `gpt-web` surface，右栏入口由该声明驱动。通用 surface 宿主（让第三方插件挂载自己的原生登录页）未实现，也不是 GPT Web 的前置条件。

### 6.3 唯一资源状态与同步

每个可同步资源必须声明唯一权威来源：插件管理的数据、工作区文件或外部系统之一。不能同时把插件内存、文件和面板副本都当作可独立提交的事实源。

资源键由 `pluginId + scope + resourceId` 组成，scope 固定为 `application`；每个资源独立校验版本，数据对所有工作区共享。

```text
用户界面操作 / 模型工具调用
              ↓
    同一资源操作服务与权限检查
              ↓
      校验版本 → 提交变更
              ↓
   发布已提交版本 → 更新订阅视图
```

同步合同：

1. 打开视图获取快照和订阅游标；使用可重放订阅或原子的快照边界，防止快照与订阅之间漏变更。
2. 更新携带资源 ID、版本和必要的变更内容；丢失增量时重新读取同一权威快照，不能用旧 UI 状态补写业务数据。
3. 操作携带预期版本；遇到并发修改明确返回冲突，不以最后到达者无条件覆盖。
4. 文件监听和远端推送属于该资源服务的输入。文件读取需验证一致性；远端没有版本时使用服务生成的观察序号，并说明刷新语义。
5. 大资源通过授权资源句柄按需读取，不将完整数据不断写入聊天事件或模型上下文。
6. 长计算返回带输入版本的结果；过期结果不得覆盖最新资源。预览草稿明确标识，不能当作已保存版本。
7. 关闭面板释放视图订阅，不自动结束任务；资源服务仅在有活动任务、订阅或获准后台活动时保活。

视图选中内容可以形成结构化上下文引用，包括插件、资源、版本、选中对象和简短摘要。用户发送或工作流请求时，经现有上下文组装与预算规则纳入模型输入；不将整个页面 DOM 隐式注入对话。

## 7. 可替换的工作流核心

### 7.1 决策与执行分工

工作流核心可决定下一步模型请求、工具操作、子任务、阶段推进、重试、等待用户及完成条件。Magi 继续负责接纳、授权、真实执行、调度、取消、预算、上下文压缩、持久化和终态校验。

```text
现有 Turn 接纳与 TaskRun 创建
              ↓
     固定的工作流核心实例
              ↓
    提交动作意图和阶段状态
              ↓
     原生执行服务校验与执行
              ↓
   真实结果持久化并反馈给核心
```

模型请求的分工按“工作流决定说什么、Magi 决定能装多少”划分，使自定义核心能够替换提示策略，而不是只能在固定提示下切换阶段：

| 工作流核心提交 | Magi 宿主负责 |
| --- | --- |
| 请求意图与目标模型/角色选择（限已授权范围） | 解析目标、校验授权，拒绝超出范围的选择 |
| 系统指令段与阶段说明文本 | 与工作区规则、安全约束和原生必需指令合并，原生段不可被覆盖或移除 |
| 显式上下文引用：历史范围、文件、资源快照、视图选中内容 | 按[上下文压力与压缩架构](context-pressure-compaction-architecture.md)装配、压缩和裁剪，预算裁决只属于 Magi |
| 本次请求暴露给模型的工具子集 | 只允许在已授权工具目录内收窄，不允许扩张；执行仍经原有治理入口 |
| 预算与优先级提示 | 作为输入参考，不作为必须满足的指令 |
| 对装配结果的后续决策 | 返回装配摘要：实际纳入与被压缩的引用、消耗预算，供核心决定下一步 |

工作流不能提交绕过装配的原始消息体，也不能直接改写 canonical 历史；默认工作流也只通过这套输入表达现有提示策略，原生实现与插件实现没有第二条装配路径。

默认工作流也实现同一合同。当前运行只有一个编排负责人；插件失败时明确进入失败或等待恢复，不能静默调用默认核心继续执行。

工作流可组合子流程，但父子关系、运行身份和责任必须显式记录。安装多个工作流不表示同时拦截所有运行。事件观察插件只能观察事实，不能通过隐藏回调获得第二个编排入口。

### 7.2 选择与固定

- 新运行选择顺序建议为：本次显式选择 → 工作区默认 → 用户默认 → 内置默认。
- 显式选择的核心不可用时拒绝启动；不能把“不可用”当作“未设置”继续查找默认值。
- 启动时固定插件 ID、贡献 ID、精确版本、包摘要、配置快照和检查点格式版本。
- 用户修改默认项只影响新运行；已开始和待恢复的运行不切换版本。
- 子任务是否使用子流程由负责人显式声明，仍进入原有 TaskStore 与调度服务。

### 7.3 动作与恢复合同

工作流返回类型化动作，例如模型请求、工具调用、派发/等待子任务、等待用户、保存阶段、申请完成。不是返回可以直接改写 daemon 状态的任意代码。

每个动作带运行内唯一动作 ID。宿主在本次 lease 下签发 `attemptId:step`，插件只能原样回传；宿主将动作意图和检查点在现有任务持久化边界内关联保存，再执行副作用并记录结果。恢复时依据动作状态与原生执行记录决定继续位置，未知副作用直接进入恢复阻塞，不能只重放插件的内存代码。

只有可证明未执行或本身幂等的动作可以自动重试。外部写入结果未知时保留“结果未确认”并要求核对；不能宣称跨进程、跨远端系统天然实现 exactly-once。

取消沿原生取消链传播到模型、工具、子任务和该运行的扩展调用上下文，按第 5.3 节释放其租约；迟到回调按 attempt/实例代次拒绝。工作流只申请完成，TaskStore 与 Coordinator 仍按当前合同提交各自终态。

缺少固定版本、检查点格式不匹配或权限已撤销时，明确说明恢复阻塞原因。不能将旧检查点交给新版本或默认核心猜测执行。

## 8. 安装、版本和生命周期

### 8.1 统一安装流程

```text
来源解析 → 获取发布包 → 校验身份/摘要/契约/平台
       → 展示能力与授权 → 写入不可变版本目录
       → 记录已安装 → 用户启用 → 激活贡献
```

插件中心提供包元数据和发布地址；指定地址应指向 Magi 发布清单或插件包。本地开发目录走显式开发加载命令，不把任意 Git 源码地址解释成可在用户机器上执行的构建脚本。支持 Git 托管发布时，也只解析为同样的发布包。

解包检查路径穿越、符号链接逃逸、压缩大小和资源上限。摘要用于内容一致性，不等同作者身份认证；市场签名和私有来源的信任规则在发布协议确定时明确。

**首版信任底线**（签名是可选增强）：安装界面展示来源、摘要和声明的全部权限；授权绑定到具体摘要；同一插件 ID 更换来源按新插件处理，不继承原授权；指定地址安装的插件在界面上与插件中心来源区分标识；不提供静默自动升级。官方来源信任与第三方可选签名见下文，不能削弱上述底线。

**当前实现：** 来源分为插件中心、指定地址、本地包和内置包四类。插件中心的使用门槛只有一个目录地址：用户填入地址即可浏览和安装，与添加 Skill 一样。目录可以是普通 JSON，也可以是 Ed25519 签名信封（签名覆盖 `payload` 原始字节，不依赖 JSON 规范化）；条目把发布 ZIP 的 SHA-256 摘要绑定到目录上，包地址可以是相对目录自身的路径，下载内容与摘要、插件 ID、版本任一不一致都拒绝安装。**受信公钥是可选的高级项**：不配置时目录按“指定地址”的信任级别对待——界面标注未签名，安装后的来源记为指定地址，与已验证的插件中心来源区分；配置后只接受该密钥签名的目录，未签名或验签失败的目录不展示任何条目，通过验签的才记为插件中心来源。两种情况下安装都不会激活，权限仍须用户逐作用域授权。指定地址与本地包不经目录，界面单独标识来源。第一方插件 ID（目前为 `openai.chatgpt-web` 与 `magi.mcp-server`）只接受内置包来源，安装与升级时由 `PluginManager` 校验，外部包不能占用该身份而获得原生宿主能力；新增第一方插件须同时登记其 ID。**官方插件中心已定案：** 就是 Magi 仓库的 `plugin-center/` 文件夹，经 GitHub 提供（默认地址 `raw.githubusercontent.com/MistRipple/magi-code/main/plugin-center/catalog.json`，开发验收可用环境变量 `MAGI_PLUGIN_CENTER_DEFAULT_URL` 覆盖）。从未配置或清空地址时使用它；来自官方地址（且未配置公钥）的目录信任来自 Magi 仓库本身，按插件中心来源对待，其余未验证目录按指定地址对待。上架即向仓库提交 PR，代码审查承担审核，不另建托管服务、官方密钥或作者身份体系；`scripts/build-plugin-center.mjs` 生成发布包与目录，CI 的 `plugin-center:check` 保证提交内容与源码一致。发布工具 `scripts/plugin-center.mjs` 同样支持第三方无密钥自托管与可选签名。

安装管理只有 daemon 一个写入入口，UI 和未来 CLI 都是调用方。操作按插件串行化，使用操作 ID 跟踪取消、失败和重连结果。下载暂存目录不等于已安装；校验完成后原子提交安装记录。

升级和卸载先提交新的安装事实，再清理不再引用的版本包；卸载时先把包移入待删除暂存位置，状态提交失败则移回原位，不留下“状态仍引用、文件已丢失”的安装；清理中断不会留下被状态引用的半包，daemon 重启时会按当前状态回收未引用的 ZIP 和暂存文件。清理失败必须返回失败状态，不能把逻辑状态已提交误报为完整清理成功。

### 8.2 状态与退出语义

包状态与运行实例状态分别记录，不能用一个 enabled 布尔值代替真实状态：

- 包：未安装、安装中、已安装、更新中、移除中、操作失败。
- 实例：禁用、激活中、就绪、排空中、停止、激活失败/崩溃。
- 设置中的启用意愿与实际就绪状态并列展示，失败不能显示为可用。

| 操作 | 规定行为 |
| --- | --- |
| 激活 | 校验依赖和权限，准备实例，统一发布可用贡献；失败释放本次资源 |
| 禁用 | 立即拒绝新运行和独立操作；已接纳运行按下述排空或取消合同结束，完成释放后才显示已禁用 |
| 升级 | 新包独立校验并比较权限；按第 8.3 节排空后切换，不热替换活动执行代码 |
| 卸载 | 有活动运行、恢复引用或资源租约时阻止直接删除，完成释放后再移除代码 |
| 崩溃 | 撤销该实例能力句柄和就绪状态，保留真实执行事实，不自动重放未知副作用 |
| 数据处理 | 卸载代码默认保留用户配置和数据；清除数据使用独立的显式操作 |

禁用的准入关闭与运行接纳必须由同一宿主控制边界排序，明确哪些运行在关闭之前已被接纳，不能由 UI 时间或插件自报状态判断。

- **排空**：关闭新运行、独立命令、资源编辑和后台作业的准入。已有运行保留宿主签发的运行租约，可在原范围、预算和当前有效权限内继续请求模型、工具和必要子任务；宿主验证这些请求属于该运行及其子树，不能借用租约启动无关工作。回答该运行待处理的问题、审批、取消和读取状态仍可用。
- **排空结束**：已有运行及其子树、在途调用均完成结算后撤销租约，停止相关订阅与后台活动，释放该作用域的资源。排空采用明确展示的有限期限，到期进入取消流程，不能无限等待插件自行退出；具体期限在生命周期 schema 中定义。
- **取消**：不再允许推进该运行的新动作，立即传播取消并失效其调用句柄。结果接收、审计和宿主资源释放仍要完成；未知副作用保留未确认状态，不能伪装成功或已撤销。
- **权限撤销**：优先于排空租约，被撤销能力立即失效。依赖它的运行进入取消或明确的恢复阻塞状态，不能以“已接纳”为由继续使用旧授权。
- **管理可见性**：功能入口停止接纳新工作，但原生插件管理和运行状态入口始终可见，显示阻塞原因、剩余运行及取消动作；不能隐藏后让用户无法处理排空。

**当前实现与目标的差距。** 运行租约是 daemon 进程内的登记（`PluginRuntimeLease`），不持久化，登记该调用的取消信号，也不校验请求是否属于该运行子树。停用与升级共用同一排空流程（`PluginManager::settle_runtime_leases`）：先关闭准入并登记排空开始时间，再等待租约清零；30 秒排空期到期后统一取消排空范围内的在途调用，再给 10 秒结算窗口。取消只是通知，租约仍由调用自身结算后释放；窗口内仍未结算则返回冲突并保留激活状态。排空期限常量属于 `magi-plugin-system`，并经 `GET /api/plugins` 的 `lifecycle` 字段与各作用域的 `draining`（阶段与截止时间）投影给界面，设置页据此倒计时；期限尚未进入清单级 schema。排空期间 UI/HTTP 的资源与设置编辑被拒绝（`ensure_editing_admitted`），在途运行经 SDK 的写入仍受租约与固定身份约束；撤销授权立即取消该范围的在途调用。租约不持久化是有意的：Worker 随 daemon 进程存在，重启后没有在途调用可恢复，恢复语义由 TaskStore 的工作流检查点承担；调用身份由宿主在发起时签发，插件无法自报运行或子任务，因此不需要再做事后的子树校验。

为恢复保留固定版本制品不表示同时启动多套实现。第一版采用排空后切换，不开放同一插件多版本并发激活。旧版本恢复引用只有在运行完成或用户明确放弃恢复后才可解除；不能为升级自动删除检查点或将其交给新版。

### 8.3 升级授权与一致切换

> **当前实现：** `PluginManager::upgrade` 要求调用方持有覆盖该插件的升级排空标记（`begin_upgrade_drain`），`POST /api/plugins/upgrade` 与内置包升级共用同一流程：关闭准入、等待或取消在途运行、原子切换。切换后保留各作用域的启用意愿，但清空激活与授权——授权绑定摘要，新包须重新授权后激活。数据格式版本变化时：插件还没有任何持久数据则无需转换、直接切换；已有数据则新版清单必须声明 `dataMigration.fromVersions`，否则拒绝（不做静默兼容）。**转换执行者已定案**：新版插件自己的后台入口，在受 OS 沙箱限制的同一 Worker 中逐条执行（`contribution = {kind:"migration", id:"data"}`），宿主不开放任何 SDK 能力，转换是只读输入、返回结果的纯函数，因此不可能获得模型、网络、进程或资源写入能力。准备阶段已实现：`POST /api/plugins/preview` 校验候选包并返回与已安装版本的版本、权限新增/移除、数据格式变化（已有数据时标记阻塞），不写入任何状态；设置页展示确认面板，确认后的安装/升级请求携带预览摘要（`expectedDigest`），来源内容与预览不一致时被拒绝（409）。转换结果由宿主校验（单条 ≤4MiB、设置符合新版 schema、保留的资源须在新版声明、与转换前数据的逐条版本核对）后写入暂存区，并登记可恢复的升级操作记录；包切换（`state.json` 提交）是唯一提交点：启动恢复时若已安装摘要等于目标摘要则重放暂存数据（幂等），否则丢弃暂存，提交后暂存数据未应用前拒绝激活。候选包不单独持久化——确认请求重新取得包并以预览摘要核对，来源内容变化即作废，这满足“准备不改变现有版本、授权绑定摘要”的要求。

升级分为准备与切换两个阶段，由同一插件管理服务串行执行，使用可恢复的操作记录。准备候选包不激活其工具、视图或后台活动；用户授权且开始切换前，现有版本可以保持运行，界面必须区分“候选包已下载”和“升级已完成”。

1. **校验来源和权限变化**：核对插件身份、来源、摘要、契约、产物格式和平台。比较新增权限、文件范围、网络目标及原生能力；任何扩张必须重新授权，不因 ID 相同自动继承。拒绝或尚未授权时不开始切换，现有版本与数据保持原状。
2. **关闭准入并排空**：切换覆盖该插件的全局实例。按第 8.2 节停止接纳新工作、完成或取消已有运行，处理恢复引用，释放旧实例及资源；条件未满足时明确等待，不能同时启用新版。
3. **准备数据版本**：旧写入者停止后，在隔离的暂存数据版本上进行一次性转换和校验。转换只允许读旧数据、写暂存数据，不开放模型、网络、进程或其他业务副作用。原数据保留作失败诊断依据；暂存数据不是第二份可被业务使用的事实源，不参与双写。
4. **准备激活**：检查新版入口、依赖和资源可用性，在不对外开放调用、不执行业务副作用的阶段完成准备。以唯一持久记录绑定包版本/摘要、数据版本、配置版本及已核准的授权；校验期间权限发生变化时重新校验，不能用过期批准覆盖撤销。
5. **提交并开放**：原子提交上述绑定，随后按该记录发布贡献和开放准入。只有新版实际就绪才标记升级成功；就绪状态和可调用性由 daemon 统一投影，不能以安装或数据转换成功代替激活成功。
6. **处理失败与重启**：切换开始后的转换、准备或激活失败均关闭该插件准入，撤销未完成注册，显示升级失败及具体阶段，不自动重启旧实现。操作记录区分提交前后：提交前暂存数据不可见；提交后只使用已提交绑定。重启按该记录恢复至确定的准备/未就绪状态，不混用新代码与旧数据，也不重放未知外部副作用。修复重试沿同一升级操作推进，不增加回退执行分支。

**失败语义的实现取舍。** 实现把转换、校验和暂存全部放在唯一提交点（`state.json` 切换）之前：提交前任何一步失败（转换报错、结果校验不过、暂存写入失败、转换期间数据变化），旧版本、旧数据和旧激活都保持原状，排空标记随调用结束自动撤销、准入恢复——此时没有“半切换”状态，关闭准入并拒绝旧实现反而是不必要的降级。提交之后只剩“应用暂存数据”一步：失败则保留操作记录并拒绝激活，由重试或重启恢复；任何时刻都不会出现新代码读到旧格式数据，也不会自动回退到旧实现。

同范围权限是否继续适用必须依据来源身份和现有授权规则校验；来源身份改变不能仅凭同名插件复用授权。切换后只写新数据格式；旧制品及数据在无恢复引用、升级操作结束且符合保留策略后回收，不保留长期双读双写或自动回退逻辑。

## 9. GPT Web 的插件化边界

GPT Web 是已存在的功能，目标是用户按需安装。**已定案的终态：功能代码保留在 Magi 内部，插件只是它的“壳”**——第一方清单承载安装、权限授权、作用域激活、入口开关和引擎/surface 声明；用户安装并激活这个壳，GPT Web 才对外可用，不安装则入口、引擎、通道、页面和进程都不出现。原生浏览器、MCP 服务和通用会话执行能力不随其卸载。

选择这个终态的理由：站点驱动、单槽位、Tunnel 与原生 Browser surface 都是受保护宿主资源，把它们改写成 Worker 里的 JS 需要先设计浏览器驱动、长时引擎调用和插件承载原生视图三类新的 SDK 权限面，成本和回归风险远大于收益，而“按需安装”的产品目标用壳已经完全达到。因此**不再计划**把站点逻辑迁成插件包内的 JS，也不再以“删除 `webSession` 专用 kind 和站点专用组件”为完成条件；这些实现作为宿主内部模块维护，只受下述门控约束。

**门控约束（验收口径）。** GPT Web 原生宿主适配器是特权路径，不是通用插件 Worker，其门控由 daemon 统一执行：
- 所有 GPT Web 接口（探测、页面、槽位、通道、引擎调用）要求第一方插件已激活（全局，无需按工作区启用）；UI 隐藏入口不能替代 daemon 准入。
- 未激活或未安装时：不注册引擎、不构造会话、不启动 Tunnel 和槽位端点、不物化页面；daemon 启动不会因持久配置而恢复任何资源。
- 停用、升级、卸载按 §8.2/§8.3 排空并核实释放宿主资源，释放失败不报告完成。
- 第一方插件 ID 只接受内置包来源，外部包不能占用该身份而获得原生宿主能力。
- 二进制随 Magi 发布，“未安装时不启动其功能逻辑”指运行时行为而非二进制内容，验收时据实说明。

下表是壳与内部模块的职责划分：

| Magi 内部模块（GPT Web 全部站点逻辑在此） | 插件壳负责 |
| --- | --- |
| BrowserAuthority、Main guest 生命周期与浏览器权限 | 清单声明、摘要与来源、权限授权（模型、浏览器） |
| 站点识别、页面驱动、就绪探测、对话模式、远端对话引用与结果解析 | 启用/激活/停用及排空 |
| GPT Web 设置、右栏视图、主页入口与会话界面 | 入口与引擎的出现与否（由激活投影决定） |
| Turn 接纳、流式事实、取消和持久化 | `gpt-web` 原生 Browser surface 的声明 |
| MCP 服务、工具授权与审计、OpenAI Tunnel 托管与槽位端点 | 引擎命名空间 `plugin/openai.chatgpt-web/*` 的占用 |

Tunnel 是独立外部程序，按第 4.1 节首期不开放插件自带程序，其进程托管属于原生受控资源服务（`magi-web-model::tunnel`）。卸载后保留的是原生托管能力，不是插件启动的连接、进程或端点；插件不得自行拉起厂商 CLI。通道只服务 GPT Web 的应用级实例，随它的激活而启动、随它的停用而释放；凭据文件路径和校验规则仍只在原生层处理。若将来出现第二个需要 Tunnel 的使用者，再抽出租约登记，现在不预先建设。该边界不得放松第 4.1 节对包内原生可执行程序的禁止。

**当前实现（Tunnel 托管语义）：**应用级停用、升级提交和“停止/重置”都先释放页面与槽位，再停止 Tunnel，并以本机运行时清单**核实**运行时确已消失（`runtimes stop` 的退出码不是唯一依据：命令失败但清单已无该别名视为已释放，命令成功但清单仍显示运行则未释放）；核实失败时保留跟踪与槽位端点、状态为 `stop_failed`，生命周期操作返回冲突而不是报告完成，再次停用可重试，待清理期间拒绝卸载。daemon 启动与插件应用级激活共用 `restore_configured_channel`：只有插件已激活才按已保存的凭据引用恢复通道，持久配置不会让已禁用的插件资源在重启后复活。

禁用或卸载进入资源释放阶段时，宿主释放 Tunnel 租约和连接；实例崩溃时释放该实例全部租约，并失效对应槽位身份与请求通道。没有其他合法使用者时停止 Tunnel 进程及其托管的 relay 子进程；若进程仍被其他合法使用者持有，只撤销当前租约及其专属端点，不能误停仍有合法使用者的进程。共享仅限连接配置与身份边界允许共享的资源，不因进程相同复用工作区授权。停止失败时保留待清理状态和进程跟踪，拒绝新调用，不报告资源释放或卸载完成；只有实际释放后才能完成生命周期操作。

包仍安装但已禁用时同样不保活 Tunnel。持久配置、Cookie 和凭据引用遵循数据保留规则，不自动删去，也不能据此在应用重启后重新启动已禁用的插件资源。

站点槽位语义可由插件声明，但租约占用、身份绑定和权限由 daemon 的受控资源服务执行，不能让插件页面自行维护另一张有效占用表。

GPT Web 插件声明应用级能力：登录态、Cookie、单槽位和会话视图属于用户级唯一实例。插件的全局激活状态既决定功能入口、设置 Tab 和引擎选项，也是 daemon 的调用准入；未激活时即使持有旧界面或请求句柄，也不能发起占用、发送消息或执行插件操作。停用进行中只允许第 8.2 节规定的排空续调和原生管理操作。

需要 BrowserAuthority 或其他受保护宿主资源的插件引擎，通过 daemon 的原生插件引擎注册表接入同一 `SessionEngineFactory` 合同；注册表占用明确的插件命名空间，通用插件 Worker 在该命名空间内不再接纳包内实现。这样宿主适配器与普通插件可以共用会话引擎路由，但一个引擎身份始终只有一个负责人。

槽位语义沿用 [GPT Web 开发基线](web-model-browser-development.md) 的 W4 与 W17：拥有者是一个 Magi 会话，工具的工作区范围在槽位建立时取自拥有者会话的项目，槽位释放即失效；被占用时一律拒绝，不提供排队或接管。多个工作区同时启用时，槽位仍只有 daemon 资源服务维护的一份占用表，非拥有者会话在授权范围内只读查看当前拥有者，不按工作区复制槽位或实例。

停用或卸载时，先按排空或取消合同结算当前 Web turn，禁止后续新 turn，完成结算后释放槽位、应用级宿主、guest 和 Tunnel 租约。只保留 Cookie 等持久数据，不保留可继续执行的活动绑定。

现有应用级原生浏览器 surface 通过统一贡献引用挂载，插件不能另建 iframe 登录页替代现有登录分区。Cookie 与秘密继续由受控宿主保存，插件拿到的是可授权使用的资源引用。

`webSession` 作为右栏的显式例外继续存在，语义见[浏览器架构](browser-runtime-design.md) §4.3：应用级宿主全程挂载、折叠右栏不卸载 guest、关闭按钮只隐藏视图、推理在视图不可见时继续、登录态使用持久分区。第 6.2 节的 `gpt-web` Browser surface 声明与这组语义一致，右栏入口由声明驱动；其他合法的 surface 语义组合在激活时被明确拒绝，不会静默按此语义运行。GPT Web 的临时/已保存模式、单槽位、上下文方向和取消恢复语义不变，仍由 [GPT Web 开发基线](web-model-browser-development.md) 定义。

既有历史记录仍可由原生读取模型展示；缺少插件时明确显示该引擎不可运行，不将历史记录转换成本地模型对话。不为旧版本保留导入或兼容分支，只维护当前一份配置。

## 11. 最小充分验收

仅维护核心合同回归与少量真实集成验收，不为每种插件复制完整测试套件。

| 验收点 | 必须证明 |
| --- | --- |
| 安装一致性 | 中心、地址、本地包进入同一服务；失败包不激活，取消不留下可用的半安装版本 |
| 唯一入口 | UI 与模型操作进入同一权限和资源操作服务，没有另一条配置或业务写入路径 |
| 隔离与权限 | 插件无法冒充其他工作区/实例、直接访问可信桥或绕过声明权限 |
| 全局准入 | 未激活时通过旧视图或直接 API 调用被拒绝；工作区作用域键被拒绝；激活后所有工作区一致可用 |
| 排空与取消 | 准入关闭前后的接纳边界确定；已有运行可按租约继续必要调用，新工作被拒绝；撤权立即生效，排空超时进入取消 |
| 升级一致性 | 新增权限未授权不切换；升级排空；转换、提交、激活各阶段失败和重启不产生版本/数据错配，也不自动启动旧实现 |
| 执行产物 | 正式包只接受选定后台格式，拒绝未选格式与宿主原生程序；视图脚本不能作为后台入口 |
| 最小插件形态 | 仅 Skill、仅 MCP、Skill 加 MCP 和带 UI 的组合均能按声明激活；没有 UI 时工具和结构化结果仍可用，不生成空面板 |
| Skill/MCP 边界 | Skill 只提供工作流说明和资源；MCP/工具负责 schema、授权和副作用；Skill 不能通过隐藏指令获得额外工具权限 |
| 界面生命周期 | 动态入口、面板重开、禁用清理正确；关闭视图不错误终止任务 |
| 结构化结果 | 工具结果在 daemon 中有明确结构和来源，模型与 UI 共用同一结果投影；不依赖插件私有文本协议恢复事实 |
| 生命周期事件 | 插件只能订阅已声明且已授权的 Magi 事件；事件处理的副作用经过统一执行入口，禁用或撤权后立即停止新接纳 |
| 同步正确性 | 并发版本冲突、断线重取、迟到结果和大资源读取均符合第 6 节 |
| 工作流唯一性 | 自定义核心被选中后默认核心不参与；取消和终态没有重复提交 |
| 恢复正确性 | 精确版本和动作记录恢复，未知副作用不自动重放，缺版本不自动切换 |
| GPT Web 插件壳 | 原有主要行为保持；未安装/未激活时不注册入口与引擎、不启动通道和页面，daemon 重启不复活；停用后全部工作区同时失效 |
| Tunnel 释放 | 最后租约释放后进程、relay 与专属端点停止；清理失败不报告完成；持久数据保留不触发已禁用资源重启 |
| 安装版可用 | 干净系统无开发工具时仍能安装运行基础插件；Desktop 三平台分别验证 |

文档和 schema 变更先做对应检查；Rust、Web、Desktop 和真实浏览器改动再按各目录规则运行最小相关检查。测试通过与真实运行验收分别记录，不能互相替代。

## 12. 尚未关闭的交付边界

- **平台验证**：Windows 实际 Worker 执行与三平台正式安装器需分别记录真实证据。Windows Worker 级 OS 限制按 §5.1 的取舍不实现，自检必须保持 `enforced=false`，不能表述为已隔离。
- **异步副作用与恢复**：当前 SDK 以同步本地资源操作为主；开放网络/进程类能力前，须补齐取消、结算和未知副作用恢复合同。排空租约持久化限制见 §8.2。
- **通用 Browser surface**：已接入 GPT Web 的特定挂载语义；其他 surface 组合仍不支持，扩展前按 §6.2 明确宿主能力和失效边界。
- **范围扩展**：插件自带外部程序与插件间依赖不属于首期能力。GPT Web Tunnel 继续由原生受控资源服务托管，不能作为开放任意可执行程序的先例。

插件中心的来源与可选签名规则已按 §8.1 定案，升级数据转换执行者和宿主排空期限已按 §8.3 定案。后续调整直接修订相应合同，不恢复已完成的阶段计划或另建长期并行方案。
