# 持久日志的追加写入与压缩设计

本文覆盖 daemon 中两类只增不减的持久日志：审计/用量账本与会话 canonical 事件日志。两者的共同问题是写入或启动成本随历史总量线性增长；本设计让写入成本只与新增量相关，启动成本只与最近一次压缩之后的增量相关。

### 1.1 状态所有权

InMemoryEventBus 持有审计/用量快照与刷盘水位，StateRepository 负责启动加载。磁盘使用分段 JSONL，执行统计重置通过 usage.stats.reset 事件记录。

### 1.2 持久化结构

```
state_root/audit-usage-ledger/
  segment-00000000000000000001.jsonl
  segment-00000000000000052113.jsonl   ← 活动段（最后一个）
```

- **只追加**：每行一条 `{"category":"audit"|"usage", ...AuditUsageLedgerEntry}`。刷盘只把内存中 sequence 大于「已落盘水位」的条目按 sequence 顺序追加到活动段，然后 `sync_data`。水位与刷盘互斥锁放在一起，由事件总线持有；不再有整本序列化。
- **分段**：活动段超过 8 MiB 时，新条目写入以其首个 sequence 命名的新段。段是保留策略的删除单位。
- **保留**：保留最近 180 天。启动加载时，最新条目早于保留期的整段被删除；最新一段始终保留以延续 sequence，内存只装载保留下来的段。保留只在启动时执行；daemon 长时间运行期间内存仍只增，但单次刷盘成本与历史量无关。
- **崩溃语义**：追加写可能在最后一行中途中断。加载时只有**最后一段**允许出现不以换行结尾的残行，按 WAL 惯例截断到最后一个完整行；任何完整但无法解析的行、或非最后一段的残行，都视为损坏，拒绝以空账本继续（与现有状态文件的严格策略一致）。
- **重置执行统计**：不再删除历史条目，而是经事件总线发布一条用量事件 `usage.stats.reset`（与其他条目走同一写入路径）。执行统计只统计最后一次重置之后的 `model.usage.recorded`。会话用量观测与重启后的用量恢复不受统计重置影响。

### 1.3 接口职责

| 位置 | 职责 |
| --- | --- |
| magi-event-bus::ledger | 分段加载、残行截断、保留删除和增量追加。 |
| InMemoryEventBus | 设置段目录、刷新增量、恢复快照并推进已落盘水位。 |
| StateRepository | 提供段目录路径并加载账本。 |
| 设置 reset_stats | 发布 usage.stats.reset 后刷盘。 |

### 1.4 只接受分段格式

持久化账本只有段目录这一种格式。`StateRepository::load_audit_usage_ledger` 只从段目录加载，不做旧格式迁移，也不识别任何旧版账本文件。

### 2.1 状态所有权

每个会话的 canonical 事件日志是会话事实源；同目录内的检查点压缩已提交事务，加载时从最新检查点继续重放后续增量。

### 2.2 持久化结构

```
state_root/session-events/<session>/
  checkpoint-00000000000000004096.json   ← 最近一次检查点
  history/
    00000000000000000001-00000000000000004096.json.gz
  00000000000000004097-00000000000000004102.json
  ...
```

- **检查点**：表示重放到 `lastEventSeq` 后的完整结果，包含 canonical Turn、Input、accepted 事实和会话标题（日志里最后一条 `session_title_changed` 的标题，没有则缺席；标题事件是会话级事件，不属于任何 Turn，会话记录是它的投影，见 `dsh-session-gateway-design.md` 的 `rename`）。`historySegments` 标识由该检查点接纳的封存范围。每个范围保存原始 JSON 事务流，采用 gzip 压缩，保留所有原事件的顺序、序号和载荷。范围连续，最后一个范围结束于检查点水位。旧检查点可能已截断一段历史，后续封存从已有水位之后开始。
- **加载**：取序号最大的检查点作为起点，只重放 `first_event_seq > lastEventSeq` 的事务。启动校验封存范围索引。内部历史读取按已提交的水位分页，按需解压封存分段。完全被检查点覆盖的事务文件（截断中途崩溃的遗留）直接跳过；跨越检查点边界的事务视为损坏。
- **写入与截断**：写入事务后，如果自上一个检查点以来的事务数达到 128，先校验待封存文件的范围连续，再流式压缩新增事务并原子落盘。新检查点一次提交回放水位与封存范围，随后清理已覆盖的松散事务与旧检查点。封存或检查点写入失败时，松散事务继续持有全部原始事件。重试从上一个已提交水位重新封存，成功后清理同起点的失败候选。
- **会话身份读取**：`read_session_id_from_root` 只读取目录中排序第一个文件的 `sessionId` 字段，事务与检查点都带该字段。
- 事件目录是 canonical 事实的唯一权威源，由已接纳的封存范围、检查点和后续松散事务组成。会话删除及孤立会话隔离沿现有完整事件目录处理。

### 2.3 运行态投影检查点

后台刷盘只捕获脏会话的 durable/sidecar 切片，不携带或写入全局 `session-current.json`；会话选择由导航及显式投影事务持久化。所有投影事务从快照捕获到磁盘提交共用 `SessionStore` 的持久化锁，防止旧检查点覆盖已经保存的重命名或恢复已删除会话。canonical/state 锁在快照构造后释放，模型事件写回与普通读取可以在刷盘期间继续；builder 从事件日志对齐期间新增的 canonical 事实，脏版本只确认实际提交的会话。

仅保留 `flush_execution_sidecar_snapshot_with` 一个运行态刷盘入口。原持锁全量刷盘及无会话归属时回退全量保存的旧路径已删除；脏标记必须包含会话身份，不能将空的部分快照解释为全量状态。

## 3. 验证

- 账本：分段追加只写增量、跨段轮转、残行截断、非末段损坏拒绝、保留删除、重置标记后的统计口径。
- 事件日志：达到阈值后封存原始事务，生成检查点并删除被覆盖的松散事务。从检查点加载结果与全量重放一致。覆盖封存失败与原事务保留、检查点提交前中断与重新封存、已有截断历史的起始序号，以及跨边界事务拒绝。分页验证从封存读取至增量事务、固定水位、单页字节上限及读期间检查点轮转。
- 投影检查点：会话切换不被后台覆盖；并发重命名与删除在重载后保持，刷盘期间仍可提交工具结果和读取会话；写盘失败、离线工作区与期间新增的脏版本不被误确认。
